# アプリケーション構成とエディタ連携 設計ドキュメント

> 対象コミット: 03fe48b / 最終更新: 2026-09-30

## 0. 目的と位置づけ

将来、WPF で作る外部エディタから TCP(ローカル)で操作される **ランタイム** として
エンジンを動かせるようにする。そのための土台として次の 3 つを入れる。

| フェーズ | 内容 | 挙動の変化 |
|---|---|---|
| P1 | `aq::Application`(継承の基底)を **`AppHost`(土台・常駐)と `IAppModule`(差し替え単位)** に分ける | なし(リファクタのみ) |
| P2 | **起動引数** `LaunchOptions` とモジュールのレジストリ。WPF の `HwndHost` へ埋め込むための **子ウィンドウ起動** | 引数を付けたときだけ変わる |
| P3 | **LinkService**: TCP + JSON(改行区切り)の命令受付。ランタイムの問い合わせと Level 操作の最小命令セット | `-editor-port` を付けたときだけ有効 |

P4 以降(Edit/Play の実行時切り替えなど)は「8. 今後の課題」に残す。本書は P1〜P3 の一次資料。
[06_ゲームアプリケーションコア設計.md](06_ゲームアプリケーションコア設計.md) の「2. アプリケーション基底」は、
P1 完了時に本書へのリンクに置き換える(同じ内容を 2 か所に書かない)。

### 全体像(P3 完了時)

```
┌─ 外部エディタ(将来 WPF)───┐  TCP 127.0.0.1:<port>   ┌─ Runtime (Game.exe) ───────────────────────┐
│  HwndHost ← 子ウィンドウ ───┼──── 改行区切り JSON ────▶│ Engine                                    │
│  (P2 の -parent-hwnd)       │                         │  └ AppHost(IApplication の実装・常駐)     │
└─────────────────────────────┘                         │      ├ LinkService(P3。通信スレッド+     │
                                                        │      │   メインスレッドでの命令実行)       │
                                                        │      ├ 描画 / ECS / Resource / Input / ImGui│
                                                        │      └ IAppModule(AquaDash 等。P1)       │
                                                        └───────────────────────────────────────────┘
```

## 1. 現状(対象コミット時点)

- `aq::Application`([Core/Application.h](../aqEngine/Core/Application.h))は、エンジンの土台と
  ゲームのフックを兼ねている。土台とは、RenderThread / ResourceManager / ECS / Input / UIContext /
  ImGui / DebugUI パネルの初期化と終了のこと。ゲームは継承して `OnInitialize` などを override する。
- ゲーム側([Game/Application/Application.h](../Game/Application/Application.h))が基底から使っているもの:
  `renderer_` / `renderThread_`(protected メンバ)、`BuildStandardPipeline` / `SetRenderPipeline`、
  `WaitForRenderIdle`(`AquaDashStates.cpp` から `app::Application::Get()` 経由)。
  Sample は `SetupStandardRenderers()` だけを使う。
- アプリの生成は、エントリ 7 か所で `Engine::CreateApplication<T>()` を呼んでいる
  (Game: Win32/UWP/Android/Mac/iOS、Sample: Win32/Mac)。
- 起動引数は、どのエントリでも読んでいない(`lpCmdLine` / `argv` は捨てている)。
- `PlatformWin32` はトップレベルウィンドウ固定で、`WM_SIZE` を扱っていない(リサイズ非対応)。
- DirectInput は `SetCooperativeLevel(hwnd, DISCL_FOREGROUND)` を使う。子ウィンドウの HWND は
  受け付けないので、埋め込み時は別の手当てが要る(P2)。
- ソケット関連のコードはリポジトリに存在しない。PCH(`aq.h`)は `WIN32_LEAN_AND_MEAN` なしで
  `windows.h` を読むので、`winsock.h`(v1)が先に入る。

## 2. P1: AppHost / IAppModule 分割

### 2.1 方針

- **継承から所有へ。** 土台は `aq::AppHost`(`final`)1 つに固定し、ゲームは `aq::IAppModule` を実装して
  AppHost に所有させる。
- **フックの名前・順序・回数は今と同じにする。** P1 は純粋なリファクタで、絵も起動ログの順序も変わらない。
  実行時の差し替え(Enter/Exit)は P4 の課題として、P1 では入れない。
- `aq::Application` という名前は廃止する(ゲーム側の `app::Application` と紛らわしいため)。
  ゲーム側のクラス名は `app::Application` のまま残す。フォルダを丸ごと差し替える方針なので、
  1 ゲームにつき 1 モジュールという意味で自然な名前であり、呼び出し側の変更量も最小になる。

### 2.2 ファイル別責務

| ファイル | 種別 | 責務 |
|---|---|---|
| `aqEngine/Core/IAppModule.h` | 新規 | 差し替え単位のインターフェース(2.3) |
| `aqEngine/Core/AppHost.h/.cpp` | 改名(`git mv` Application.h/.cpp) | 旧 `aq::Application` の土台部分すべて。フックの呼び出し先を `module_->` に替える。`IApplication` を実装 |

### 2.3 インターフェース

```cpp
namespace aq
{
	class AppHost;

	/**
	 * AppHost に載せて動かす差し替え単位(ゲーム本体・将来のエディタ用モードなど)。
	 * フックの呼ばれる位置は旧 aq::Application の On* と同じ。
	 */
	class IAppModule
	{
	public:
		virtual ~IAppModule() = default;

		/** ログやレジストリで使う名前(起動引数 -app= と照合する) */
		virtual const char* GetName() const = 0;

		/** エンジンサブシステム初期化後に 1 回 */
		virtual bool OnInitialize(AppHost& host) { return true; }
		/** エンジンサブシステム終了前に 1 回 */
		virtual void OnFinalize() {}
		/** エンジン標準 System の登録後、FinalizeRegistration 前に 1 回 */
		virtual void OnRegister() {}
		/** Input/ECS/Level/Resource 更新後、UI 更新前に毎フレーム */
		virtual void OnUpdate() {}
		/** メインパス Submit 前に毎フレーム */
		virtual void OnPreRender() {}
#ifdef AQ_IMGUI
		virtual void OnImGuiRender() {}
#endif
#ifdef AQ_DEBUG_IMGUI
		virtual void OnDebugRenderMenu() {}
		virtual void OnDebugRender() {}
#endif
	};
}
```

`AppHost` がモジュールへ公開する操作(旧 protected を public にする):

| メンバ | 備考 |
|---|---|
| `static AppHost& Get()` / `static bool IsAvailable()` | 旧 `app::Application::Get()` 経由の土台アクセスを置き換える |
| `rendering::Renderer& GetRenderer()` | 旧 `renderer_` |
| `rendering::RenderThread& GetRenderThread()` | 旧 `renderThread_`(オフスクリーン Submit 用) |
| `SetupStandardRenderers` / `BuildStandardPipeline` / `SetRenderPipeline` | 中身は変えない |
| `SetSplitViews` / `ClearSplitViews` / `WaitForRenderIdle` | 同上 |
| `IAppModule& GetModule()` | 現在のモジュール |

`RendererPreset` の `using` は `AppHost.h` へ移す(ゲームは `aq::RendererPreset` と書いたまま通る)。

## 3. P2: 起動引数・モジュールレジストリ・子ウィンドウ起動

### 3.1 起動引数

| 引数 | 既定 | 意味 |
|---|---|---|
| `-app=<名前>` | 登録順の先頭 | 起動するモジュールを `IAppModule::GetName()` で指定する。**見つからなければ初期化失敗**(エディタからの起動ミスを黙って別アプリで動かさないため) |
| `-mode=play\|edit` | `play` | P2 では値を受け取って保持するだけ。`edit` は「未実装のため play で起動」とログを出す(P4) |
| `-editor-port=<1-65535>` | 0(無効) | 0 以外なら P3 の LinkService をこのポートで待ち受ける |
| `-parent-hwnd=<10進 or 0x16進>` | 0(無効) | Win32 のみ。指定したウィンドウの子として作り、エディタに埋め込む |

- 形式は `-key=value` とする(`--key=value` も同じ扱い)。値の中の空白は `"` で囲む。
- 知らないキーや値の誤りはログに出して無視する(`-app` の不一致だけは失敗扱い)。
- 引数を渡せるのは Win32(`lpCmdLine`)と Mac(`argv`)。UWP / Android / iOS は既定値で動く。

### 3.3 埋め込み時の入力

- DirectInput は子ウィンドウを協調ウィンドウとして受け付けず、`InputManager::Setup()` が失敗する。
  このままだと初期化全体が落ちる。そこで埋め込み時は `PlatformWin32` が **非表示のトップレベルウィンドウ**
  (入力の協調用。1x1、`WS_POPUP`、表示しない)を別に作る。DirectInput にはこれを
  `DISCL_BACKGROUND` で渡す。Engine はこれを `GetInputWindowHandle()` として公開し、`Input.cpp` の取得元を差し替える
  (埋め込みでないときは従来どおりメインウィンドウを返す)。
- BACKGROUND にするとフォーカス外のキーも拾ってしまう。そこで、フォーカスが無いフレームは
  `SuppressKeyboard/Mouse` で落とす。XInput / DualSense は HWND に依存しないので影響しない。
- ImGui はウィンドウメッセージで入力を受けるため、子ウィンドウでもそのまま動く想定。
- **リサイズ追従は P2 の範囲外**。現状の Win32 に `WM_SIZE` 処理が無いため、埋め込み時の寸法は起動時の
  親の大きさで固定する(エディタ側で固定サイズにしておく)。

## 4. P3: LinkService(TCP + JSON)

### 4.1 プロトコル(バージョン 1)

- **トランスポート**: TCP。`127.0.0.1` にだけ bind する(外部ネットワークには公開しない)。同時に接続できるクライアントは 1 つ。
  2 つ目の接続は `error` イベントを 1 行送ってから切断する。
- **フレーミング**: **改行区切り JSON**(UTF-8。1 メッセージ = 1 行、終端 `\n`)。
  JSON の文字列中の改行はエスケープされるので、行を区切っても衝突しない。
  C# 側は `StreamReader.ReadLine()` だけで読める。1 行の上限は 16 MiB で、超えたら切断する。
- **メッセージ種別**:

```jsonc
// エディタ → ランタイム(要求)
{"type":"request","id":12,"cmd":"level.load","params":{"path":"Assets/Levels/Stage1.level.json"}}
// ランタイム → エディタ(応答。id は要求と同じ)
{"type":"response","id":12,"ok":true,"result":{"levelId":3}}
{"type":"response","id":12,"ok":false,"error":{"code":"not_found","message":"..."}}
// ランタイム → エディタ(通知。id なし)
{"type":"event","event":"hello","data":{"protocol":1,"app":"AquaDash","pid":1234}}
```

- **エラーコード**: `bad_request`(JSON として壊れている、必須キーが無い)、`unknown_command`、
  `invalid_params`、`not_found`、`failed`(ハンドラ内の失敗)。
  壊れた行を受けても接続は切らない(`id` が読めなければ `id: null` で返す)。

### 4.2 P3 の命令セット

| cmd | params | result | 備考 |
|---|---|---|---|
| `ping` | なし | `{"time": 総経過秒}` | 疎通と往復遅延の確認 |
| `runtime.info` | なし | `{"protocol","app","mode","graphicsApi","renderWidth","renderHeight","fps","pid"}` | |
| `runtime.commands` | なし | `{"commands":["ping",...]}` | 登録済みの命令一覧(エディタ側のデバッグ用) |
| `level.load` | `{"path"}` | `{"levelId"}` | `LevelManager::Load`(同期)。失敗時は `not_found` / `failed` |
| `level.reloadAll` | なし | `{}` | `LevelManager::ReloadAll` |

- 接続直後に、ランタイムから `hello` イベントを送る。
- モジュールは `OnInitialize` で `LinkService::Get().RegisterCommand(...)` を呼べば、ゲーム固有の命令を追加できる
  (`OnFinalize` で Unregister する)。P3 の AquaDash は何も追加しない。

### 4.3 スレッド構成

```
通信スレッド(std::thread。1 本)             メインスレッド(AppHost::Update 内)
  select(listen/client, 50ms) ループ           LinkService::Tick()
   ├ accept → inbox に Connected                ├ inbox を取り出す(mutex)
   ├ recv → 行に分割 → inbox に Line            ├ Connected → hello を outbox へ
   ├ outbox があれば send                       ├ Line → Parse → ハンドラ実行 → 応答を outbox へ
   └ stop フラグで終了                          └ Disconnected → ログ
```

- **命令はメインスレッドでだけ実行する。** 実行位置は `AppHost::Update` の `ResourceManager::Update()` の後、
  `module_->OnUpdate()` の前。ECS の反復中ではなく、Level の即時生成も安全な「安全点」。
  ハンドラに ECS / Level / Resource を触らせても、スレッド境界規約を破らない。
- 通信スレッドは JSON を解釈しない(バイト列と行の分割だけ)。inbox と outbox はそれぞれ mutex 付きの `std::vector<std::string>`。
- 1 フレームに処理する行数は上限なし(ローカルの編集操作は少量という前提)。重くなったら P4 以降で上限を設ける。
- 終了時は、stop フラグを立てて join し、ソケットを閉じる。AppHost の `Finalize` 冒頭(モジュールの `OnFinalize` の後)で行う。

### 4.4 ソケット実装

- P3 は **Win32 のみ**(`AQ_PLATFORM_WIN32`)。それ以外では `LinkService` はスタブになり、`-editor-port` を
  指定されたら「未対応」とログを出す。POSIX(Mac)と UWP(ループバック除外と capability が要る)は今後の課題。
- PCH が `winsock.h`(v1)を先に取り込むので、`winsock2.h` はインクルードしない。
  必要な API(`socket/bind/listen/accept/recv/send/select/ioctlsocket/closesocket/WSAStartup`、IPv4)は
  すべて `winsock.h` にある。リンクは `.cpp` 内で `#pragma comment(lib, "ws2_32.lib")` を指定して行う
  (プロジェクトの構成ごとの依存ライブラリ一覧は触らない)。

- [ ] 壊れた JSON を送ると `bad_request` が返り、接続は維持される。未知の cmd は `unknown_command`
- [ ] 切断 → 再接続でき、2 つ目の同時接続は拒否される
- [ ] 接続したまま終了してもハングせず、終了コード 0 で終わる(通信スレッドの join)
- [ ] `ping` を 100 回連続で送り、往復時間(フレーム律速で数十 ms 以内の想定)を記録する
- [ ] ゲームの走行中に命令を送っても、フレーム落ちやクラッシュが起きない
- [ ] D3D11 / D3D12 / Vulkan の 3 構成ビルドが通る

## 6. 採用しなかった案

| 案 | 採用しなかった理由 |
|---|---|
| 長さプレフィクス(4 バイト)のフレーミング | 大きなバイナリを送らない間は、改行区切りのほうが C# 側も手動デバッグ(telnet など)も簡単 |
| `WIN32_LEAN_AND_MEAN` を全体に入れて winsock2 を使う | 影響範囲が全 TU に及ぶ。IPv4 ループバックだけなら v1 API で足りる |
| 通信スレッドで命令を直接実行する | ECS / Level をメインスレッド外から触ることになり、規約に反する |
| P2 で埋め込みを共有テクスチャ(D3DImage)にする | DX11 / 12 / Vulkan で分岐が重い。子ウィンドウならプロセス分離の利点もある |
