# aqEngine エディタ E11: シーンビュー(編集用カメラ、クリック選択、ギズモ)

> 対象コミット: d3abdc9 / 最終更新: 2026-11-26(新規。詳細設計)
> 全体の構成・到達点・フェーズ一覧・未決事項は [エディタ全体設計](../エディタ全体設計.md)。

E10 まで実装済み(E9・E10 の動作確認は後回し。ユーザー決定)。Mac 機で設計した。実装も Mac のエディタ(E10 の `macos-ninja-metal-editor`)で進められる。Windows の Editor.exe でも同じコードが動くように、Editor とエンジンの共通部分だけで書く。

## 現状(調査結果。d3abdc9 で確認)

| 項目 | 実コード |
|---|---|
| エディタの入力の時点 | `OnBeginFrame` はエディタ用の `ImGui::NewFrame` より前(プラットフォームの NewFrame の後)で、`io` のボタン・マウスの差分・ホイールはまだこのフレームの値になっていない(ホイールは前のフレームの `EndFrame` で 0)。このフレームの入力が `io` に入るのは `OnBuildUI` の中 |
| カメラ | `Camera` は値型。`CameraManager` が `Main` と `Offscreen` を持つ(`Graphics/Camera.h`)。`SetPosition` / `SetTarget` / `SetUp` / `SetNear` / `SetFar` / `SetViewAngle`、`CaptureState` / `RestoreState`。行列は `Update()` で作り直し、`AppHost::Update` が `UpdateAll()` を呼ぶ。描画(`RenderSystem::BuildRenderFrame`)は `Main` を使う |
| Edit 中のカメラ | ゲームのカメラ制御の System は既定の `RunMode` が Play だけなので、Edit では動かない。Edit の `Main` は起動時の既定値のまま(E5 の「メインカメラのまま」)。`PlayModeController` は Play の開始で `Main` / `Offscreen` の状態を控え、停止で戻す |
| 2 視点の描画 | 1 枚の RT を分ける `BuildViews`(分割画面)と、別の RT・別のパイプラインで描くミニマップ(`GameModule` の `OnPreRender`。影・ポストなし)がある。シーンビューをゲームビューと別に描くと、シーンの描画とメモリがほぼ 2 倍になり、Edit 用の描画の口・2 本目のパイプラインと RT のリサイズ・MotionBlur の履歴・Hi-Z の無効化が要る |
| 行列 | 左手系・行ベクトル・行優先(`XMFLOAT4X4` と同じ並び。平行移動は `_41`〜`_43`)。射影の深度は [0, 1]。スクリーン → レイの共通関数は無い(`HeightmapPainter::ScreenToRay` などの私的な実装だけ)。レイと AABB の交差も無い。`math::AABB`(中心と半分の大きさ)と `Transformed(Matrix4x4)` はある |
| 3D の補助線 | 線を描く仕組み(DebugDraw)は無い。Terrain のブラシは `ImGui::GetForegroundDrawList` に、手で投影した円を描いている |
| 編集ノードと実エンティティ | 対応は無い。`editId` は JSON に出ない。プレビューは `LevelEditModel::ProcessPreviewRequest` → `LevelSerializer::FromJson` → `LevelManager::Load` → 次の Flush の `InstantiateEntities` が `data->entities` を前順で生成し、生成ごとに `stamp(Entity, const PrefabNodeData&)` を呼ぶ。トップレベルの `entities_[i]` と `data->entities[i]`、インラインのノードの子と `PrefabNodeData` の子は 1 対 1。参照ノードは 1 つが部分木(複数のエンティティ)に展開される |
| プレビューの作り直し | コマンドが成功するたびに、GPU の完了待ち・Flush 2 回・全体の再生成・メッシュの再読み込みをする。ドラッグ中に毎フレーム作り直すのは現実的でない(インスペクターもドラッグ中は送らず、確定でだけコマンドにする) |
| 描画物の境界 | 静的メッシュは `MeshResource::GetLocalAABB`、スケルタルはバインドポーズの AABB(描画では 1.5 倍)、`InstancedStaticMesh::GetLocalBounds`。コンポーネントの外からは `FillRenderItem` 経由でしか取れない(`worldMatrix_` などは private) |
| Transform | `TransformComponent` はローカル値で、Reflect のキーは `position`(Vector3)・`rotation`(Quaternion)・`scale`(Vector3、最小 0.001)。ワールドは `HierarchicalTransformComponent::transform` に位置・回転・拡縮で入り、`HierarcicalTransformSystem::UpdateWorld` が毎フレーム計算する(`RunMode` は All)。**合成は行列の積ではなく成分ごと**: 位置は「ローカルの位置 × 親のワールド行列(S·R·T)」、回転は「ローカル × 親」、拡縮は成分ごとの積。値の書き換えは構造変更ではないので、ECS の反復の外ならその場で書いてよい。Prefab の生成は Transform を自動で足すが、編集モデルの実体ノードには Transform が無いことがある(読み込みでは足さない) |
| 選択 | `EditorContext` はノード ID 1 つ。Play 中のヒエラルキーは `SceneHierarchySystem` の `EntityHandle` を別に持つ |
| ImGuizmo | リポジトリに無い。同梱の ImGui は 1.93.0(docking)。ThirdParty は `ThirdParty/<名前>/` に素のまま写し、`imgui.vcxproj` と CMake の imgui ターゲットの両方に登録する流儀(E1) |

## 決定

E11 を 3 段に分ける。**E11a: 編集用カメラと補助線** → **E11b: クリック選択(ノードとエンティティの対応表)** → **E11c: ギズモ**。

### 1. シーンビューの描き方(E11a)

- **Edit 中だけ、メインカメラを編集用カメラで上書きする**。シーンビュー専用の 2 つ目の描画は作らない。ゲームビューのウィンドウは、Edit 中はシーンビュー(編集用カメラの画)、Play / Pause 中はゲームビュー(ゲームのカメラの画)になる。
  - 理由: 2 視点の描画は描画とメモリがほぼ 2 倍で、Edit 用の描画の口・2 本目のパイプライン・状態を持つパス(MotionBlur・Hi-Z)の扱いが要る。差し替えは Edit ではゲームのカメラ制御が動かないので上書きされず、Play の開始と停止のカメラの控え・戻し(E5)にもそのまま乗る。
  - 代わりに失うもの: Play 中にシーンビューを並べて見ること、Edit 中に「ゲームのカメラからの見え方」を見ること。必要になったら、ミニマップと同じ別パイプラインの方式で E11 の後に足す(このフェーズで作らないもの)。
- ウィンドウ名(`Game View`)は変えない(ドックの配置の保存を壊さないため)。表示の名前だけ、Edit 中は `Scene`、それ以外は `Game` にする(ImGui の `###` で ID を固定して表示名だけ変える)。ウィンドウの左上に、今どちらのカメラかを小さく出す。
- 編集用カメラは `editor::SceneCamera`(Editor、新規)が持つ。位置・ヨー・ピッチ・注視点までの距離・移動速度。**操作の入力は `OnBuildUI`(エディタ用の `NewFrame` の後。`io` がこのフレームの値)で読んで `SceneCamera` を更新し、`Main` へ書くのは次のフレームの `OnBeginFrame`(`EntityContext::Update` と `CameraManager::UpdateAll` より前)**。操作から画面への反映は 1 フレーム遅れる(入力を読む時点が NewFrame の後にしか無いため)。書くのは Edit のときだけで、`SetPosition` / `SetTarget` / `SetUp(0,1,0)` / `SetViewAngle` / `SetNear` / `SetFar`。アスペクト比は今までどおり `AppHost::CommitRenderResize` が決める。
- 起動時の編集用カメラ: 位置 (0, 10, -20)、注視点は原点、画角 60°、near 0.1、far 1000(起動時の `Main` の既定値は位置 (0, 0, -1)・画角 90° で、編集の初期の視点として使いにくいため)。Level を開いたとき・New のときは変えない(開いた Level の場所が分からないため。E11b の `F` で選んだノードへ寄れる)。
- Play の開始と停止: Play を始めるとき、`PlayModeController` は今までどおり `Main` を控える(控えるのは編集用カメラの状態になる)。Play 中はゲームが `Main` を動かす。停止で戻した後、次のフレームから編集用カメラがまた上書きする(編集用カメラの状態は `SceneCamera` が持っているので、Play の前の視点に戻る)。Pause 中は編集用カメラを動かさない(Play に戻るとゲームが上書きするため)。

### 2. カメラの操作(E11a)

ウィンドウの画像の上にマウスがあり、Edit のときだけ受け付ける。Unity / Unreal に近い割り当てにする。

| 操作 | 動き |
|---|---|
| 右ドラッグ | 見回す(ヨーとピッチ。ピッチは ±89°) |
| 右ドラッグ中の W / A / S / D / Q / E | 前後・左右・下上へ飛ぶ。Shift で 4 倍。ホイールで移動速度を変える(0.1〜1000、倍々) |
| 中ドラッグ | 平行移動(視点の面の上) |
| ホイール(右ドラッグ中でない) | 注視点へ寄る・離れる |
| Alt + 左ドラッグ | 注視点の周りを回る |
| F(E11b) | 選んだノードのワールド AABB(無ければ位置)が収まるように寄る。対応表と境界の口が要るので E11b で足す |

- **Edit のときは、`GameViewInput` が右ボタン・中ボタン・ホイールと、Alt を押した左ボタンをゲーム用へ転送しない**(`GameViewInput` は `OnBeginFrame` でエディタ用のイベントの列を転送するので、カメラの操作を始めたかを知る前に押下が流れてしまう。Edit ではゲームの System は止まっているので、ゲーム用のデバッグ UI で右クリック・ホイールが使えなくなるだけ)。カメラの右ドラッグ中は、キー(WASDQE と Shift)も転送しない(`SceneCamera` が前のフレームに立てた「操作中」の印で判定する)。Play / Pause では今までどおりすべて転送する。
- 入力はエディタ用 ImGui の `io`(マウスの差分・ボタン・キー)から読む。Mac の Command / Ctrl の入れ替え(E10)の影響を受けるキーは使わない。

### 3. 補助線(E11a)

- ゲームビューのウィンドウの描画リスト(`GetWindowDrawList`、画像の矩形で切り抜く)に、**エディタ用 ImGui で**描く。レンダラーに線の描画は足さない。
- グリッド: y = 0 の XZ 面に 1 m 間隔(カメラの高さで 1 / 10 / 100 m を切り替える)、原点の X 軸を赤・Z 軸を青。範囲はカメラの真下から ±max(|カメラの高さ| × 10, 50) まで(高さが 0 や負でも出る)。
- 選んだノード: そのエンティティ群のワールド AABB(E11b の対応表と境界の口を使う)を黄色の箱で描く。E11a の段階では選択を出さない。
- 線はクリップ空間で近い面(z = 0)に切ってから w で割る(カメラの後ろへ回り込んだ線が画面を横切らないように)。
- 投影と逆投影はエンジンの共通の関数にする(4.)。

### 4. 数学の共通関数(E11a。エンジン)

- `aqEngine/Math/Bounds.h` に `struct Ray { Vector3 origin; Vector3 direction; }` と `bool IntersectRayAABB(const Ray&, const AABB&, float& outDistance)`(スラブ法。始点が箱の中なら距離 0)。
- `Camera` に、ビューポートの中の正規化座標(左上 (0,0)〜右下 (1,1))からワールドのレイを作る `Ray ScreenPointToRay(float u, float v) const` と、ワールドの点をクリップ空間へ写す `Vector4 WorldToClip(const Vector3&) const`(線の切り抜きはクリップ空間で行う)。`HeightmapPainter` / `SplatmapPainter` の私的な `ScreenToRay` はこのフェーズでは置き換えない(挙動を変えないため。重複は README の既知の課題に記録する)。

### 5. ノードとエンティティの対応表(E11b。エンジン)

- `LevelManager` に、エンティティを生成するたびに呼ぶ口を足す: `using SpawnObserver = std::function<void(LevelId, ecs::Entity, const ecs::PrefabNodeData&)>`、`SetSpawnObserver(SpawnObserver)`(1 つだけ。既定は空)。`InstantiateEntities` の `stamp` の中で、levelId を差した後に呼ぶ。インラインの subLevel も同じ関数を通る。非同期の `LoadAsync` の経路では呼ばない(プレビューは同期の `Load` だけを使う。口のコメントに書く)。
- `LevelEditModel` が対応表を持つ(`AQ_DEBUG_IMGUI` の中。モデルに置くのは、プレビューを作る・捨てるのがモデルだから):
  - プレビューを作るとき、`FromJson` で得た `LevelData` と編集モデルを並べて歩き、`const PrefabNodeData*` → `editId` の表を作る。トップレベルは添字で、子は並びで対応させる。**参照ノードは、展開された部分木のすべての `PrefabNodeData` を、その参照ノードの `editId` に結ぶ**。インラインの subLevel(1 段目まで。UI と同じ)の entities も同じ。ファイル参照の subLevel は対象外。並びが食い違ったら(数が合わない)、そこから下は表に入れず、ログを 1 回出す。
  - `SetSpawnObserver` で、プレビューの levelId(とその子の subLevel)の生成を受け、`editId` → エンティティの列(先頭がそのノードの根)と、エンティティ → `editId` を記録する。
  - `ReleasePreview` で表を空にし、`SetSpawnObserver` を外す。`LevelData` の `PrefabNodeData` のポインタは、登録が続く間(`Register` から `Unregister` まで)だけ有効なので、表もその間だけ持つ。
  - 公開する口: `const std::vector<ecs::EntityHandle>* FindPreviewEntities(uint32_t editId) const`、`uint32_t FindEditIdOfEntity(ecs::EntityHandle) const`(無ければ 0)。
- 境界の口: `StaticMeshComponent` / `SkeletalMeshComponent` / `BoxStaticMeshComponent` に `bool GetWorldBounds(math::AABB& out) const`(読み込みが済んでいなければ false)を足す。中身は描画と同じ境界(`FillRenderItem` が使う `localBounds` × ワールド行列。スケルタルは描画と同じく 1.5 倍)。エディタはエンティティが持つものを順に試す。**`InstancedStaticMeshComponent` は対象外**(共有のメッシュを指すだけで、配置は別の `InstancedPointListComponent` と点ごとの変換・ベイクしたセルにあり、1 つの「ローカル境界 × ワールド行列」では点の群れを囲めない。こうしたエンティティは境界の無いものとして、位置の 8 px 以内のクリックで選ぶ)。

### 6. クリック選択(E11b。Editor)

- `editor::ScenePicker`(新規): Edit のとき、ゲームビューの画像の上で左クリック(ドラッグでない、Alt なし、ギズモの上でない)したら、マウスの位置を画像の矩形で正規化して `ScreenPointToRay` でレイを作り、対応表のすべてのエンティティについて、ワールド AABB があれば `IntersectRayAABB`、無ければ位置を画面へ写して 8 px 以内かを調べる。最も近いもの(AABB の距離、画面の点はカメラからの距離)の `editId` を `SetSelectedId` する。何も当たらなければ選択を外す。
- 参照ノードの部分木のどれに当たっても、その参照ノードが選ばれる(5. の表のとおり)。
- Play / Pause 中はクリック選択をしない(このフェーズで作らないもの)。

### 7. ギズモ(E11c)

- **ImGuizmo を入れる**。`ThirdParty/imguizmo/` に、ImGui 1.93 で動く版(実装のときに上流の最新のリリースから選び、コミットのハッシュを README に書く)の `ImGuizmo.h/.cpp` と `LICENSE`(MIT)を素のまま写す。`imgui.vcxproj` と CMake の imgui ターゲットに足す(E1 の流儀)。ImGui 1.93 でビルドできない・動かないときは、直す範囲が小さければ `ThirdParty/imguizmo/README.md` に差分を書いて直し、大きければ止めて設計を見直す。
- 行列: エンジンの行列(左手系・行ベクトル・行優先)を float[16] としてそのまま渡す。ImGuizmo は行ベクトル・行優先の並びで計算するので並びの変換は要らない見込み。左手系と深度 [0, 1] で軸の向き・回転の向き・カメラの後ろの判定が正しいかは E11c の最初に確かめ、合わなければ渡す前後で変換する薄い関数を `editor::GizmoMath` に置く。
- 操作: W = 移動、E = 回転、R = 拡縮(右ドラッグ中でないとき)。ワールド / ローカルの切り替えはウィンドウの上の小さなボタン。スナップは Ctrl(Mac は Command)押下中に移動 1 m・回転 15°・拡縮 0.1。
- 対象: 選んだノードの `Transform`。ImGuizmo には、根のエンティティの `HierarchicalTransformComponent::transform`(ワールドの位置・回転・拡縮)から組んだ S·R·T の行列を渡す。戻ってきた行列をワールドの位置・回転・拡縮に分け、**`UpdateWorld` の成分ごとの規則の逆**でローカルにする: 位置 = ワールドの位置 × 親のワールド行列(S·R·T)の逆行列、回転 = ワールドの回転 × 親の回転の逆、拡縮 = ワールドの拡縮 ÷ 親の拡縮(成分ごと)。成分ごとの規則なので、親の拡縮が非一様でもこの逆算は厳密に戻る(行列の積で合成していないので、せん断は生じない)。親が無ければワールド = ローカル。これらの計算は `editor::GizmoMath` に置き、`UpdateWorld` と同じ順で合成し直して元に戻ることを T16(c) で確かめる。
- **ドラッグ中の見た目**: 対応表からそのノードの根のエンティティを引き、`TransformComponent` を直接書き換える(`OnBuildUI` の中。ECS の反復の外)。モデルは変えない。確定(ImGuizmo の `IsUsing` が true → false)で、変わったキーだけを `SetFieldCommand` にし、2 つ以上なら新しい `CompositeCommand`(名前は `Transform`)にまとめて 1 回で積む。積んだ後はいつもどおりプレビューが作り直される。
- ドラッグの取り消し: 途中で Esc・選択の変更・Play・ウィンドウからの離脱があったら、控えた元の値をエンティティへ書き戻して何も積まない。ドラッグの途中で状態が変わったときは 2 つに分ける。(a) **プレビュー(`GetPreviewLevelId`)が変わった**(Undo / Redo・ファイル操作・別のパネルのコマンドでプレビューが作り直された)なら、控えたエンティティは捨てられているので、**書き戻さずに**操作をやめる(新しいエンティティへ古い値を書かない。新しいプレビューはモデルの値で作られている)。(b) **プレビューは同じでモデルの版(`EditorContext::GetVersion`)だけが変わった**(通常の Save は版を進めるがプレビューを作り直さない)なら、控えた元の値をエンティティへ**書き戻して**操作をやめる(画面をモデル・保存した内容と一致させる)。どちらも何も積まない。
- **モデルの実体ノードに Transform が無いとき**(読み込んだファイルに Transform が書かれていない。生成では自動で足されるので画面には出る): 確定は `SetFieldCommand` ではなく、ドラッグ後の位置・回転・拡縮を持つ `AddComponentCommand("Transform", JSON)` 1 つにする(モデルの `AddComponent` は `addable` を見ないので Transform も足せる)。**ただし今の `AddComponentCommand::Undo` が呼ぶ `LevelEditModel::RemoveComponent` は `addable == false`(Transform)を拒むので、そのままでは取り消せない**(取り消しに失敗すると `CommandHistory` が履歴を捨てる)。そこで `RemoveComponent` に「`addable` を見ない」引数(`bool ignoreAddable = false`)を足し、`AddComponentCommand::Undo` だけがそれを true で呼ぶ(足したものを外すのは足す操作のちょうど逆なので、`addable` の制限の対象ではない)。インスペクターの Remove Component は今までどおり false で呼ぶ。**参照ノードで、解決した参照先に Transform が無いとき**は、ギズモを出さない(override で Transform を足す経路は E12 の override の編集 UI で扱う)。判定はドラッグ開始の `GetComponentField` が false かどうか。
- `CompositeCommand` の契約(`IEditorCommand` の「false ならモデルは変えない」を保つ): `Execute` は子を順に実行し、途中の子が false なら、それまでに成功した子を逆順に `Undo` してから false を返す。`Undo` は子を逆順に取り消し、途中の子が false なら、取り消した子を順に `Execute` し直してから false を返す。立て直しの途中でも失敗したら(モデルとコマンドが食い違っている)、ログに出して false を返す(それ以上は直せない。`EditorContext` は失敗したコマンドを履歴に入れない今の扱いのまま)。
- 参照ノードの Transform は、確定で `SetFieldCommand` を積めば override になる(E7 の `SetComponentField` の付け替え)。ドラッグの開始の値は `GetComponentField` で 1 回だけ取る(ファイルを読むため、毎フレームは呼ばない)。
- ベイク済みの `InstancedPointList` などワールド行列を焼き込んだエンティティは、ドラッグ中は動かない(確定後の作り直しで正しい位置になる)。詳細はこの節に書き、README の既知の課題にはこの節へのリンクを 1 行足す(E11c の実装のとき)。

## テスト方針

手順の一次資料: Mac の起動・撮影・合成入力は [エディタ全体設計](../エディタ全体設計.md) の E1b の「Mac での確かめ方」([E1_ImGui更新.md](E1_ImGui更新.md))と [E10_Macのエディタ.md](E10_Macのエディタ.md) のテスト方針。

**T16(ReflectionTest)**

- (a)(E11a、全構成)`IntersectRayAABB`(当たる・外れる・始点が中・軸に平行・後ろ向き)、`ScreenPointToRay` と `WorldToClip` の往復(画面の中央・四隅で、レイの上の点を写すと元の正規化座標に戻る。許容 1e-4)。
- (b)(E11b、Debug)T6 の試験データ(実体ノード・子・参照ノード)を `LevelEditModel` に読んでプレビューを作り(T8 と同じ `Engine::Create` の環境)、すべての実体ノードに `FindPreviewEntities` があること、参照ノードの部分木のエンティティがすべてその参照ノードの `editId` に引けること、`FindEditIdOfEntity` が逆に引けること、`ReleasePreview` で空になること。
- (c)(E11c、Debug)`GizmoMath` のワールド ↔ ローカルの往復(親の回転・平行移動・一様と非一様の拡縮あり。ローカル → `UpdateWorld` と同じ規則でワールド → 逆算でローカルが元に戻る。許容 1e-4)。`CompositeCommand` の実行・取り消し・やり直しでモデルの JSON が戻ること、**途中の子が失敗したときにモデルの JSON が実行前と同じ**であること(2 つ目の子に存在しないノードを指す `SetFieldCommand` を入れる)。Transform の無い実体ノードへの `AddComponentCommand("Transform")` の実行・取り消し・やり直し(取り消しで Transform が外れ、モデルの JSON が実行前と同じ)。インスペクターと同じ `RemoveComponent`(`ignoreAddable = false`)では今までどおり Transform を外せないこと。

## E11a の結果(2026-11-26、Mac 機。実装とビルドまで)

- 確かめたこと: 通常のツリーの Game・Sample・ReflectionTest の Debug / Release、エディタのツリーの Editor.app の Debug / Release がビルドでき、警告は既存のものだけ。ReflectionTest は Debug 427/427・Release 185/185(T16(a) は 14 件)。**起動・撮影・合成入力・ユーザー確認はしていない**(E10 と同じく後回し)。
- 実装で決めたこと:
  - `Main` へ書くのは `OnBeginFrame` の `PlayModeController::ApplyPendingRequest` の直前(同じフレームに Play が来ても、控えるのは編集用カメラの最新の状態になる)。
  - 表示名は `Scene###Game View` / `Game###Game View`。`###` から後ろが ID なので、ID は今までの `Game View` と同じ(一時プログラムで `ImHashStr` の値が一致することを確かめた)。`editor_layout.ini` の配置は失われない。
  - ドラッグの開始は、画像と同じ大きさの `InvisibleButton` の `IsItemHovered` で判定する(ポップアップなどがあるときは始まらない)。Edit でなくなった・画像が見えなくなったらドラッグをやめる。
  - グリッドの間隔はカメラの高さが 10 未満で 1 m、100 未満で 10 m、それ以上で 100 m。10 本ごとに太い線。補助線は、このフレームの画を描いた `Main` で投影する(入力から `Main` への反映は 1 フレーム遅れ)。
  - `GameViewInput` は Alt の押下をエディタ用の列のキーイベントから追い、アプリが裏に回ったら外す。右ドラッグ中は文字の入力も転送しない。
  - `ScreenPointToRay` のレイの始点は near の面の上で、向きは正規化済み。`IntersectRayAABB` は外れたとき距離を変えない。
- 既知の課題: スクリーン → レイの計算が Terrain の 2 か所と重複する(README の既知の課題に記録)。
