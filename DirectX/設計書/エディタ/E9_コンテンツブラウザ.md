## 7.10 E9 の詳細(2026-11-25 追記)

設計は Mac 機で書いた。Editor.exe は Windows 専用(E10 まで)なので、**Editor の起動と自動操作は Windows 機**で行う。Mac 機ではエンジンの CMake ビルドと ReflectionTest(T15)までを確かめられる。

### 現状(調査結果。5ae6e12 で確認)

| 項目 | 実コード |
|---|---|
| パネル | `EditorLayer::OnBuildUI` がエディタ用コンテキストで `Hierarchy` / `Inspector` / `Console` を描く(`OnBeginFrame` は保留中の操作の適用・モードの遷移・入力の処理)。`Window` メニューは Console の開閉だけ。初期配置(`SetupInitialLayout`)は `Hierarchy` の配置の保存が無いときに 1 回だけ |
| パスのフィールド | `FieldPath(key, path, label, FieldAttr{}.Asset(kind))`。`AssetKind` は `None / Model / Texture / Prefab / Level / Particle / Audio`(`ECS/FieldAttr.h`。E6b で入れたがまだ誰も読まない)。描画は `fieldwidget::DrawString`(`ImGuiFieldVisitor.h`)で、`ImGuiFieldVisitor`(Play 中のインスペクター、ゲームのデバッグ UI)と `ImGuiEditEventVisitor::CommitOnEnter`(Edit のインスペクター)が共有する。Enter で確定し、値が変わったら true。編集イベント Visitor は true のとき `Begin`(前の値)と `Commit` を同じフレームに出し、インスペクターが `SetFieldCommand` にする(Undo は E8a で対応済み) |
| ツリーのドラッグ | `PrefabNodeDrawTree` がノードを `PREFAB_NODE_DRAG_PAYLOAD`(荷物はノードのポインタ)のドラッグ元にし、ノードの上を Move のドロップ先にする(`enableMove` のとき)。Hierarchy は `allowRefChild = false`。ルート列の見出しは `HierarchyPanel::DrawRootHeader` が自前でドロップ先にし、荷物のポインタが今のモデルにあるかを `ContainsNode` で確かめてから読む |
| 参照ノード | `PrefabEditNode::prefabRef` が空でなければ参照ノード。`LevelEditModel::InsertNode` は参照ノードの下・ファイル参照の subLevel へは入れない。`PrefabNodeToJson` は参照ノードを `{ name, prefab, overrides }` で書き(override は `overridesRaw` から。E4a)、実体ノードは `{ name, components, children }` |
| Prefab の参照の解決 | `PrefabSerializer` の `JoinPath(baseDir, rel)`。`baseDir` は Level ならそのファイルのディレクトリ(`LevelEditModel::GetBaseDir`、新規は空)、Prefab ならその Prefab のディレクトリ。`..` は畳まずにそのまま `fopen` へ渡す。循環の検出は結合した文字列の比較。参照ノードの `overrides.children` で足した子(`PrefabEditNode::children` ではなく `overridesRaw` の中にある)も、呼び出し側の `baseDir` で解決される |
| パスの書き方 | コンポーネントのパス(model / texture / particle など)は作業ディレクトリ(`DirectX/Game`)からの `Assets/...`。Prefab の参照は `baseDir` からの相対(試験データの `"T6_Base.prefab.json"`)。`Game/Assets` に `.prefab.json` はまだ無い |
| アセット | `Game/Assets` は 81 ファイル(png 27、json 20、fbx 8、wav 7、DDS 6 など)。拡張子の大文字小文字が混ざる(`.DDS` と `.dds`) |
| ディレクトリの列挙 | 共通の口は無い。`std::filesystem` は `LevelEditModel.cpp`・`AssetPath.cpp` などで使っている。Editor は C++20 |
| Prefab エディタ | `PrefabEditorPanel`(`ECS/PrefabEditor.h`)。ゲーム用コンテキストの DebugUI の `Tools` に登録(`AppHost` が持つ。外から引く口は無い)。パスは `char pathBuf_[260]`、`Load()` は失敗で `EngineAssertMsg`。変更の有無は持たない。`SpawnPreview()` は `PrefabSerializer::FromJson(json)` を `baseDir` なしで呼ぶ(相対の参照は作業ディレクトリ基準で解決される)。DebugUI は `AppHost` の `showDebugUI_` が false(F1・中クリックで切り替え)だとパネルごと描かれない |
| Level を開く | `LevelFileMenu::BeginOpen` が dirty なら確認のモーダルを出してからパスのモーダル。パスを決めて開く口(パスのモーダルを飛ばす)は無い |
| 試験 | ReflectionTest が Editor の `.cpp` を直接コンパイルして T13(コマンド)・T14(`ConsoleLog`)を試している |

### 決定

E9 を 2 段に分ける。**E9a: 一覧とパスのドロップ** → **E9b: Prefab の作成と配置**。

**1. アセットの一覧(E9a。`Editor/AssetCatalog.h/.cpp`、新規。ImGui に依らない)**

- 根は作業ディレクトリからの `Assets`(パスの書き方と合わせる)。`std::filesystem::recursive_directory_iterator` ではなく、フォルダごとに `directory_iterator` を回して木を作る。`std::error_code` の版だけを使い、読めないフォルダは飛ばしてログに 1 行出す。シンボリックリンクはたどらない。名前が `.` で始まるものは出さない。
- 持つもの: `AssetFolder { name, path, std::vector<AssetFolder> folders, std::vector<AssetEntry> files }`、`AssetEntry { name, path, AssetKind kind }`。`path` は `Assets/...` の `/` 区切り。並びはフォルダ・ファイルとも名前の大文字小文字を無視した順。
- 種類の判定 `ClassifyAsset(path) -> AssetKind`(拡張子は小文字にして比べる):

| 種類 | 拡張子 |
|---|---|
| Prefab | `.prefab.json` |
| Level | `.level.json` |
| Model | `.fbx` `.tkm` |
| Texture | `.png` `.dds` `.jpg` `.jpeg` `.tga` |
| Particle | `.particle` |
| Audio | `.wav` `.ogg` |
| None | それ以外(一覧には出すが、ドラッグできない) |

- 読み直しは、パネルを初めて描くとき・`Refresh` ボタン・Prefab を作った後(E9b)だけ。ファイルの監視はしない(ホットリロードは 13 章の別機能)。81 ファイルなので全体を読み直す。選んでいたフォルダはパスで覚え、読み直して無くなっていたら根に戻す。

**2. ドラッグの荷物(E9a。`aqEngine/Editor/AssetDragDrop.h`、新規。`AQ_DEBUG_IMGUI` の中)**

インスペクターのパスのフィールド(エンジン)とコンテンツブラウザ(Editor)が同じ荷物を読み書きするので、エンジンに置く。

- 種類名 `ASSET_DRAG_PAYLOAD = "AQ_ASSET"`。荷物は固定長の `AssetDragPayload { AssetKind kind; char path[512]; }`(ImGui が写しを持つので固定長にする。512 は `DrawString` の入力の長さと同じ。NUL を除いて 511 バイトを超えるパスはドラッグ元にしない)。
- `bool SetAssetDragPayload(AssetKind, const std::string&)`(`BeginDragDropSource` の中で呼ぶ)、`bool AcceptAssetDragPayload(AssetKind accept, std::string& outPath)`(`BeginDragDropTarget` の中で呼ぶ。`GetDragDropPayload` で種類を先に覗き、**種類が違えば `AcceptDragDropPayload` を呼ばない**(受けられない所を光らせない。7.9 節の E7a の結果と同じ流儀)。`accept == None` は何も受けない)。

**3. パスのフィールドへのドロップ(E9a。エンジン)**

- `fieldwidget::DrawString` で、`InputText` の直後に `attr.asset != None && !attr.readOnly` ならドロップ先にする。受けた値が今の値と違えば `value` を書き換えて true を返す(Enter で確定したときと同じ扱い)。
- これで Edit のインスペクターでは `Begin` / `Commit` → `SetFieldCommand` になり、Undo できる(新しいコマンドは要らない)。Play 中のインスペクター(`ImGuiFieldVisitor`)では実行中の値を直接変える(Enter での入力と同じ。履歴に残らない)。ゲームのデバッグ UI はゲーム用コンテキストで、荷物が来ないので変わらない。
- 参照ノードのパスへのドロップも `SetFieldCommand` なので override になる(7.9 節 8. のとおり)。

**4. コンテンツブラウザのパネル(E9a。`Editor/Panels/ContentBrowserPanel.h/.cpp`、新規)**

- ウィンドウ名 `Content Browser`。エディタ用コンテキストで描く。`Window` メニューに Console と同じく開閉を足す。初期配置では Console と同じ下の区画にタブで入れる(既に配置の保存がある環境では、Console のときと同じく浮いて出る)。
- 左右 2 列の表(`BeginTable`、列の幅は動かせる)。左はフォルダの木(`TreeNodeEx`、選んだフォルダを強調)。右は上に今のフォルダのパスと `Refresh`・絞り込みの入力(名前の部分一致、大文字小文字を無視)、下に今のフォルダのサブフォルダとファイルの列(`Selectable`。先頭に種類の短い印 `[M]` `[T]` `[P]` `[L]` `[FX]` `[A]`、フォルダは `[D]`)。サムネイルは作らない。
- 操作:

| 操作 | 動作 |
|---|---|
| ファイルにホバー | ツールチップにパス |
| 種類のあるファイルをドラッグ | `AQ_ASSET` の荷物(ドラッグ中の表示は名前) |
| サブフォルダをダブルクリック | そのフォルダへ移る |
| `.level.json` をダブルクリック(Edit のときだけ) | Level を開く(5.) |
| `.prefab.json` をダブルクリック | Prefab エディタで開く(E9b。8.) |
| 右クリック | `Copy Path`(`ImGui::SetClipboardText`) |

- パネルは `EditorContext` を読むだけで、ほかのパネルを直接呼ばない。Level を開く要求はパネルが持ち、`EditorLayer` が取り出して `LevelFileMenu` へ渡す(5.)。

**5. ブラウザから Level を開く(E9a)**

- `LevelFileMenu::BeginOpenPath(context, path)` を足す。dirty なら既存の確認のモーダル(`ConfirmAction::Open`)を出し、`Discard` を選んだらパスのモーダルを出さずに `RequestOpen(path)` する。dirty でなければすぐに `RequestOpen(path)`。確認のモーダルの既存の動き(メニューからの Open)は変えない(どちらの Open かは、控えた開くパスが空かどうかで分ける)。
- `ContentBrowserPanel` はダブルクリックで `pendingOpenLevel_` にパスを入れるだけ。`EditorLayer` がパネルを描いた後に `TakeOpenLevelRequest()` で取り出して `BeginOpenPath` を呼ぶ。Edit 以外では要求を作らない。

**6. ヒエラルキーのノードから Prefab を作る(E9b。`Editor/PrefabAuthoring.h/.cpp`、新規。ImGui に依らない)**

ノードをブラウザのフォルダ(左の木の項目、または右の列の空いた所 = 今のフォルダ)へドロップすると、そのフォルダに `.prefab.json` を作り、元のノードを参照ノードに置き換える。

- 受けるのは `PREFAB_NODE_DRAG_PAYLOAD`。Hierarchy の見出しと同じく、荷物のポインタが今のモデルのノードかをアドレスで確かめてから読む(`LevelEditModel` から木を探す関数を、Hierarchy の `ContainsNode` と共有する形で `Editor` 側に 1 つにまとめる)。
- 受けない: Edit でないとき(ファイルを書く前に判定する。`Submit` が捨てても書いたファイルは残るので)、**参照ノードそのもの**(参照の参照になり、override の意味が変わるため。必要になったら E12 で扱う)、`editId == 0` のノード。子孫に参照ノードがあるのはよい。
- 中身: `PrefabNodeToJson(node)` をルートにした JSON。**その JSON の中のノードの `prefab` が相対なら、Level の `baseDir` 基準から新しい Prefab のディレクトリ基準に書き換える**(`RebaseReference(ref, fromDir, toDir)`。絶対パスは変えない。相対の判定は `JoinPath` と同じ)。たどるのはノードの JSON の `children` と、参照ノードの `overrides.children`(足した子・既存の子への override のどちらも。`PrefabSerializer` が同じ `baseDir` で解決するため)を再帰したもの。コンポーネントの中の値(`Spawner` の `prefab` など)とコンポーネントのパス(`Assets/...`)は作業ディレクトリ基準なので変えない。`editId` は書かれない(`PrefabNodeToJson` が書かない)。
- ファイル名: ノード名のうち `\ / : * ? " < > |` と制御文字を `_` にし、前後の空白を落とす。空なら `Node`。`<名前>.prefab.json` が既にあれば `<名前>_1` から順に空いている名前を探す(**既存のファイルを上書きしない**)。
- 書き込み: `JsonSerializer::WriteFile`(LF。先頭のコメントは付けない)。失敗したらモデルは変えず、ブラウザの上に赤で理由を出す。
- 参照ノードへの置き換え: `ReplaceWithReferenceCommand(nodeId, prefabRef, name)`(`Editor/Commands/NodeCommands.h` に足す)。`prefabRef` は Level の `baseDir` からの相対(`MakeReferencePath(baseDir, assetPath)`。`baseDir` が空なら `Assets/...` のまま)。`Execute` は元のノードを `DetachNode` で取り外して控え、同じ置き場所に `{ name, prefabRef }` の参照ノード(override なし)を `InsertNode` する(初回に ID が振られ、やり直しでは同じ ID のまま戻る)。`Undo` は参照ノードを取り外して元のサブツリーを同じ場所へ戻す(子孫の ID も戻る)。選択が消えたノードを指していたら `ApplyPending` が外す(既存)。
- **Undo してもファイルは消さない**(7.7 節の表のとおりファイルは操作 1 回につき 1 回書くだけ。消すとやり直しで参照先が無くなる)。ログに `[editor] prefab created: <path>` を出す。
- 書いた後にブラウザを読み直し、作ったファイルを選んだ状態にする。

**7. Prefab をヒエラルキーへ置く(E9b)**

- ドロップ先: ルート列の見出し(その列の末尾)と、実体ノードの上(その子の末尾)。参照ノードの上・ファイル参照の subLevel は受けない(`InsertNode` の制約と同じ。`allowRefChild = false` の判定を流用)。
- `PrefabTreeDrawOptions` に `acceptPrefabDrop`(既定 false)を足し、true なら `PrefabNodeDrawTree` がノードの上で `AQ_ASSET`(種類 Prefab)を受けて、操作要求 `PrefabNodeOpKind::DropPrefab`(`target` = 親のノード、`PrefabNodeOp` に足す `std::string assetPath`)を返す。Prefab / Level エディタは false のままなので挙動は変わらない。
- `HierarchyPanel` は `DropPrefab` と見出しへのドロップを `CreateReferenceNodeCommand(parent, index, name, prefabRef)`(新規。`CreateNodeCommand` と同じ形で、作るノードが参照ノード)にする。名前はファイル名から `.prefab.json` を除いたもの。`prefabRef` は 6. と同じ `MakeReferencePath`。選択は変えない(`CreateNodeCommand` と同じ。作ったノードを選ぶ仕組みは今は無い)。
- 置いた参照ノードは Prefab のルートの Transform をそのまま使う(override なし)。位置を変えるのはインスペクター(override になる)。
- 相対の参照ができるので、以後の Save As は同じディレクトリだけになる(7.9 節の `CanSaveTo` の既存の規則)。

**8. Prefab エディタで開く(E9b。エンジン)**

- `PrefabEditorPanel::OpenFile(const std::string& path) -> bool` を足す。`pathBuf_`(260 バイト)に入らない長さ(NUL を除いて 259 バイト超)なら切り詰めずに false。読めたらウィンドウを表示にする。**失敗は assert せず false**(ログに理由)。既存の `Load()` ボタンの動きは変えない。
- **Prefab エディタのプレビューを Prefab のディレクトリ基準にする**: `PrefabEditorPanel` に `baseDir_` を持たせ、`Load()` / `OpenFile` で読んだファイルのディレクトリ、`NewPrefab()` で空にする。**`Save()` では変えない**(JSON の中の相対参照は書き換えずにそのまま書くので、別のフォルダへ保存したファイルは参照先がずれる。これは今の `Save()` にもある問題で、E9 では直さず README の既知の課題に記録した。プレビューは編集中の内容が作られた場所を基準にし続ける)。`SpawnPreview()` は `PrefabSerializer::FromJson(json, baseDir_.c_str())` にする(今は作業ディレクトリ基準で、6. で作る子孫に相対の参照を持つ Prefab のプレビューが壊れるため)。
- `AppHost::OpenPrefabEditor(const std::string& path) -> bool` を足す。`PrefabEditorPanel::OpenFile` を呼び、成功したら `showDebugUI_` を true にする(DebugUI を隠していても開いたパネルが見えるように)。パネルそのものは外へ出さない。
- `ContentBrowserPanel` は `.prefab.json` のダブルクリックで `AppHost::OpenPrefabEditor` を呼ぶ(`OpenFile` はファイルを読んで編集ツリーを作るだけで ImGui に触れないので、エディタ用コンテキストの描画中に呼んでよい)。失敗したらブラウザの上に赤で出す。Prefab エディタはゲーム用コンテキストの DebugUI に出る(Game View の中)。
- Prefab エディタは変更の有無を持たないので、編集中の内容は確認なしに置き換わる。README の既知の課題に記録した(直すのは別の機会)。
- Prefab エディタで保存しても、それを参照する Level のプレビューは自動では作り直さない(ホットリロードは 13 章)。

### このフェーズで作らないもの

- サムネイル、アイコン画像、グリッド表示。
- ブラウザでのファイル操作(改名・削除・移動・フォルダ作成)。改名に伴う参照の書き換えはアセット GUID(14 章、E12)と一緒に考える。
- ファイルの監視と自動の読み直し、アセットのホットリロード(13 章)。
- Level のファイル参照の subLevel をドロップで作る、Level をヒエラルキーへドロップする。
- 参照ノードそのものからの Prefab 作成、参照ノードの Prefab パスの差し替え(E12 の override 編集 UI と一緒に)。
- OS のファイルダイアログ(10 章のプラットフォーム抽象の後ろに置くもの。E10 以降)。
- Mac での確認(E10)。

### テスト方針

**T15(ReflectionTest。Editor の `AssetCatalog.cpp`・`PrefabAuthoring.cpp` と E9b のコマンドを直接コンパイルする)**

- (a)(E9a、全構成)`ClassifyAsset` の表のとおり(大文字の拡張子 `.DDS`・`.Prefab.JSON`、`.json` だけ、拡張子なしを含む 15 例)。`TestData/T15_Assets/` に小さな木(フォルダ 2 段、各種類のファイル 1 つずつ、`.` で始まるファイル)を置いて読み、木の形・並び・種類・`.` で始まるものが出ないこと。

### E9b の結果(2026-11-25、Mac 機)

- 確認したこと: Mac の CMake(`macos-ninja-metal`)で Game・Sample・ReflectionTest の Debug / Release がビルドでき、警告は既存のものだけ。T1〜T15 が Debug 413/413、Release 171/171 で PASS(T15(b) は Debug のみで 57 件。`T15_Prefab.level.json` が T6 の往復にも入って 1 件増えた。T15(a) までの件数は変わらない)。Editor の変更したファイル(`ContentBrowserPanel` / `HierarchyPanel` / `EditorContext` / `PrefabAuthoring` / `NodeCommands`)は、エンジンと同じフラグとスタブの `stdafx.h` で `clang++ -fsyntax-only` が通る。
- **未確認(Windows 機)**: Editor と Game の Win32 構成のビルド・警告、自己テスト、テスト方針の E9b の自動操作とユーザー確認。特に、ブラウザの一覧の子ウィンドウ全体(`EndChild` の直後の `BeginDragDropTarget`)がノードのドロップ先として効くこと、見出し・ノード・フォルダの項目が受けられるときだけ光ること。
- 実装で決めたこと: `PrefabNodeDrawTree` は、ドラッグ元は今までどおり `enableMove` のときだけ、ドロップ先は `enableMove || acceptPrefabDrop` のときに 1 つの `BeginDragDropTarget` の中でノードと Prefab の荷物を両方扱う。`ContainsNode` は `EditorContext` の static に移した。ブラウザのドロップ先は左の木のフォルダの項目(そのフォルダ)と右の一覧の子ウィンドウ(今のフォルダ)。Prefab を作った後の木の読み直しは**次のフレームの先頭**で行う(左の木のドロップ先は木をたどる途中にあり、その場で読み直すとたどっている参照が無効になる。本体のレビューで直した)。`ReplaceWithReferenceCommand`(履歴の名前 `Make Prefab`)と `CreateReferenceNodeCommand`(`Place Prefab`)は、`prefabRef` が空なら false。`ReplaceWithReferenceCommand` は挿入に失敗したら元のサブツリーを戻して false。`PrefabEditorPanel::OpenFile` は失敗したら入力欄のパスを元に戻す。`CreatePrefabFromNode` はフォルダを作らない(無ければ書き込みの失敗)。
- 分かったこと: `MakeReferencePath` / `RebaseReference` は字句だけで相対パスを作る(`lexically_relative`)。基準と対象の片方だけがシンボリックリンクを含む絶対パスだと、`..` の列が実際のフォルダとずれる(macOS の一時フォルダ `/var` → `/private/var` で T15(b) が最初に失敗した。試験は一時フォルダを `canonical` にして避けた)。Editor の通常の使い方(どちらも作業ディレクトリからの `Assets/...`)では起きない。README の既知の課題に記録した。
