### 決定(Codex レビュー 3 回で計 5 点の重大な見落としを指摘され、実コードで確認して直した版)

1 回目: (1) `D3D12ImGui`(E1a)は匿名名前空間の static グローバルでヒープ・フォント変換状態を 1 組しか持たず、2 コンテキストを同時に扱えない。(2) バックバッファは `CopyToBackBuffer` の複写先専用で RTV を持たない。ほかに「`FrameContext` ではなく `FrameSlot`/`Submit()` の引数で運ぶ」「`AppHost` のメンバを ifdef で増減させない」「`GetImGuiTextureId` は既存の `GetRenderTargetSRVShared` 経由で足りる」。
2 回目: (3) 公式バックエンドはレンダー時に「現在の ImGui コンテキスト」の `BackendRendererUserData` を読むため、レンダースレッドでの明示的な `SetCurrentContext` が要る。(4) `CreateBackBuffers()` の時点では `rtvHeap_` が未初期化(`CreateRtvDsvHeaps()` より前に呼ばれる)。
3 回目: (5) **2 コンテキストで別々のヒープ(インスタンス)を使う設計は、共有フォントアトラスと両立しない**。共有アトラスの `ImTextureData` は単一の `TexID`/`BackendUserData` しか持たないため、先に生成した側のインスタンスの GPU ディスクリプタをもう一方がそのまま使ってしまい、`ResolveUserTextures()` は `_TexData != nullptr`(フォント等)を変換対象外にしているので別ヒープのハンドルのまま描画される。

この (5) を受けて、**ヒープ/バックエンドのインスタンスを 2 つに増やす設計(`D3D12ImGuiInstance` の新設)は撤回し、E1a の `D3D12ImGui`(単一の匿名名前空間 static)をそのまま使う**。

4 回目のレビューで、「`io.BackendRendererUserData` のポインタだけをもう一方のコンテキストへ共有する」という当初の直し方は不十分と判明した。公式の `ImGui_ImplDX12_Init()`(`imgui_impl_dx12.cpp:991-1023`)は、current なコンテキストの `io.BackendFlags |= ImGuiBackendFlags_RendererHasTextures` と、そのコンテキストの `ImGui::GetMainViewport()->RendererUserData` も合わせて設定する。これらはコンテキストごとの状態(メイン viewport は各コンテキストが個別に持つ)なので、ポインタ共有だけでは埋まらず、共有アトラスの整合性チェック(`imgui.cpp:9780-9798` の `UpdateTexturesNewFrame`。`atlas->RendererHasTextures == has_textures` を assert する)に落ちる。

**正しい直し方は、ヒープそのものは 1 つのままで、`ImGui_ImplDX12_Init()` 自体をコンテキストごとに正式に呼ぶこと。** `ImGui_ImplDX12_Init()` は呼ばれた時点の current context 専用の `ImGui_ImplDX12_Data`(PSO・ルートシグネチャ等も含めて)を新規に 1 つ作り、`bd->InitInfo = *init_info`(ディープコピー)で `SrvDescriptorHeap`/`SrvDescriptorAllocFn`/`FreeFn` の**値だけ**を引き継ぐ(`imgui_impl_dx12.cpp:999`)。ヒープの実体そのものは共有したまま、コンテキストごとに独立した正しい内部状態(`BackendFlags`、メイン viewport の `RendererUserData`、将来 Multi-Viewport を有効にしたときの `PlatformIO` コールバック)を公式コードに作らせられる。`ImGui_ImplDX12_Shutdown()` が解放するのは PSO・ルートシグネチャ・アップロードバッファ等(`bd` が所有するもの。`imgui_impl_dx12.cpp:935-949`)だけで、共有ヒープ(`pd3dSrvDescHeap` は参照を保持するだけ)には触らないことも確認済み。

- **`D3D12ImGui::InitEditor()`(新設)**: 既存の `Init()`(ヒープ作成・空きリスト初期化・ゲーム用コンテキストでの `ImGui_ImplDX12_Init()` 呼び出し。**変更なし**)がすでに実行済みであることを前提に、**ヒープは作り直さず**、`g_device`/`g_srvHeap`/`SrvDescriptorAlloc`/`SrvDescriptorFree` を指す**新しい** `ImGui_ImplDX12_InitInfo info2`(`Device`/`CommandQueue`/`NumFramesInFlight`/`RTVFormat`/`DSVFormat`/`SrvDescriptorHeap`/両コールバックは `Init()` と同じ値)を作り、エディタ用コンテキストが current の状態で `ImGui_ImplDX12_Init(&info2)` を呼ぶ。`ShutdownEditor()` はエディタ用コンテキストを current にして `ImGui_ImplDX12_Shutdown()` を呼ぶだけ(共有ヒープの解放は既存の `Shutdown()` が最後に 1 回だけ行う。呼び出し順は「`ShutdownEditor()` → `Shutdown()`」)。
- これは `GraphicsDevice::ImGuiInitEditor(ImGuiContext* gameCtx, ImGuiContext* editorCtx)`(新設。D3D12 以外は no-op)が `D3D12ImGui::InitEditor()` を呼ぶ形で実装し、同時に両方の `ImGuiContext*` を `D3D12GraphicsDeviceImpl` のメンバ(`gameImGuiCtx_`/`editorImGuiCtx_`)に控える(後述のレンダースレッドでの `SetCurrentContext` に使う)。`ResolveUserTextures`・`SrvDescriptorAlloc`/`Free` など `D3D12ImGui.cpp` の既存ロジックは変更しない。
- **レンダースレッドでの `SetCurrentContext` は、呼び出し側(`D3D12GraphicsDeviceImpl`)が行う。** 公式バックエンドはレンダー時に現在のコンテキストの `BackendRendererUserData` を読むため(Codex 2 回目の指摘):
  - `D3D12GraphicsDeviceImpl::ImGuiRender(ImDrawData* drawData)`(既存。ゲーム用コンテキストの描画データ)の先頭で `if (gameImGuiCtx_) ImGui::SetCurrentContext(gameImGuiCtx_);` を足す(ランタイムビルドは `gameImGuiCtx_` が未設定のままなので no-op、動作は変わらない)。
  - 新設の `RenderEditorOverlay(ImDrawData* editorDrawData)` の中で `if (editorImGuiCtx_) ImGui::SetCurrentContext(editorImGuiCtx_);` してから `D3D12ImGui::Render(editorDrawData, cmdList)`(既存の関数をそのまま呼ぶ)。
  - **これが安全な理由**: エディタ構成は 5.6 の決定で直列固定(`AQ_RENDER_PIPELINED` 無効)であり、メインスレッドは `RenderThread::Submit()` の後に `Engine::FlushRender()`(`Engine.cpp:678` 付近)→`AppHost` 経由の `WaitForCompletion()`(`AppHost.cpp:714` 付近)でレンダースレッドの完了を待ってから次フレームの UI 構築(= 次の `ImGui::SetCurrentContext` 呼び出し)に進む(Codex で確認済み)。したがってレンダースレッドが `GImGui`(単一のグローバル変数)に触れる区間とメインスレッドが触れる区間は重ならない。
  - **ユーザーテクスチャ用スロットの取り合いに注意する。** `ResolveUserTextures()` のスロット書き込みカーソル(`nextSlot`、現在は呼び出しごとにローカルで `slotBegin` へ戻る)は、1 実フレームに `ImGuiRender`(ゲーム用)と `RenderEditorOverlay`(エディタ用)の **2 回** 呼ばれるようになる。`CopyDescriptorsSimple` は CPU 側で即座にヒープを書き換えるため、同じ `slotBegin` から 2 回書き始めると、後から呼ばれた側が先に呼ばれた側のディスクリプタを GPU 実行前に上書きしてしまう(ゲーム側のデバッグパネルが `ImGui::Image` でエンジンのテクスチャを表示している状態で、エディタ側の `displayRT` 表示と同一フレームに重なると誤描画になりうる)。**このカーソルを「`ResolveUserTextures` 呼び出しごと」ではなく「実フレームごと」にリセットする**: `nextSlot` の初期値を保持する変数(フレームインデックスごとの配列)を `D3D12ImGui` 側に持たせ、リセットは(2 回呼ばれても 1 回しか走らない)`D3D12GraphicsDeviceImpl::BeginFrameIfNeeded()` の中(`frameOpen_` を立てる処理と同じタイミング)で行う。E2a の時点ではゲーム用コンテキストに入力が届かずデバッグパネルを開けない(5.1/5.7 の既知の制約)ため実際には発生しないが、E2b 以降は発生しうるため今のうちに直しておく。
- **バックバッファに RTV を足す。** 現在の初期化順は `CreateBackBuffers()`(L85)→`CreateRtvDsvHeaps()`(L86)→`CreateMainRenderTargets()`(L88)で、`CreateBackBuffers()` の時点では `rtvHeap_` がまだ無い(Codex の指摘で判明)。**`CreateBackBuffers()` 自体は変えず**、`CreateRtvDsvHeaps()` の直後に新設の `CreateBackBufferRTVs()` を呼ぶ(`RENDER_TARGET_COUNT` 枚ぶん `rtvHeap_` から `rtvNext_` を進めてスロットを確保し `CreateRenderTargetView`)。D3D12 はレンダーリサイズ未対応 = バックバッファは起動時の 1 回しか作られないため、作り直しへの追従は不要(E3b でレンダーリサイズに対応するときに合わせて見直す)。
- **`RenderEditorOverlay(ImDrawData* editorDrawData)` の D3D12 実装**: `BeginFrameIfNeeded()` → バックバッファを `PRESENT → RENDER_TARGET` へ遷移し `backBufferStates_[currentBackBufferIndex_]` を更新(`CopyToBackBuffer` の `PRESENT → COPY_DEST` と同じ形。**`Present()`(`D3D12GraphicsDeviceImpl.cpp:722-733`)は `backBufferStates_` の値を見て汎用的に `PRESENT` へ戻すので、ここを変える必要はない**ことを確認済み)→ 新設のバックバッファ RTV で `OMSetRenderTargets`→`ClearRenderTargetView`→(`editorImGuiCtx_` へ `SetCurrentContext` してから)`D3D12ImGui::Render(editorDrawData, GetCommandList())`。
- `IGraphicsDeviceImpl`/`GraphicsDevice` に新規メソッド `bool ImGuiInitEditor(ImGuiContext* gameCtx, ImGuiContext* editorCtx); void ImGuiShutdownEditor(); void ImGuiNewFrameEditor(); void RenderEditorOverlay(ImDrawData* editorDrawData);`(既定実装はすべて no-op/false。D3D12 だけ上記の実装を書く)。
- **`GetImGuiTextureId` は新しい仮想関数にしない。** `GraphicsDevice` に非仮想の `void* GetImGuiTextureId(RenderTargetHandle rt)`(戻り値は `void*`。`ImTextureID` にすると `IGraphicsDeviceImpl.h` が ImGui ヘッダに依存してしまうため、呼び出し側の Editor コードで `(ImTextureID)` にキャストする)を 1 つ足すだけでよい。実装は既存の `GetBackendName()` で D3D12 以外なら `nullptr`、D3D12 なら `GetRenderTarget(rt)->GetRenderTargetSRV().GetNativeHandle()` を返す(Hi-Z/GBuffer パネルと同じ経路の再利用で、`TransitionToSRV` は E1a の自動変換機構がそのまま行うため二重実装にならない)。
- **`IEditorLayer` は E2a では最小の 2 フックにする**(`displayRT` は引数で渡し、`Engine`/`AppHost` に新しい取得 API を足さない):
  ```cpp
  // aqEngine/Editor/IEditorLayer.h(#if AQ_EDITOR)
  namespace aq
  {
      class IEditorLayer
      {
      public:
          virtual ~IEditorLayer() = default;
          /** エディタ用コンテキストでパネルを構築する(NewFrame の後、Render の前)。gameViewRT はこのフレームの displayRT */
          virtual void OnBuildUI(aq::rendering::RenderTargetHandle gameViewRT) = 0;
          /** エディタ用コンテキストの描画データを確定する(内部で ImGui::Render() を呼ぶ) */
          virtual void OnEndFrame() = 0;
      };
  }
  ```
  5.2 で示した `OnBeginFrame` / `GetMode` は、モード切り替え(Edit/Play/Pause)が要る **E5 で追加する**(インターフェースの拡張。`RunMode.h` も E5 で新設)。E2a 時点では存在しない。
- **フックの呼び出し位置は「構築」の直後・提出の直前の 1 か所だけに置く(簡略化)。** 5.3 の最終形(手順 7、ECS の反復より前)は、エディタのコマンドが編集モデルへ反映される E4/E5/E7 になってから意味を持つ。E2a はゲームビューの表示だけなので、`AppHost::Render()` を割った直後(新設の `BuildRenderCommands()` の後、`SubmitRenderCommands()` の前)で呼ぶ。**手順の位置を 5.3 の形へ移すことは E5 の TODO として残す。**
- **`AppHost::Render()` を分割する**: `BuildRenderCommands()`(現 L772〜964、ImGui 構築から `ImGuiRenderCommand` の Enqueue まで)と `SubmitRenderCommands(ImDrawData* editorDrawData)`(現 L965-966 の `Submit`)に分ける。`editorDrawData` は **`RenderThread::Submit()` の引数列と `RenderThread::FrameSlot`(`RenderThread.h:93-114`)に足す**(`FrameContext` は `RenderThread::Run()` 内で `FrameSlot` から都度組み立てられる一時オブジェクトで、スレッド間の運搬には使えないため。`RenderThread.h` に `struct ImDrawData;` の前方宣言を 1 行足す)。`Run()`(`RenderThread.cpp:173-183` 付近)は、`slots_[slot]->editorDrawData` が非 null なら `GraphicsDevice::Get().RenderEditorOverlay(editorDrawData)` を呼んで **`CopyToBackBuffer` を呼ばない**。null なら既存どおり `CopyToBackBuffer`。`Present()` はどちらの場合も呼ぶ(既存のまま)。この分岐はデータ駆動(`editorDrawData` の有無)であり `RenderThread.cpp` に `#if AQ_EDITOR` を書く必要はない(Game.exe は `editorDrawData` を常に null のまま渡すので既存の `CopyToBackBuffer` 経路から変わらない)。
- **`AppHost` のメンバ変数は ifdef で増減させない(3.5 節の規約)。** `class IEditorLayer;` の前方宣言と、メンバ `IEditorLayer* editorLayer_ = nullptr;`、トリビアルな inline setter `void SetEditorLayer(IEditorLayer* layer) { editorLayer_ = layer; }` は **常にコンパイルする**(ポインタ 1 個なのでランタイムビルドでも無害。ポインタを保持するだけなら前方宣言で足り、完全な型は不要)。`#if AQ_EDITOR` で囲むのは、完全な `IEditorLayer` 型が要る箇所 ── `AppHost.cpp` 側の `#include "Editor/IEditorLayer.h"` と、`editorLayer_->OnBuildUI(...)`/`OnEndFrame()` を実際に呼ぶ数か所の呼び出しだけ(3.5 節の「エンジンの入口」に該当)。登録は `DebugUI::Register` と同じ非所有ポインタの考え方(`IAppModule` のような所有・コンストラクタ注入は使わない。Editor 側のオブジェクトのライフタイムは `EditorMain.cpp` が持つ)。
- **`Engine` に `AppHost* GetAppHost() const` を 1 つ足す。** `EditorMain.cpp` が `SetEditorLayer()` を呼ぶ公開経路が無いため(`appHost_` は private)。既存の `GetPlatform()`(`Engine.h:227`)と同じ形の inline アクセサを、同じ `public:` ブロック(`Engine.h:260` 付近)に足す。
- **2 つの ImGui コンテキストとフォントアトラスの共有、バックエンドの接続順序**: `AppHost::Initialize` の既存の `CreateContext()`(L256)の直後、`AQ_EDITOR` のときだけ `ImFontAtlas* sharedAtlas = ImGui::GetIO().Fonts;` を控えて `editorImGuiContext_ = ImGui::CreateContext(sharedAtlas);` を作り、**`ImGui::SetCurrentContext(gameImGuiContext_)` で明示的にゲーム用へ戻す**(`CreateContext` が暗黙に current を変えるかに依存しない)。既存のフォント読み込み・スタイル設定(L285〜376)はゲーム用コンテキストのまま今までどおり実行する(アトラス共有によりエディタ側にも反映される)。
  続く既存のバックエンド初期化(L377-384: `platform->ImGuiInit()` と `GraphicsDevice::Get().ImGuiInit()`)は、**ランタイムビルドでは現状のまま**(win32+DX12 を同じ唯一のコンテキストへ)。**`AQ_EDITOR` のときは win32 をゲーム用コンテキストへ接続しない**(5.1 の方針。`platform->ImGuiInit()` の呼び出しをここではスキップし、DX12 の `GraphicsDevice::Get().ImGuiInit()`(ゲーム用インスタンス)だけ呼ぶ)。その後 `ImGui::SetCurrentContext(editorImGuiContext_)` に切り替え、`io.ConfigFlags |= ImGuiConfigFlags_DockingEnable`、`io.IniFilename = "editor_layout.ini"`(ゲーム用の `imgui.ini` と分ける)、`ImGui::StyleColorsDark()` を設定してから `platform->ImGuiInit()`(win32 → editor ctx)と `GraphicsDevice::Get().ImGuiInitEditor()`(DX12 editor インスタンス)を呼び、最後に `ImGui::SetCurrentContext(gameImGuiContext_)` へ戻す。
  - **終了処理の順序(5 回目の Codex レビューで指摘)**: `ImGui_ImplDX12_Shutdown()`(`imgui_impl_dx12.cpp:963` 付近)は参照カウントが 1 になったテクスチャを破棄する。両コンテキストが生きている間はフォントアトラスの参照カウントが 2 のままなので、**`ShutdownEditor()` → エディタ用コンテキストを `ImGui::DestroyContext()` → ゲーム用コンテキストへ `SetCurrentContext` → 既存の `Shutdown()` → ゲーム用コンテキストを `DestroyContext()`** の順で呼ぶ(エディタ側を先に破棄して参照カウントを 1 に落としてから、ゲーム側の `Shutdown()` にフォントテクスチャとディスクリプタを解放させる)。逆順(先に `Shutdown()`、後で `ShutdownEditor()`)やコンテキストを先に `DestroyContext` してしまう順序は GPU リソースリークになるので避ける。
  - **既知の未確認点(実装時に grep して確認する。TODO)**: `IPlatform::ImGuiNewFrame()`(= `ImGui_ImplWin32_NewFrame()`)の既存の呼び出し箇所。ゲーム用コンテキストには win32 バックエンドを接続しなくなるため、**ゲーム用コンテキストが current のときにこの呼び出しが走ると未初期化の `BackendPlatformUserData` を踏んで assert する**。呼び出し位置を特定し、エディタ構成では「エディタ用コンテキストが current のときだけ呼ぶ」に変える(具体的には、新設する「エディタ用コンテキストへ切り替えて `OnBuildUI`/`OnEndFrame` を呼ぶ」ブロックの先頭で呼ぶのが自然)。
  - **この結果、E2a の時点ではゲーム用コンテキストのデバッグ UI はゲームビュー内に表示されるが操作できない(クリックが効かない)。既知の制約であり、E2b で解決するため 11.3 の E2a チェック対象には含めない。**
- **ゲームビューパネルは Editor プロジェクト側に実装する。** `IEditorLayer::OnBuildUI(gameViewRT)` で受け取った `RenderTargetHandle` を使い、`ImGui::DockSpaceOverViewport()` の中で `ImGui::Image((ImTextureID)GraphicsDevice::Get().GetImGuiTextureId(gameViewRT), size)` を、アスペクト比を保って表示する(5.5 の方針どおりレンダー解像度は変えない)。戻り値が `nullptr` のときは「未対応」の文字列を表示する。ファイルは `Editor/EditorLayer.h/.cpp`(E2a 時点では唯一のパネルなので分けない。`Editor/Panels/` への分割は E7 でパネルが増えてから行う)。

### このフェーズで作らないもの(次フェーズへ)

- ゲーム用コンテキストへの入力転送、ゲームビューのフォーカス判定(`SetFocusBlocked`) → E2b
- Multi-Viewport(`ImGuiConfigFlags_ViewportsEnable`) → E3a
- D3D11 / Vulkan のエディタ合成 → E3a
- `RunMode` / `OnBeginFrame` / モードに応じた更新の切り替え → E5
- `EditorContext`(選択・コマンドスタック) → E7/E8

## 5.8 E2b の詳細(2026-11-19 追記)

対象は E2a と同じく **D3D12 の Editor.exe**(Editor は D3D12 構成しか持たない)。Windows 機で進める。

### 現状(調査結果。9c3c207 で確認)

| 項目 | 実コード |

### 決定

Codex レビュー 1 回目の指摘 7 件(重大 3・中 3・軽 1)は、すべて実コードで確かめて採用した: 転送するキーの範囲(マウスの別名で assert)、OS のフォーカスに `io.AppFocusLost` は使えない、ランタイム構成で `unique_ptr` の型が不完全、前フレームの判定と今フレームの入力の混在、`SuppressMouse` でゲーム内 UI の押下表示が残る、文字は `InputText` に消費される、テストの合否条件の不足。
2 回目の指摘 2 件(中)も確かめて採用した: 転送が 1 フレーム遅れるとゲーム用の `WantCaptureMouse` とゲームの入力の判定がずれる、前フレームの `focused` だけでは、フォーカスを移すクリックがゲームの入力で失われる(ImGui のクリックによるフォーカス移動は `EndFrame`)。転送を `Update()` の先頭へ移し、ゲーム側のフォーカスに「このフレームで中をクリックした」を含める形にした。
3 回目の指摘 2 件(重大 1・中 1)も確かめて採用した: エディタ用の `NewFrame` を先に行うと共有フォントアトラスの検査で assert する(所有者のゲーム用が先に `NewFrame` する必要がある)、アクティブな `InputText` を `editorHoldsMouse` に含めると最初のクリックが失われる。`NewFrame` の順序は変えず、エディタ用の入力キューを覗いて転送する形にし、`editorHoldsMouse` はマウスを押して操作中の項目だけにした。
4 回目の指摘 2 件(中)も確かめて採用した: win32 の `NewFrame` が補う Shift / Win キーの離しが覗き見の後に積まれて消える、trickle で `io.MousePos` が覗き見で読んだ位置より古くなる。win32 の `NewFrame` を覗き見の前へ移し、マウス位置は転送器が自分で覚える形にした。
5 回目の指摘 1 件(重大): 初回の `Update()` ではゲーム用が current のまま(エディタ用へ切り替えるのはフレーム末尾の `FlushRender`)で、win32 の `NewFrame` が未接続のコンテキストで assert する。エディタ用を明示して current にする形にした。6 回目は指摘なし。
その後、ユーザーの決定(0)で、転送と判定を AppHost(エンジン)から Editor プロジェクトへ移した(方式は 6 回目までと同じ)。

**0. 置き場所の方針(ユーザー決定 2026-11-19)**

**エンジンはゲームのためのもの、エディタはエディタのもの**と分ける。E2b のエディタの機能(ゲームビューの状態、入力の転送、ゲームビューのフォーカスでゲームの入力を止める判断)は **Editor プロジェクト**に置く。エンジンには、エディタが差し込むための**口だけ**を足す。3.3 節の「パネル・コマンド・Undo は Editor プロジェクトに置く」と同じ考え方。

| エンジンに足す口 | ランタイム(Game.exe)への影響 |
|---|---|
| `IEditorLayer::OnBeginFrame(ImGuiContext* gameContext)` と、その呼び出し(`AppHost::Update` の先頭) | `#if AQ_EDITOR` の中だけ。ランタイムには入らない |
| `InputManager::SetPointerView`(カーソルの換算と範囲外のマウスの扱い) | 入るが呼ばれないので動作は変わらない。「画面の一部に縮小して出した絵」への汎用の口として書く。DirectInput のカーソルはエンジンの中で読むので、外からは差し替えられず、エンジンに口が要る |
| `IPlatform::IsAppActive()`(アプリが前面か) | 入るが呼ばれない。既定は true |
| `BuildRenderCommands` の先頭の assert(ImGui のコンテキストの取り違えの検出) | Debug の assert のみ |

**1. フレームの先頭のフック(エンジン)**

5.2 節の当初案にあった `OnBeginFrame` を、E2b で `IEditorLayer` に足す(E5 のモード遷移も、後でここに載せる)。

```cpp
// aqEngine/Editor/IEditorLayer.h(#if AQ_EDITOR)
struct ImGuiContext;

class IEditorLayer
{
public:
	/**
	 * フレームの先頭(InputManager::Update の前)。エディタ用コンテキストが current で、win32 の NewFrame は済んでいる。
	 * gameContext はゲーム用 ImGui コンテキスト(入力の転送先)。戻るときの current は問わない(AppHost がゲーム用へ戻す)
	 */
	virtual void OnBeginFrame(ImGuiContext* gameContext) = 0;
	virtual void OnBuildUI(const aq::rendering::RenderTargetHandle gameViewRT) = 0;   // E2a のまま
	virtual void OnEndFrame() = 0;                                                     // E2a のまま
};
```

`AppHost::Update` の先頭の順序(エディタ構成。ランタイムは今と同じ):

1. 今の入力抑制(ゲーム用を明示して `WantCaptureKeyboard` / `WantCaptureMouse`)と、埋め込み起動の `SetFocusBlocked`(今のまま)
2. **`#if AQ_EDITOR`**: エディタ用コンテキストを**明示して** current にし(初回の `Update()` は初期化の後でゲーム用が current のままなので、`FlushRender` の切り替えに頼らない)、**win32 の `NewFrame`(`IPlatform::ImGuiNewFrame`)を `Render()` からここへ移して呼び**、`editorLayer_->OnBeginFrame(gameImGuiContext_)` を呼ぶ。終わったらゲーム用を current に戻す
3. `InputManager::Update`(以降は今と同じ)

- win32 の `NewFrame` を AppHost に残すのは、どのコンテキストに win32 を繋いだかを知っているのが AppHost だけだから。ここへ移すのは、win32 バックエンドが `NewFrame` の中で、取りこぼされた Shift / Win キーの離しを補うイベントやマウス位置のイベントを積むため(`imgui_impl_win32.cpp` の `ProcessKeyEventsWorkarounds`)。`Render()` に残すと、Editor が覗き見た後に積まれ、直後のエディタ用の `ImGui::NewFrame` で処理されて消えるので、ゲーム用ではキーが押されたままになる。win32 の `NewFrame` は入力イベントと `io` の値(画面の大きさ、経過時間)を入れるだけで `ImGui::NewFrame` を呼ばないので、共有フォントアトラスの順序には関係しない。
- **`ImGui::NewFrame` の順序は変えない**(ゲーム用 → エディタ用)。共有フォントアトラスは所有者のゲーム用コンテキストの `NewFrame` で毎フレーム更新され、所有者でないエディタ用が先に `NewFrame` すると初回に assert する(`imgui.cpp` の `UpdateTexturesNewFrame`)。`Render()` のエディタのブロックは、win32 の `NewFrame` を移したほかは今と同じ(`ImGuiNewFrameEditor` → `ImGui::NewFrame` → `OnBuildUI` → `OnEndFrame`)。
- 2 を 1 の後に置くのは、Editor の `SetFocusBlocked` を最後に効かせるため。Editor は埋め込み起動の条件も OR して入れる(下の 3)。

**2. ゲームビューと入力の転送(Editor プロジェクト)**

| ファイル(Editor プロジェクト) | 中身 |
|---|---|
| `Editor/EditorLayer.h/.cpp`(既存) | `IEditorLayer` の実装。`OnBeginFrame` で `GameViewInput` を呼ぶ。`OnBuildUI` でドックスペースとゲームビューを描き、ゲームビューの状態を `GameViewInput` に渡す |
| `Editor/GameViewInput.h/.cpp`(新規) | `GameViewState`、前フレームの状態の控え、入力キューの覗き見、判定、ゲーム用コンテキストへの転送、`InputManager` への指示(`SetFocusBlocked` / `SetPointerView`)。`imgui_internal.h` を使うのはこのファイルだけ |

```cpp
// Editor/GameViewInput.h
/** ゲームビューの状態。座標はエディタ用コンテキストの io.MousePos と同じ空間(= メインウィンドウのクライアント座標) */
struct GameViewState
{
	bool  visible          = false; // ゲームビューに displayRT の画像を描いた
	bool  focused          = false; // ゲームビューのウィンドウがエディタ内でフォーカスを持つ
	bool  editorHoldsMouse = false; // エディタがマウスを使っている(ポップアップが開いている、別の項目をマウスで操作中)
	float imageMinX = 0.0f, imageMinY = 0.0f;   // 画像の左上
	float imageMaxX = 0.0f, imageMaxY = 0.0f;   // 画像の右下(黒帯を含まない)
};

class GameViewInput
{
public:
	/** OnBeginFrame から呼ぶ。前フレームの状態で今フレームの入力を振り分け、ゲーム用へ転送し、ゲームの入力を設定する */
	void BeginFrame(ImGuiContext* gameContext);
	/** OnBuildUI でゲームビューを描いた後に呼ぶ。次のフレームの振り分けに使う */
	void SetViewState(const GameViewState& state);
	// 控え: 前フレームの GameViewState、最後に読んだ EventId、覚えているマウス位置、
	//       ゲーム用へ押下を送ったボタンとキー、ゲーム側のフォーカス
};
```

**ゲームビューのパネル**(`EditorLayer::DrawGameView`):

- `ImGui::Image` の上に同じ大きさの `ImGui::InvisibleButton("##GameViewInput", size, 左・右・中ボタン)` を重ねる。押している間はこのボタンがアクティブになり、浮かせたゲームビューの中身をドラッグしてもウィンドウが動かない。
- `focused` は `IsWindowFocused()`、画像の矩形は `GetItemRectMin/Max()` から取る。`editorHoldsMouse` は `IsPopupOpen(0, AnyPopupId | AnyPopupLevel)` のとき、またはエディタの別の項目をマウスで操作中(`IsAnyItemActive() && !IsItemActive() && IsAnyMouseDown()`)のとき true。アクティブな `InputText` のようにマウスを押していない項目は含めない(ゲームビューのクリックでフォーカスを移せなくなるため)。
- `visible` が false(ゲームビューが閉じている・畳まれている・未対応の API)のときは、`focused` も false にする。
- 起動直後はゲームビューにフォーカスを与える(最初のフレームだけ `SetNextWindowFocus()`)。何もクリックしなくてもゲームを操作できる、今の Game.exe と同じ始まり方にするため。

**覗き見と転送**(`GameViewInput::BeginFrame`):

win32 のメッセージは `Update()` の前(`RunFrameLoop`)で処理され、E2a の決定でフレームの合間はエディタ用が current なので、今フレームの入力はエディタ用の入力キュー(`ImGuiContext::InputEventsQueue`)に積まれている。これを読んでゲーム用へ送ると、同じフレームのゲーム用の `NewFrame`(`BuildRenderCommands`)が受け取るので、**Game.exe と同じ遅れ**になる(エディタだけ 1 フレーム遅れることはない)。キューは読むだけで変えず、エディタ用の `NewFrame` は今どおり `Render()` の中で同じイベントを処理する。文字も、エディタのパネルの `InputText` に消費される前のイベントで取れる。

1. **覗き見**: エディタ用コンテキストの `InputEventsQueue`(`imgui_internal.h`)のうち、`EventId` が前回までに見たものより新しいイベントを、積まれた順に読む。ImGui は同じフレームのボタンの押し離しなどを次のフレームへ回すこと(trickle)があり、同じイベントがキューに残るので、`EventId` で二度送りを防ぐ。
2. **振り分け**: 1 のイベントを順に見て、下の「判定」と表で、送るイベントを決める。
3. **転送**: ゲーム用コンテキストを current にし、2 で決めたイベントを `AddMousePosEvent` / `AddMouseButtonEvent` / `AddMouseWheelEvent` / `AddKeyEvent` / `AddInputCharacter` / `AddFocusEvent` で積む。
4. **ゲームの入力**: 3 の `SetFocusBlocked` と `SetPointerView` を呼ぶ。

**判定**(イベントの中のマウス位置と、前フレームの `GameViewState`):

- マウス位置は **`GameViewInput` が自分で覚える**。マウス位置のイベントを読むたびに更新し、フレームをまたいで持ち越す(起動直後は「不明」で、外と同じ扱い)。エディタ用の `io.MousePos` は使わない。エディタ用の `NewFrame` は trickle で後ろのイベントを次のフレームへ回すので、`io.MousePos` は覗き見で読み終えた位置より古いことがあるため。すべてのイベントを積まれた順に 1 回ずつ読むので、覚えた位置は常に最後に読んだイベントの位置になる。
- **中** = `visible` かつ `!editorHoldsMouse` かつ、その時点のマウス位置が画像の矩形の中。
- **ゲーム側のフォーカス** = アプリが前面(`IPlatform::IsAppActive()`)かつ (`focused` または **このフレームで中でボタンを押した**)。ImGui はクリックしたウィンドウへのフォーカスの移動を `EndFrame` で行う(`UpdateMouseMovingWindowEndFrame`)ので、前フレームの `focused` だけを見ると、フォーカスを移すクリックがゲームの入力で失われる。中で押した時点でフォーカスがあるものとして扱い、同じクリックをゲーム用 ImGui とゲームの入力の両方へ届ける(Unity と同じ動き)。
- 矩形と `editorHoldsMouse` は前フレームの値で、マウス位置とボタンは今の値。残るずれは、ゲームビューの移動・大きさの変更の 1 フレームと、浮いたエディタのウィンドウが画像に重なっている場合(E7 で浮かせるパネルが増えたら、重なりの判定を足す。TODO)。

| イベント | ゲーム用コンテキストへ送る条件 |
|---|---|
| マウス位置 | 中のとき、またはゲーム用へ押下を送ったボタンが 1 つでも押されたままのとき(ゲームビューの外へドラッグしても離すまで追う)。それ以外になったら 1 回だけ `AddMousePosEvent(-FLT_MAX, -FLT_MAX)`(マウスが外れた扱い)。座標は `(PosX/Y - imageMin) / (imageMax - imageMin) * (レンダー幅, レンダー高さ)`。ゲーム用の `io.DisplaySize` は今どおりレンダー解像度なので、この換算でクリック位置と反応位置が合う |
| マウスボタン | 押下は中のときだけ送る。離しは、押下を送ったボタンなら場所を問わず送る |
| ホイール | 中のとき |
| キー | キーボードのキー(`ImGuiKey_NamedKey_BEGIN` 〜 `ImGuiKey_GamepadStart` の手前)と修飾キー(`ImGuiMod_Ctrl` / `Shift` / `Alt` / `Super`)だけを扱う。マウスの別名は `AddKeyEvent` で assert するので送らない(win32 バックエンドもキューに積まない)。押下はゲーム側のフォーカスがあるときに送り、離しは押下を送ったキーなら送る |
| 文字 | ゲーム側のフォーカスがあるとき |
| フォーカス | ゲーム側のフォーカスが変わったら `AddFocusEvent(...)`。false のときゲーム用コンテキストは ImGui の仕組みで全キー・全ボタンを離した扱いにする(`ClearInputKeys` / `ClearInputMouse`)ので、送った状態の控えも同時に消す(控えと ImGui の状態を揃える)。エディタ用のキューにある win32 のフォーカスのイベントは送らない |
| その他(ビューポート、マウスの種類) | 送らない |

- ImGui を更新して `InputEventsQueue` / `ImGuiInputEvent` の形が変わったら、`GameViewInput.cpp` を直す(内部構造に頼る唯一の箇所)。
- ゲーム用の `WantCaptureMouse` は、Game.exe と同じく前のフレームのゲーム用 `NewFrame` で決まった値を使う(Game.exe と同じ遅れ。エディタで増える遅れは無い)。
- マウスカーソルの形(ゲーム用コンテキストが要求する I ビームなど)は反映しない。win32 バックエンドはエディタ用コンテキストの要求だけを見るため。必要になったら別フェーズで扱う。
- E2a で `FlushRender` の最後にエディタ用を current にしている処理(WndProc の入力をエディタ用へ届けるため)は残す。

**3. ゲームの入力の口(エンジン)と、Editor からの使い方**

- **アプリが前面か**: `IPlatform` に `virtual bool IsAppActive() const { return true; }` を足す。Win32 は `GetForegroundWindow()` のウィンドウが自分のプロセスのものなら true(`GetWindowThreadProcessId` で比べる。E3a で外へ出したウィンドウが前面でも true になる)。ImGui の `io.AppFocusLost` は一時的な値なので使わない。
- **フォーカス**: Editor は `BeginFrame` の最後に `SetFocusBlocked((埋め込みで HasInputFocus が false) || !ゲーム側のフォーカス)` を呼ぶ。埋め込み起動の条件も OR するので、AppHost が手順 1 で入れた値を消さない。XInput のパッドはウィンドウのフォーカスと無関係に読めるので、アプリが前面かも見る(ゲーム側のフォーカスに含まれる)。これでキーボード・マウス・パッドがまとめて止まる。
- **マウスの範囲とカーソル座標**: `InputManager` に `SetPointerView(const PointerView&)` を足す(エンジン)。`PointerView` は「有効か」、絵を出している矩形(クライアント座標)、「マウスを外とみなす」フラグ(Editor は `editorHoldsMouse` を入れる)を持つ。Editor は `BeginFrame` で前フレームの `GameViewState` から作って渡す(有効 = `visible`)。有効なとき `Mouse::Update` は Poll の後で次を行う。
  - **範囲の判定は Poll したカーソルで行う**。中 = フラグが立っていない、かつカーソルが矩形の中(2 の判定と同じ規則。DirectInput のカーソルとエディタ用の `io.MousePos` は同じクライアント座標)。
  - **押したままの追従**: 中で押したボタンが 1 つでもあれば、離すまで「中」として扱う(外へドラッグしても、離しがゲームに届く)。
  - **外のとき**: ボタンを全部離した扱いにし、移動量とホイールを 0 にする。`SuppressMouse` は使わない(`UIInputSystem::UpdatePointer` が何もせずに戻り、押下表示が残るため)。
  - **カーソル座標**: 中でも外でも、`(cursor - rect.min) / rect.size * (GetScreenWidth, GetScreenHeight)` に換算する。`UIInputSystem::HitTest` はクライアントサイズで割る前提なので、**矩形の中の相対位置をクライアントサイズの空間へ写す**ことで、UI 側を変えずに当たり判定が合う(UI は描画先全体へ伸ばして描かれるので、矩形の中の相対位置 = canvas の中の相対位置)。外のカーソルは canvas の外に写るので、ゲーム内 UI のホバーが外れ、`FireHoverExit` で押下表示も消える。
  - `blocked`(フォーカスなし)のときはカーソルを前フレームの値に留める今の動きを変えない。
- ゲーム用コンテキストの `WantCaptureMouse` による `SuppressMouse` は今のまま残す(Game.exe と同じ)。
- ランタイムビルドでは `SetPointerView` を呼ばないので、動作は変わらない。
- マルチビューポート(E3a)を有効にすると `io.MousePos` がスクリーン座標になる。そのときは矩形をクライアント座標へ直してから渡す(E3a の TODO)。

**4. `ImGui::GetIO()` をコンテキスト指定なしで呼ぶ箇所(11.3 の E2b の 3 項目め)**

すべて直すのではなく、**「`AppHost::Update` の 1 の手順 2 の後(エディタ構成。ランタイムは先頭)から `Render()` のエディタのブロックまではゲーム用が current」という不変条件を守り、`BuildRenderCommands` の先頭に `EngineAssert(ImGui::GetCurrentContext() == gameImGuiContext_)` を置く**。デバッグ UI(下の Terrain / UI エディタ)はこの区間で呼ばれるので、指定なしで正しいコンテキストを読む。

- **実装中に分かって足したこと**:
  - **ゲームビューはアルファを 1 に固定して表示する。** エンジンの `BlendMode::AlphaBlend` はアルファを src の値で上書きする(`SrcBlendAlpha=ONE` / `DestBlendAlpha=ZERO`)ため、ゲームの半透明 UI を描いた場所の `displayRT` のアルファが 1 未満になり、ImGui のアルファブレンドで黒く透けた(Game.exe はコピーでアルファを無視するので見えない)。ブレンド式は全バックエンドに効くので変えず、`IGraphicsDeviceImpl::GetImGuiTextureId(IRenderTarget*)`(既定 `nullptr` = 未対応)を足し、D3D12 は ImGui 用ヒープのスロットへ `Shader4ComponentMapping` のアルファを `FORCE_VALUE_1` にした SRV を描画時に作る(`D3D12ImGui::RegisterOpaqueTexture`)。`GraphicsDevice::GetImGuiTextureId` はバックエンド名の判定をやめてこれに委譲する。不透明エントリは RT の破棄経路が無い(D3D12 はレンダーリサイズ未対応)ので表から外していない。E3b で作り直しに対応するときに外す。デバッグパネルの `ImGui::Image` は従来の経路のまま(G-Buffer0 などが透ける既知の課題は、この口へ寄せれば直せる)。
  - 初回起動(`editor_layout.ini` が無いとき)は、`SetNextWindowDockID(dockspace, ImGuiCond_FirstUseEver)` でゲームビューをドックスペースいっぱいにドッキングする(指定が無いと 32 ピクセル四方の浮いたウィンドウで出た)。

  - レンダースレッドでコンテキストを切り替えた D3D12 の関数は、終わりに元の current へ戻す(メインスレッドの暗黙の前提を崩さないため)。
  - 「未対応」の表示文言は英語(`Game View: not supported on this graphics API`)。
