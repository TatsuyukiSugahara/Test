## 7.8 E4 の詳細(2026-11-19 追記)

Mac 機で進める(E4 はプラットフォームに依存しない)。D3D12 / Vulkan のデバイスロストの確認と、操作感のユーザー確認は後でまとめて行う(ユーザー指示 2026-11-19)。

### 現状(調査結果。e0c7705 で確認)

| 項目 | 実コード |
|---|---|
| 編集状態 | `LevelEditorPanel`([LevelEditor.h](../../aqEngine/Level/LevelEditor.h))が private に `name_`、`entities_`(`PrefabEditNode` のフォレスト)、`subLevels_`(`SubLevelEdit`。インラインとファイル参照)を持つ。UI の状態(`selected_`、`pendingDelete_`、`pathBuf_`、`lastAsync_`)も同じクラスにある。`AQ_DEBUG_IMGUI` のときだけコンパイルされる(`PrefabEditNode` も同じ) |
| JSON 往復 | `PrefabNodeToJson` / `PrefabNodeFromJson`([PrefabEditNodeOps.cpp](../../aqEngine/ECS/PrefabEditNodeOps.cpp))を Prefab エディタと Level エディタが共有する |
| override の文法 | `PrefabSerializer` の `ApplyPatch` / `PatchComponents` が解釈するのは `overrides` の `name`、`components`(deep-merge)、`addedComponents`、`removedComponents`、`children`(名前で同定して再帰適用・追加)、`removedChildren` |
| override の不具合 | `PrefabNodeFromJson` は `overrides` のうち `components` と `removedComponents` しか読まず、`name` / `addedComponents` / `children` / `removedChildren` を**捨てる**。`PrefabNodeToJson` は override のコンポーネントを `serializePtr` で**全フィールド**書き出す。そのため、参照ノードを読んで保存し直すと、override に既定値のキーが増え、子の override は消える。Prefab エディタの入れ子の参照ノードも同じ |
| 数値 | `JsonValue` は double を持つが、`JsonSerializer::Stringify` は `static_cast<double>(v.AsFloat())` で **float に狭めてから** `%g`(有効 6 桁)で書く。読み込みは `strtod` |
| Load in World | 編集内容を JSON → `LevelSerializer::FromJson` → `"<level-editor-preview-N>"` の新しいキーで `LevelRegistry::Register` → `LevelManager::Load`。前のプレビューはアンロードせず、登録も消さない(押すたびにエンティティと登録が増える) |
| LevelRegistry | `Load` / `Register` / `Clear` だけ。キー単位の登録解除は無い |
| 生成の完了 | `LevelManager::Load` はスロットを確保して `loaded = true` にし、生成は `RequestDeferredBuild` で次の Flush に遅らせる。完了を知る手段は無い。`LoadAsync` は `LevelLoadHandle::IsDone()` で分かる |
| 同期ロードと Unload(不具合) | `Load` の遅延生成のコマンドは、実行時に Level がまだロード済みかを確かめない。`Load` → `Unload` → Flush の順になると、`Unload` は既存のエンティティだけを破棄するので、その後でコマンドが古い `LevelId` のエンティティを作る。`Unload` は System の中(`LevelStreamSystem`)からも呼ばれるので、`Unload` の中で Flush して解決することはできない |
| 入れ子のインライン subLevel(不具合) | ランタイム(`LevelSerializer` の `Build`)はインライン定義の中の `subLevels` を再帰で読むが、`LevelEditorPanel` の `SubLevelEdit` は `name` と `entities` しか持たず、読み込みでも書き出しでも内側の `subLevels` を捨てる |
| プレビューの基準ディレクトリ | 通常のファイルロードは、相対パス(Prefab、外部 subLevel)を読んだファイルのディレクトリから解決する。`LoadInWorld` は `LevelSerializer::FromJson(root)` に基準ディレクトリを渡さないので、プレビューだけ解決の基準が違う |
| 非同期ロードと Unload(不具合) | `Unload` は `asyncLoads_` を見ない。非同期ロードの途中で Unload すると、スロットは解放されるのに、残りのジョブが古い `LevelId` のままエンティティを作り続ける(どの Level にも属さないエンティティが残る) |
| 自動リロード(不具合) | `PollFileChanges` は Unload の後に GPU の完了を待たない。`ReloadAll` は同じ理由で `WaitForRenderIdle` + `FlushPendingCommands` を入れている(D3D12 で `DXGI_ERROR_DEVICE_HUNG`)が、自動リロードには入っていない |
| 呼ばれる場所 | `LevelEditorPanel::DebugRender` と `LevelManager::Tick` は System の反復の外で呼ばれる(`ReloadAll` のコメントと `AppHost` の呼び出し順) |
| `std::to_chars` | Mac(Apple clang、デプロイ対象は既定)と iOS 16.4 の両方で、float / double の `to_chars` がコンパイル・実行できた(2026-11-19)。`from_chars` の浮動小数点版は iOS 26 からなので使わない。Android(NDK r26 の libc++ 17)は未確認。MSVC は対応済み |

### 決定

E4 を 2 段に分ける。

| 段 | 内容 |
|---|---|
| E4a | 数値の書き出しと override の保持を直す。往復テスト(11.4)を検査ツールに足す。先に往復テストを今のコードで回し、不合格を既知の失敗として控えてから直す |
| E4b | `LevelEditModel` の切り出し、ノード ID、プレビューの置き換え(7.3)、`LevelRegistry::Unregister`、`LevelManager::IsSpawned`、Unload による非同期ロードの取り消し、自動リロードの GPU 待ち |

**1. 数値(E4a)**

- `JsonValue::AsDouble(double def = 0.0)` を足す。
- `Stringify` の数値は次の順で書く。
  1. 整数で、絶対値が 2^53 未満 → 今と同じく `std::to_string`(小数点なし)。
  2. float に狭めても同じ値になる(`static_cast<double>(static_cast<float>(d)) == d`)→ float の最短表現(`std::to_chars(float)`)。float の値を double に広げたもの(`JsonWriteVisitor` などが作る値)が `0.10000000149011612` のような表記にならないようにするため。
  3. それ以外 → double の最短表現(`std::to_chars(double)`)。
- これで、override の生 JSON の数値(テキストから読んだ double)は double のまま往復し、float のフィールドは float のまま往復する。
- **表記は変わることがある**。`%g` と最短表現は、固定小数と指数の選び方が違う(例: `0.0001` は `%g` では `0.0001`、最短表現では `1e-04`)。値は変わらない。そのため T3 は文字列ではなく値で比べる(数値は float として一致)。
- 7.2 節の「`JsonFieldVisitor` の float フィールドは float の最短表現を書き出す」は、上の 2 で `Stringify` 側が受け持つ(`JsonFieldVisitor` は今のまま double に広げて入れる)。
- 2 の規則には例外が 1 つある。float と同じ値を持つ double をわざと書いた場合(例: 他のツールが float を double で書いた `0.30000001192092896`)は、`0.3` と書き直され、double としては変わる(float としては同じ)。今のアセットには無い。11.4 節の比較はこの規則の後の値で行う。
- 読み込みは今の `strtod` のまま(`from_chars` は iOS で使えない)。
- `std::to_chars` が使えない環境が見つかったら、その時点で代わりを決める(`%.9g` は `0.1f` を `0.100000001` と書くので、そのままでは代わりにならない)。Mac と iOS 16.4 は使えた。Android は Windows 機で確かめる。

**2. override の保持(E4a)**

7.2 節の当初案は「`LevelEditModel` の保存経路では `PrefabNodeToJson` を使わない」だったが、**共有関数そのものを直す**ことに変える。Prefab エディタの入れ子の参照ノードにも同じ不具合があり、1 か所で直せるため。

- `PrefabEditNode` に、参照ノード用の 2 つを足す。
  - `overridesRaw`: 読み込んだ `overrides` の生 JSON(無ければ空のオブジェクト)。
  - 各 `PrefabEditComponent` に `loadedJson`: 読み込んだ直後に `serializePtr` で書き出した値(参照ノードの override コンポーネントだけ。新しく足したコンポーネントは空)。
- `PrefabNodeToJson`(参照ノード)は `overridesRaw` を写して始め、次だけを変える。
  - 各 override コンポーネントについて、今の `serializePtr` の値を `loadedJson` と比べ、**違うキーだけ**を `overrides.components.<typeName>` に書き足す(既存の deep-merge の意味どおり)。`loadedJson` が空(新しく足した)なら、全フィールドを書く(今と同じ)。
  - 読み込んだときにあったのに、今の一覧に無い override コンポーネントは、**読み込んだ出どころ(`overrides.components` か `addedComponents`)から消す**。両方にあった型は両方から消す。
  - 新しく足したコンポーネント(`loadedJson` が空)は `overrides.components` に全フィールドを書き、同じ型が `addedComponents` に残っていればそこから消す(`addedComponents` は後から適用されるので、残すと新しい値が上書きされる)。
  - 「違うキー」は**再帰で**求める。オブジェクトは中まで比べて違う葉だけを書き、配列とスカラーは値ごと置き換える(`JsonValue::Merge` の規則と同じ: オブジェクトは再帰マージ、配列は置換)。
  - `removedComponents` は今の一覧で置き換える(空ならキーを消す)。
  - `addedComponents` にあるコンポーネントも編集ノードに読み込み、出どころ(`components` か `addedComponents` か)を `PrefabEditComponent` に覚える。`addedComponents` は後から丸ごと上書きする意味なので、出どころが `addedComponents` のコンポーネントは、変わっていれば全フィールドを `addedComponents` に書き戻す(`components` には書かない)。
  - 名前: 読み込みでは `overrides.name` があればそれを、無ければ外側の `name` を `node.name` にする(実行時と同じ優先順)。書き出しでは外側の `name` に `node.name` を書き、`overrides.name` があったときはそちらも `node.name` にする。既存の Name 欄の編集が実行時の名前に効くようにするため。
  - `children`、`removedChildren` は触らない(E12 まで編集 UI が無い)。
  - 結果の `overrides` が空なら書かない(今と同じ)。
- 参照ノードの `name`(`overrides` の外の `name`)は今と同じく `node.name` を書く。
- 実体ノード(参照でないノード)の書き出しは変えない。
- 値を変えて元に戻したキーは「違うキー」に当たらないので書かない(override に既にあったキーは `overridesRaw` に残る)。

**3. `LevelEditModel`(E4b、新規 `aqEngine/Level/LevelEditModel.h/.cpp`、`AQ_DEBUG_IMGUI`)**

```cpp
class LevelEditModel
{
public:
	void NewLevel();
	bool LoadFile(const std::string& path);           // 失敗したら false。モデルは変えない
	bool SaveFile(const std::string& path);           // 一時ファイルに書いてから置き換える(7.7)。成功すると baseDir を更新するので const にできない(E4b で判明)
	util::JsonValue ToJson() const;                   // 今の BuildJson
	bool FromJson(const util::JsonValue& root);       // 今の Load の中身

	void RequestPreview();                            // Load in World。同じフレームの要求は 1 回にまとめる
	void ProcessPreviewRequest();                     // System の反復の外で、1 フレームに 1 回呼ぶ

	// ノード ID(保存しない。読み込み・新規・ノード追加のたびに振る。モデルの中で一意)
	PrefabEditNode* FindNode(uint32_t id);
	uint32_t        AssignId(PrefabEditNode& node);   // 子孫も含めて未採番のノードに振る
	// 以下、今の LevelEditorPanel の private メンバ(name_、entities_、subLevels_)をそのまま移す
};
```

- インラインのサブ Level は、自分の `subLevels` を持てるようにする(`SubLevelEdit` を再帰の形にし、`name`、`entities`、`subLevels` を読み書きする)。今のエディタが内側の `subLevels` を捨てる不具合を直す。UI は今と同じく 1 段目だけを編集し、2 段目以降は表示しない(保存では保持する)。
- 基準ディレクトリ(`baseDir`)を持つ。`LoadFile` / `SaveFile` でそのファイルのディレクトリにし、新規では空にする。プレビューでは `LevelSerializer::FromJson(root, baseDir)` に渡し、通常のロードと同じ基準で相対パスを解決する。
- `PrefabEditNode` に `uint32_t editId = 0`(0 は未採番)を足す。採番は `LevelEditModel` が行い、Prefab エディタは使わない(0 のまま)。
- `LevelEditorPanel` は UI の状態だけを持ち、編集状態は `LevelEditModel` に持たせる。ボタンの動き(New / Load / Save / Load in World / Load Async / Reload Refs / Auto)は変えない。Save は一時ファイルに書いてから置き換える形になる(7.7 節)。
- `DebugRender` の先頭で `ProcessPreviewRequest()` を呼ぶ。Load in World のボタンは `RequestPreview()` を呼ぶだけにする。

**4. プレビューの置き換え(E4b)**

7.3 節の手順のうち、E4 で行うのは次のとおり(Play 中にゲームがロードした Level のアンロードは E5)。

1. `Engine::WaitForRenderIdle()`
2. `EntityContext::FlushPendingCommands()`
3. 前回のプレビューの Level を `LevelManager::Unload`
4. `FlushPendingCommands()`
5. 前回のキーを `LevelRegistry::Unregister`
6. 編集モデルから `LevelData` を作り、新しいキーで登録して `LevelManager::Load`
7. 新しい `LevelId` とキーを記録する

- キーは今と同じ `"<level-editor-preview-N>"`(N は増え続けるが、登録は常に 1 つだけ)。
- 要求が無いフレームでは何もしない(完了待ちも入らない)。

**5. `LevelRegistry::Unregister(key)`(E4b)**: キーを正規化して `cache_` から消す。無ければ何もしない。

**6. `LevelManager::IsSpawned(LevelId)`(E4b)**

- `LevelSlot` に `spawned` を足す。`Load` の遅延生成のコマンドが最後のノードを作り終えたとき、`LevelManager::Get().MarkSpawned(levelId)` で立てる(コマンドは Flush の中でメインスレッドから走る)。`LoadAsync` は、その Level のジョブを作り終えたときに立てる。ジョブが 0 個の Level は、フラット化した時点で立てる。
- **同期ロードの不具合の修正**: 遅延生成のコマンドは、最初に `LevelManager::Get().IsLoaded(levelId)` を確かめ、アンロード済み(世代が違う)なら何も作らない。`Unload` の中では Flush しない(System の中から呼ばれるため)。
- `IsSpawned(id)` は、その Level と、`loadOnStart` で一緒に読んだサブ Level のすべてが `spawned` のとき true。アンロード済み・古い ID は false。
  **実装は `children`(`LevelSlot::children`)の子孫全体を見る形になった**(E4b 実装時の判断)。`children` は `AllocateSlot` が親子関係を登録する箇所で、現状は `loadOnStart` のサブ Level 以外にそこへ登録する呼び出しが無いため、実質的には一致する。将来 `LevelStreamSystem` 等が `Load(path, parent)` で動的にストリーミング読み込みした Level を同じ `children` に載せるようになった場合は、`IsSpawned` がそれらの完了も待つ形になる点に注意(区別したい場合は子ごとに「loadOnStart 由来か」の印を足す必要がある。今は未対応)。
- コマンドが走る前にスロットがアンロード・再利用されていたら、`MarkSpawned` は世代の違いで何もしない。

**7. Unload で非同期ロードを取り消す(E4b、既存の不具合の修正)**

- 15 章の TODO「取り消し API の形」は、**専用の API を足さず、`Unload` が取り消す**と決める。進行中の非同期ロードの Level をアンロードしたとき、それ以上エンティティを作る理由が無いため。
- `Unload` は、進行中の非同期ロードのうち、対象の Level(子孫を含む)に属するジョブに「飛ばす」印を付ける。ジョブ列からは消さない(`parentJobIndex` と `cursor` の添字をずらさないため)。飛ばすジョブは作らず、予算も使わないが、`built` には数える(進捗が 100% に届くように)。印が付いたジョブの子孫は同じ Level に属するので、同じく飛ばされる。
- 根の Level(`progress->id`)が対象のときは、`LevelLoadProgress` の `cancelled` を立て、`done = true` にしてロード全体を外す(ローディング画面が待ち続けないように)。`LevelLoadHandle::IsCancelled()` で読める。
- 子の Level だけが対象のときは、そのロードの `cancelled` も `done` も変えない(親と兄弟のジョブは続く)。
- 作り終えたエンティティは、今までどおり `LevelMemberComponent` で破棄される。

**8. 自動リロードの GPU 待ち(E4b、既存の不具合の修正)**: `PollFileChanges` も `ReloadAll` と同じく、Unload の後に `WaitForRenderIdle` + `FlushPendingCommands` を行ってから Load する。

**9. 検査ツールの追加(ReflectionTest)**

| 試験 | 内容 | 段 |
|---|---|---|
| T6 Level の往復 | `--assets` 以下の全 `*.level.json` と、ツールに同梱する試験用の Level・Prefab(`Tools/ReflectionTest/TestData/`)を、編集ノードへ読み込んで書き出し、11.4 節の規則で元と比べる。試験用のデータには、`overrides` の `name` / `components` / `addedComponents` / `removedComponents` / `children` / `removedChildren` をすべて持つ参照ノード、入れ子の参照ノードを持つ Prefab(Prefab エディタの経路)、2 段のインライン subLevel を入れる。無編集の往復に加えて、プログラムで編集してから書き出す試験も行う: (a) override のフィールドを変える → そのキー(入れ子のオブジェクトなら葉)だけが増える、(b) 変えて元に戻す → 元と同じ、(c) override コンポーネントを外して同じ型を足し直す、(d) `addedComponents` のコンポーネントを変える → `addedComponents` 側が変わる、(e) Name を変える → 外側と `overrides.name` の両方が変わる。(f) `addedComponents` のコンポーネントを外す → 保存して読み直しても復活しない。(g) `addedComponents` のコンポーネントを外し、同じ型を足し直して値を変える → 保存して読み直すと新しい値になる(`addedComponents` に古い値が残らない)。**E4a ではノード単位**(各 Level の `entities` の各ノードと、Prefab ファイルのルートを `PrefabNodeFromJson` → `PrefabNodeToJson`)で比べ、E4a の前は無編集の往復が `[XFAIL]`(override が増える・子の override が消える)。**E4b では Level 全体**を `LevelEditModel` の `FromJson` / `ToJson` で比べる(サブ Level の構造を含む。入れ子の subLevel の不具合は E4b の前に `[XFAIL]` として控えてから直す) | E4a / E4b |
| T7 数値 | 7 桁以上の小数を持つ通常のフィールド(float)と override の値(double)を含む試験用 Level を、ファイルへ書いて読み直し、float のフィールドは float として、override の値は double として一致する。`Stringify` の表記と往復も確かめる: `0.1f` → `0.1`、`1234567.5`、`16777217`(float では丸まる整数)、`2147483647` と `-2147483648`、`9007199254740992`(2^53)と `9007199254740993`、`1e20`、`1e-05`、`-0.0`。整数の分岐は小数点なしで書かれ、読み直して double として一致する | E4a |
| T8 生成と取り消し | 画面無しで `EntityContext` を使い、Transform だけの試験用 Level で: (a) `Load` 直後は `IsSpawned` が false、`FlushPendingCommands` の後は true。(b) `Load` → `Unload` → Flush でエンティティが 1 つも作られない(同期ロードの不具合)。(c) `LoadAsync`(1 フレーム 1 個)を 2 回進めて根を `Unload` すると `IsCancelled` と `IsDone` が true になり、以後 `Tick` を回してもエンティティ数が増えず、Level に属さないエンティティが残らない。(d) 子のサブ Level を持つ Level の `LoadAsync` 中に子だけを `Unload` すると、子のエンティティは作られず、親のエンティティは最後まで作られて `IsDone` が true、`IsCancelled` は false。(e) `Register` → `Unregister` → `IsRegistered` が false(`Load` は Debug で assert するので呼ばない。`IsRegistered` は検査用に足す)。(f) プレビューの置き換え(`RequestPreview` を同じフレームに 10 回 → `ProcessPreviewRequest`)を 10 フレーム続けても、エンティティ数が 1 回目と同じで、プレビューの登録が 1 つだけ | E4b |
