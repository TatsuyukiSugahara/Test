## 0. 全体構造(起動から終了まで)

```
[エントリ]  Main.cpp(Win32 WinMain) / UWPMain.cpp(IFrameworkView) / MacMain.mm(main)
            / AndroidMain.cpp(android_main) / iOSMain.mm(UIApplicationMain + AqAppDelegate)
      │  IPlatform 実装を生成(PlatformWin32 / UWP / Mac / Android / iOS)
      ▼
Engine（シングルトン）
  Create() → app::RegisterAppModules(registry) → Initialize(param) → RunGame() → Finalize() → Release()
  → (全エントリ共通で最後に) aq::ShutdownMemory()
      │
      ├─ Initialize: 起動引数の記録 → (Win32 埋め込み時は親 HWND 検証) → -app= でモジュール生成 → AppHost 生成
      │              → Memory → SetGameRootName → PhysicsAllocatorHook → COM(Windows 系)
      │              → Sound 生成 + 初期化を別スレッドで開始 → Window(Platform) → GraphicsAPI
      │              → ThreadPool → AudioDirector → AppHost::Initialize → EnsureSoundInitialized
      │              → AppHost::Register → gameTimer_.Initialize
      │
      └─ RunGame: platform_->RunFrameLoop([]{ FrameStep(); })
            FrameStep(): SyncSoundActivity → EnsureSurfaceUpToDate → IsRenderable でなければ return
                         → SyncScreenSize → Update()
            Update():    gameTimer_.Tick() → [ToggleMainRT] → appHost_->Update()
                         → Sound/Audio Update → appHost_->FlushRender() → ResetStackAllocator
      ▼
AppHost（aq::AppHost）… エンジンサブシステムの初期化/更新/終了と描画の土台。IAppModule を 1 つ所有して呼ぶ
      │  OnInitialize / OnRegister / OnUpdate / OnPreRender / OnFinalize(+ ImGui 系)
      ▼
app::GameModule（ゲーム実装。aq::IAppModule）→ GameFlow(IGameState: Title / Loading / InGame / Result)
```

**ハイブリッドの 3 つの分岐点**:
1. **エントリ/ウィンドウ/ループ/ライフサイクル** … `IPlatform`(Win32 / UWP / Mac / iOS / Android。§3)。
2. **グラフィックス API** … `GraphicsDevice::Create<TImpl>()`(D3D11 / D3D12 / Vulkan / Metal)を `ENGINE_GRAPHICS_*` で選択。
3. **リソース予算** … `PlatformBudget.h`(Win32 / Mac = 無制限 / Xbox UWP = 5GB・6 worker・2GB/ファイル / iOS 1.5GB / Android 2GB。§3.3)。

### 1.1 `Engine` の公開面

- **`InitializeParameter`**: `platform`(呼び出し側所有)、`screenWidth/Height`、`renderWidth/Height`、`gameObjectPriortyMax`、`memoryConfig`、`gameRootName`(既定 `"Game"`。`"Assets/..."` の解決先フォルダ名。[使いやすさ改善設計](使いやすさ改善設計.md) P3-A)、`launch`(起動引数。§2.3)。
- **`Create / Get / IsCreated / Release`**: `IsCreated()` は iOS のように「Engine がまだ居ないかもしれない」文脈用。
- **`Initialize / RunGame / Finalize`**: §5 を参照。`Finalize` は `Engine::Release()` の後に呼ばれる **`aq::ShutdownMemory()`**(エントリが最後に 1 回)と対で、メモリ管理を畳む(Debug ではここでリーク報告)。Engine・プラットフォーム実装が生きているうちに呼ぶと、それらの確保が全部「リーク」に並ぶ。
- **`GetAppModuleRegistry / GetLaunchOptions`**: モジュール登録と起動引数(§2)。
- **`EnsureSoundInitialized`**: 別スレッドで進めるサウンド初期化(XAudio2 等)との合流点。`Initialize` 内でも AppHost 初期化後に必ず合流する。
- **`WaitForRenderIdle`**: `AppHost::WaitForRenderIdle` への窓口(CPU・GPU とも完了待ち)。AppHost を知らないエンジン内部(Level の作り直しなど)が、GPU バッファを持つエンティティを破棄する前に使う。
- **`GetMainRenderTarget / GetMainRenderTargetHandle / ToggleMainRenderTarget`**: RT ダブルバッファのトグル管理。
- **`GetContentRoot / GetUserDataDirectory`**: `IPlatform` へ委譲(§3.2)。
- **`GetNativeWindowHandle`**: Win32=HWND / UWP=CoreWindow / Mac・iOS=CAMetalLayer* / Android=ANativeWindow* を `void*` で保持。`GetHWND` は Win32 専用の最後の接合点。
- **`IsEmbedded / HasInputFocus / GetInputCooperativeWindow`**: 外部エディタへの子ウィンドウ埋め込み時の入力制御(§2.3)。
- **`GetDeltaTime / GetTotalTime / GetFPS / SetFPSLimit`**: `gameTimer_` の static ラッパー。

### 1.2 メインループの要点

- **フレーム駆動はプラットフォームへ委譲**: `RunGame` は `IPlatform::RunFrameLoop` に `FrameStep` を渡すだけ。既定実装は「`PumpEvents()` が false を返すまで回す」で Win32 / UWP / Mac / Android はこれを使う。iOS だけは CADisplayLink に登録してすぐ戻る(§3.1)。
- **`FrameStep` の先頭 3 段**: ① `SyncSoundActivity`(`IsRenderable()` の変化点でサウンドの `OnSuspend/OnResume`) → ② `EnsureSurfaceUpToDate`(`ConsumeSurfaceChanged` を受けたら `WaitForRenderIdle` のうえ `GraphicsDevice::RecreateSurface`。復帰に失敗したらフレームを飛ばして次で再試行) → ③ `IsRenderable()` が false ならフレームごと飛ばす。その後 `SyncScreenSize`(`GetSurfaceSize` で `screenWidth_/Height_` だけ追従)と `HandleRenderResize`(次項)。
- **描画解像度のリサイズ(`HandleRenderResize`)**: `SupportsRenderResize()` が true のバックエンド(Metal / MoltenVK の Vulkan / Windows の D3D12)だけ有効。
  `IPlatform::GetClientPixelSize`(取れなければ `GetSurfaceSize`)を見て、**同じ値が 2 フレーム続いたら**確定する(0×0 は無視)。
  直近の要求寸法(`lastRequestedW_/H_`)と比べるので、確定寸法が要求と違っても毎フレーム再要求しない。
  手順: ① `AppHost::CanResizeRender()`(全パスが `Independent` / `Resizable` で、`Independent` が `Scene` 以外を Writes していなければ有効。違えば何もせず固定寸法。ログは 1 回)→ ② `WaitForRenderIdle` →
  ③ `GraphicsDevice::ResizeMainTargets`(確定寸法を得る)→ ④ 全パスの `PrepareResize`(確定寸法で)→ ⑤ `CommitRenderResize` → ⑥ `Engine` の寸法(`renderWidth_/Height_` と `screenWidth_/Height_`。`GetSurfaceSize` を持たないバックエンドは確定寸法を入れる)を同じフレームで更新し `GameTimer::ResetDelta()`。
  通常は同じフレームの `Update` へ進む。**失敗経路だけ**「リサイズ保留」になり、`FrameStep` は `Update` を飛ばして 200 ms 以上あけて再試行する
  (失敗が累計 5 回に達した時点で `[engine] FATAL` を出して `RequestExit(2)`。最初の試行を含む。次項)。
  保留中も `UpdateSoundOnly()` でサウンド供給を続ける(実経過時間を自前で測って渡す。`GameTimer` は Tick されないため)。後に 2 ms の sleep で CPU の空回りを抑える。
  レンダー側の契約(パスの Prepare / Commit / Abort、オフスクリーン RT の解放)は [01 §2.11](01_レンダリング設計.md)。
- **終了要求(`Engine::RequestExit(int exitCode = 0)`)**: ゲームコードと Engine 内部から呼ぶ。最初に要求された終了コードを保ち、`IPlatform::RequestExit()` で次の `PumpEvents()` を false にする(要求したフレームは最後まで回る)。iOS はプログラムから終了しない決まりなので、ログだけ出して無視する。`Main.cpp` / `MacMain.mm` は初期化に成功したら `GetExitCode()` を返す(0 = 正常 / 1 = 初期化失敗 / 2 = 実行中の致命失敗)。リサイズの致命失敗は `RequestExit(2)` で、以後の `FrameStep` は Update・描画・リサイズ・サーフェス再作成をせずに待つ。経緯は [エンジン課題解消設計](エンジン課題解消設計.md) P5。
- **RT トグル**: `AQ_RENDER_PIPELINED` 時、フレーム N/N+1 で別メイン RT を使う(`ToggleMainRenderTarget`)。これがレンダースレッドの 1 フレーム重複の前提。
- **スレッド境界**: `FlushRender()` 後まで描画 API はレンダースレッドに閉じる。メインは `Submit` 以降コンテキストを触らない。
- **サウンド初期化の並列化**: `SoundEngine::Create` は同期、`Initialize()`(実測 0.25〜1.0 秒、大半がデバイス待ち)は `std::async` で別スレッド。ウィンドウ/グラフィックス/シェーダ初期化と並走させる。COM(MTA)はメインスレッドでプロセス寿命ぶん保持する(Windows 系のみ)。
- **初期化順序**: Memory を最初に(ウィンドウ/グラフィックス初期化中の new/delete もエンジンアロケータ管理下)。ただし**モジュールの生成(`appModuleRegistry_.Create`)と `AppHost` の new だけはその前**(旧 `CreateApplication` と同じ順)。Bullet アロケータフックは Bullet 型生成前。`SetGameRootName` はアセット解決(ワーカー並列)より前。

### 2.1 `AppHost::Initialize` の順序(現行)

```
RenderThread 初期化 → ResourceManager → RegisterEngineResourceBanks(9 型。OnInitialize より前)
→ EntityContext → InputManager(Setup 失敗で初期化失敗) → UIContext → CameraManager → LightManager
→ (AQ_DEBUG_IMGUI) DebugUI → ComponentRegistry::RegisterCoreComponents / RegisterLevelComponents
→ (AQ_IMGUI) ImGui コンテキスト・フォント・プラットフォームバックエンド・描画バックエンド
→ (-editor-port 指定時) LinkService::Initialize + RegisterEngineCommands
→ module_->OnInitialize(*this)
→ (compute 非対応なら ClusterCull 無効) / (対応なら GpuClusterCuller + Hi-Z テスターを登録)
→ (AQ_DEBUG_IMGUI) デバッグパネル生成
```

- **リソースバンクの既定登録はエンジン側**(`RegisterEngineResourceBanks`)。`OnInitialize` で `Load` できるよう、位置は `ResourceManager::Initialize` の直後に固定([使いやすさ改善設計](使いやすさ改善設計.md) P2-A)。
- **ImGui の入力バックエンドはプラットフォーム別**: Win32=`imgui_impl_win32` / Mac=自前 `MacImGui` / Android・iOS=`ImGuiPointerInput`(タッチ→マウス合成済みの入力を流すだけ)/ UWP=バックエンド無し(`DisplaySize` と `DeltaTime` だけ自前で入れる)。iOS は `imgui.ini` の置き場を `GetUserDataDirectory()` へ向け、Android・iOS はメニューバー等を `MOBILE_UI_SCALE`(Android 2.0 / iOS 1.25)で拡大する。デバッグ UI の表示トグルは F1 / 中クリック、タッチ環境は 4 本指ダブルタップ。

### 2.2 `AppHost::Update` / `Register` / `Finalize`

- **Update**: `Input::Update`(埋め込み時は `SetFocusBlocked`、ImGui 時は `SuppressKeyboard/Mouse`)→ `EntityContext::Update` → `LevelManager::Tick`(安全点で非同期ロード進行・ファイル監視)→ `ResourceManager::Update` → **`LinkService::Tick`**(有効時のみ。ECS の反復外でエディタ命令を実行)→ `module_->OnUpdate` → UI(入力・画面更新・バッチ収集)→ `CameraManager::UpdateAll` → `Render`(ImGui フレーム構築 → `OnImGuiRender` → デバッグ UI → `OnPreRender` → メインパス Submit)。
- **Register**: エンジン標準 System(HierarcicalTransform / Animation / Spawn / LevelStream / Particle / Render と依存、デバッグ時は SceneHierarchy)を登録 → `module_->OnRegister` → `FinalizeRegistration()` の結果を返す(false なら初期化失敗)。System 登録の誤りは Release でも失敗として止まる(`34aa75c`)。
- **Finalize**: `OnFinalize` → `LinkService::Finalize`(通信スレッドを先に止める)→ `FlushRender` → RenderThread 停止 → **`GraphicsDevice::WaitIdle`**(Vulkan / D3D12 は Present がフェンス Signal だけで GPU 完了を待たないため。D3D11 は no-op)→ ImGui → DebugUI → GpuClusterCuller / InstancedStaticMesh 名前レジストリ → UIContext / LightManager / EntityContext / ResourceManager / InputManager / CameraManager。

### 2.3 起動引数とモジュール登録

- **`LaunchOptions`**: `-key=value`(`--key=value` も同じ。空白を含む値は `"` で囲む。未知のキー・誤った値はログして既定値のまま)。`-app=`(モジュール名。空=登録順の先頭)、`-mode=play|edit`(`edit` は保持するだけで未実装。play として動く)、`-editor-port=`(エディタ連携の待ち受けポート。0 で無効)、`-parent-hwnd=`(埋め込み先の親ウィンドウ。**Win32 のみ有効**、他は無視してログ)。`Parse(argc, argv)` と `ParseCommandLine(cmdLine)` の 2 入口。
- **誰が引数を渡すか**: Win32 は `lpCmdLine` を `ParseCommandLine`、Mac は `argv` を `Parse`。UWP / iOS / Android は `launch` を既定値のまま(= `-app=` 省略で登録先頭のモジュールが起動する)。
- **モジュール登録**: エントリが `Engine::Initialize` より前に `app::RegisterAppModules(engine.GetAppModuleRegistry())` を呼ぶ(`GameModule.cpp` が `"AquaDash"` を登録)。`-app=` に未登録名を渡すと**別のモジュールで黙って動かさず初期化失敗**にする(登録済み一覧をログ)。失敗は Win32 では終了コード 1 になる。
- **埋め込み(Win32)**: `-parent-hwnd` 指定時、Engine は親ウィンドウを**モジュール生成より前に**検証(失敗なら `Finalize` が何も触らずに戻れる)、スクリーンサイズを親のクライアント矩形に合わせ、`WindowDesc::parentWindow` で子ウィンドウとして作る。親のリサイズには追従しない。`HasInputFocus` / `GetInputCooperativeWindow` は `IPlatform` へ委譲(§3.1)。詳細は [アプリケーション構成とエディタ連携設計](アプリケーション構成とエディタ連携設計.md) §3。

### 2.4 LinkService(エディタ連携。入口のみ)

`aqEngine/Link/`(`LinkService` / `LinkSocket` / `LinkCommands`)。**`-editor-port` 指定時だけ** `AppHost::Initialize` が `LinkService::Initialize(port, module名)` し、`RegisterEngineCommands`(`ping / runtime.info / runtime.commands / level.load / level.reloadAll` と評価用 `debug.*`)を登録する。TCP(127.0.0.1)+ 改行区切り JSON。通信は `LinkSocket` の通信スレッド、命令の実行は `AppHost::Update` 内の `Tick()`(メインスレッド。1 フレームの行数 256・予算 4ms)。モジュールは `IsAvailable()` を確かめてから `RegisterCommand` で命令を足せる。**Win32 以外では「未対応」とログして false**(待ち受け失敗でもゲームは動く)。プロトコル・スレッド構成・接続世代は [アプリケーション構成とエディタ連携設計](アプリケーション構成とエディタ連携設計.md) §4 が一次資料。

## 3. プラットフォーム抽象(`aqEngine/Platform/`)

### 3.1 `IPlatform`(`IPlatform.h`)

| メソッド | 意味 / 既定 |
|---|---|
| `CreateMainWindow(desc, out)` | ウィンドウ生成(または到着待ち)し `NativeWindowHandle` を返す。`WindowDesc` は幅・高さ・タイトル・`parentWindow`(Win32 埋め込み用)。**iOS / Android は冪等**(エントリが解像度を知るために先に 1 度呼び、`Engine::Initialize` が内部でもう一度呼ぶ)。 |
| `PumpEvents()` | イベントを処理し、終了要求で false。 |
| `RunFrameLoop(frame)` | **フレーム駆動の委譲**。既定は `while (PumpEvents()) frame();`。iOS だけが override し、CADisplayLink に登録して即 return(コピーして保持する)。 |
| `OnSuspend / OnResume` | PLM(UWP)/ 前面・背面(Android・iOS)。既定は何もしない。 |
| `IsRenderable()` | 描画してよいか。false の間 Engine は `FrameStep` を丸ごと飛ばし、サウンドも止める。既定 true。 |

## 5. ライフサイクル詳細

### 5.1 初期化順序(`Engine::Initialize`)
```
起動引数を記録(-mode=edit は未実装ログ / 非 Win32 の -parent-hwnd は無視ログ)
→ (Win32 埋め込み時) 親ウィンドウ検証
→ appModuleRegistry_.Create(-app=) → AppHost 生成(subsystemsStarted_ = true)   ※見つからなければ false
→ MemoryManager → SetGameRootName → PhysicsAllocatorHook → CoInitializeEx(MTA。Windows 系)
→ SoundEngine::Create + Initialize を std::async で開始
→ Window(Platform::CreateMainWindow) → GraphicsAPI(GraphicsDevice::Create<Impl> + Initialize + RenderContext 設定)
→ ThreadPool(予算 worker 数) → AudioDirector
→ appHost_->Initialize(§2.1) → EnsureSoundInitialized(必ず合流)
→ appHost_->Register → gameTimer_.Initialize
```
各段で `StartupLog` / `StartupMark` を吐く(UWP 実機はデバッガ接続不可のため LocalState/startup.log から、他は起動計測の `startup_timing.log` から到達点を特定)。

### 5.2 終了順序(`Engine::Finalize`)
```
(subsystemsStarted_ が false なら何もせず return。モジュール生成失敗時)
→ appHost_->Finalize(§2.2)→ delete appHost_ → AudioDirector → (サウンド初期化スレッドが未合流なら待つ) → SoundEngine
→ GraphicsDevice → ThreadPool → CoUninitialize(Windows 系)
```
依存の逆順で破棄(AudioDirector は SoundEngine より先 = SoundStream が SoundEngine を参照するため)。**`MemoryManager` は `Finalize` では畳まない**。Engine 本体とプラットフォームがまだ生きているうちにリーク報告を出すと全部が「リーク」に並ぶため、`Engine::Release()` とプラットフォーム破棄の後にエントリが `aq::ShutdownMemory()` を呼ぶ。Mac の終了時リークの既存分は別問題([Mac移植設計](Mac移植設計.md)・[Android移植設計](Android移植設計.md)参照)。

### 5.3 前面/背面・サスペンド
プラットフォームごとに入口が違う(§3.2 の表)。共通の受け口は **`IPlatform::IsRenderable()` と `ConsumeSurfaceChanged()`**:
- Android / iOS は `IsRenderable()` が false の間 `FrameStep` が描画を丸ごと飛ばし、`SyncSoundActivity` がその変化点でサウンドを止める/再開する。
- UWP の PLM は `PlatformUWP` が `GraphicsDevice::OnSuspend/OnResume` を直接呼ぶ(GPU アイドル化・メモリ解放。バックグラウンド 128MB 制限対応。[Xbox移植設計](Xbox移植設計.md) Phase 4)。Engine 側の `IsRenderable` 経路は使わない。
- Android のサーフェス再生成は `EnsureSurfaceUpToDate` が `WaitForRenderIdle` のうえ `RecreateSurface` する。
