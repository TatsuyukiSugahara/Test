## 6.4 E6 の詳細(2026-11-19 追記)

Mac 機で進める(E6 はプラットフォームに依存しない。11.2 節)。Windows 機の確認は最後にまとめる。

### 現状(調査結果。3fc9eb8 で確認)

| 項目 | 実コード |
|---|---|
| Visitor | `JsonWriteVisitor` / `JsonReadVisitor`([JsonFieldVisitor.h](../../aqEngine/ECS/JsonFieldVisitor.h)、常時)、`ImGuiFieldVisitor`([ImGuiFieldVisitor.h](../../aqEngine/ECS/ImGuiFieldVisitor.h)、`AQ_DEBUG_IMGUI`)の 3 つ。`Field(key, 値, label = nullptr)` の型は `float` / `int` / `bool` / `Vector3` / `Quaternion`。ほかに `FieldPath(key, std::string&, label)`(戻り値 bool)と `ReadOnly(...)` |
| 文字列 | **既に `FieldPath` が文字列フィールドを担う**。Reflect 内の文字列はすべてパス(モデル、テクスチャ、Prefab、Level、パーティクル、オーディオ)で、パス以外の文字列フィールドは無い。`ImGuiFieldVisitor::FieldPath` は Enter で確定したときだけ書き換えて true を返す |
| 疎な JSON | `JsonReadVisitor` は、スカラーは `Contains` のときだけ、配列は `IsArray` のときだけ、パスは `Contains` のときだけ書き換える。つまり **Reflect 経由の読み込みは既に疎な JSON を扱える**。各 `Reflect` の「一時変数に取り出して書き戻す」形(Ocean / Terrain の resolution、AudioSource の enum)も、キーが無ければ同じ値を書き戻すだけ |
| 例外 1(不具合) | `AnimationComponent` は Reflect ではなく専用の `SerializeTo` / `DeserializeFrom` で保存し、`serializePtr` / `deserializePtr` もこの 2 つで埋めている(`FillReflectPtrFns` は使わない)。`DeserializeFrom` は先頭で `slots_.clear()` するので、`clips` が無い JSON(`{}` や `playSpeed` だけ)を渡すとクリップが消える。**疎な JSON を扱えない**。`AddAnimation` はパスを控えるだけでロードしないので、検査ではクリップ付きの実体を作れる |
| 例外 3(不具合) | (E6a の検査で `heightScale` / `terrainSize` も同じと判明。`HeightmapChunk::SetHeightScale` / `SetTerrainSize` はハイトマップ未読込のとき値を捨てるので、`Reflect` が書き戻しても残らない)`TerrainComponent::Reflect` の `resolution` は、書き出しが `chunk_.GetResolution()`(`HeightmapChunk` の desc の値)、読み込み先が `authorResolution_` で、別の変数になっている。`chunk_` に反映するのは `OnDeserialized` の `SetDesc` だけで、`deserializePtr` は `OnDeserialized` を呼ばない。そのため **型消去の経路で読んで書き出すと、resolution が既定値に戻る**(Prefab エディタで Terrain を読んで保存し直すと値が失われる) |
| 例外 2 | `DecalComponent::Reflect` は `FieldPath` が true のとき `SetTexturePath` を呼ぶ(Reflect 内の副作用)。ロードは `Update` の状態機械で遅れて行うので、編集用のコピーでもその場で GPU に触れない |
| 型消去の経路 | `FillReflectPtrFns<T>` が `serializePtr` / `deserializePtr` / `drawInspectorPtr` を埋める。`deserializePtr` は `OnDeserialized` を呼ばない(編集用のコピーでリソースを読まないため。エンティティ経路の `deserialize` だけが呼ぶ) |
| 登録 | エンジンの `RegisterCoreComponents` が 14 型、`LevelComponentRegistry` が `LevelStream` を登録する。Game 側の登録は無い。`LevelStream` には `FillReflectPtrFns` が無い |
| 公開情報 | `ComponentMeta` の `remove == nullptr` が「削除できない」を表す。追加の可否とカテゴリは無い。Add Component パレットは、Prefab エディタが `drawInspectorPtr` の有無で、ヒエラルキーが全登録で絞り込んでいる |
| テストの場 | 単体テストのフレームワークは無い。前例は CMake 専用のツール [Tools/MixerTest](../../Tools/MixerTest/README.md)(`aqEngine` をリンクし、`--selftest` で自動判定する) |

### 決定

E6 を 2 段に分ける。**先に検査ツールを作って現状の出力を控え、その後でエンジンを変える**。変更の前後で既存アセットの保存結果が変わらないことを機械的に比べるため。

| 段 | 内容 |
|---|---|
| E6a | 検査ツール `Tools/ReflectionTest` を足す。エンジンのコードは変えない。現状の出力を控える。例外 1・例外 3 は**既知の失敗**として検査ツールに名前を持たせ(`[XFAIL]` と出し、終了コードには数えない)、README の「既知の課題」に記録する |
| E6b | 属性・文字列フィールド・編集イベント Visitor・`ComponentMeta` の公開情報を足す。例外 1・例外 3 を直し、既知の失敗の印を外す。E6a の控えと比べる |

**0. 既存の不具合の修正(E6b)**

- Animation: `DeserializeFrom` は `clips` があるときだけ `slots_` を作り直す。`current` も `clips` と同じく、キーがあるときだけ扱う(今のまま)。
- Terrain: `Reflect` の `resolution` は、書き出しで `authorResolution_` が 0 でなければそれを、0 なら `chunk_.GetResolution()` を使う。読み込みは今のまま `authorResolution_` へ入れる。
- Terrain の `heightScale` / `terrainSize` も同じ形にする。読み込んだ値をコンポーネント側のオーサリング値(`resolution` の `authorResolution_` と同じ扱い)に持ち、書き出しはそれを使う。ハイトマップがあれば今までどおり `chunk_` にも渡し、`OnDeserialized` の `desc` もオーサリング値から作る。
- T3 の出力のうち、E6a の控えと違ってよいのは、既定値と違う値を持つ Terrain の `resolution` / `heightScale` / `terrainSize` だけ。差分はすべて本節に書く(E6a の時点で `Game/Assets` に Terrain を使うアセットは無い)。

**1. フィールド属性 `FieldAttr`**(新規 `aqEngine/ECS/FieldAttr.h`、常時コンパイル)

```cpp
enum class AssetKind : uint8_t { None, Model, Texture, Prefab, Level, Particle, Audio };

struct FieldAttr
{
	float       min      = 0.0f;   // hasMin のときだけ有効
	float       max      = 0.0f;   // hasMax のときだけ有効
	float       speed    = 0.0f;   // ドラッグの速さ。0 なら型ごとの既定
	const char* tooltip  = nullptr;
	AssetKind   asset    = AssetKind::None;
	bool        hasMin   = false;
	bool        hasMax   = false;
	bool        readOnly = false;  // 表示するが編集できない。保存はする
	bool        hidden   = false;  // インスペクターに出さない。保存はする

	constexpr FieldAttr Min(float v) const;      // 以下、自分の写しを返すビルダー
	constexpr FieldAttr Max(float v) const;
	constexpr FieldAttr Range(float lo, float hi) const;
	constexpr FieldAttr Speed(float v) const;
	constexpr FieldAttr Tooltip(const char* text) const;
	constexpr FieldAttr Asset(AssetKind kind) const;
	constexpr FieldAttr ReadOnly() const;
	constexpr FieldAttr Hidden() const;
};
```

- 全 Visitor の `Field` と `FieldPath` に、末尾の省略可能な引数 `const FieldAttr& attr = {}` を足す。既存の 2 引数・3 引数の呼び出しはそのまま通る。
- JSON の 2 つの Visitor は属性を無視する。**最小・最大は UI だけで効かせ、読み込んだ値は丸めない**(既存のファイルの値を変えないため)。
- `ImGuiFieldVisitor` は属性を効かせる。範囲と速さはドラッグに渡し、`readOnly` は `ImGui::BeginDisabled` で囲み、`hidden` は描かない。ツールチップはホバーで出す。既存の `FieldPath` のツールチップ「Press Enter to apply」には、属性のツールチップを改行して続ける。
- 範囲の渡し方: ImGui のドラッグは `v_min < v_max` のときだけ範囲を効かせるので、片側だけのときは無い側を `-FLT_MAX` / `FLT_MAX` にして渡す。範囲があるときは `ImGuiSliderFlags_AlwaysClamp` を付け、Ctrl+クリックの直接入力でも範囲の外に出ないようにする。int も同じ(`INT_MIN` / `INT_MAX`)。範囲が無いときは今と同じく `0, 0` を渡す(既存の操作感を変えない)。
- 属性を付けるのは、6.2 節の例の Transform の `scale`(`Min(0.001f)`)と、全 `FieldPath` の `Asset(...)` だけにする。範囲を付けると既存の操作感が変わるので、ほかの数値は E7 で必要になったときに足す。

**2. 文字列フィールド**

パスの文字列は既存の `FieldPath` のまま扱い、属性の `asset` で種類を表す(E9 のドロップ先の判定に使う)。パス以外の文字列のために `Field(key, std::string&, label, attr)` を全 Visitor に足す。動きは `FieldPath` と同じ(Enter で確定)で、戻り値は無い。今の Reflect には使う所が無いので、E6 では検査ツールの試験用の型だけが使う。

**3. 編集イベント Visitor `ImGuiEditEventVisitor`**(新規 `aqEngine/ECS/ImGuiEditEventVisitor.h`、`AQ_DEBUG_IMGUI`)

```cpp
enum class FieldEditPhase : uint8_t { Begin, Update, Commit, Cancel };

struct FieldEditEvent
{
	FieldEditPhase  phase;
	std::string     key;    // Reflect の永続キー
	util::JsonValue value;  // Begin = 変更前の値、Update = 現在の値、Commit = 変更後の値、Cancel = 空
};

struct ImGuiEditEventVisitor
{
	std::vector<FieldEditEvent> events;  // このフレームに起きたもの(呼び出し側が毎フレーム読む)
	// Field / FieldPath / ReadOnly は ImGuiFieldVisitor と同じ形
};
```

- ウィジェットの描き方は `ImGuiFieldVisitor` と共有する。ImGuiFieldVisitor.h の中に、型ごとに「描いて、変わったら true」を返す関数を置き、2 つの Visitor から呼ぶ。描き方を 2 か所に書かない。
- イベントは **フィールド単位の「操作」**で出す。ImGui の項目単位(`IsItemActivated` など)では出さない。`DragFloat3` のように部品が 3 つあるウィジェットは、部品ごとに活性が移り、`EndGroup` が状態を寄せ集めるだけなので、部品の切り替えを 1 操作として扱える保証が無いため。
- 操作の状態(操作中か、操作中に値が変わったか、最後に描いたフレーム番号)は、**ImGui のウィンドウの状態保存(`ImGui::GetStateStorage()`)に、フィールドの ID(`ImGui::GetID(キー)`)で持つ**。Visitor の実体はフレームをまたいだ状態を持たない。
- 各フィールドで、描く前に値を控える(float などの写し。JSON にするのはイベントを出すときだけ)。描いた直後に、ウィジェットの項目(グループのときは `EndGroup` 後の項目)が操作中か(`IsItemActive()`)を見る。
  - 操作中になった(前フレームは操作中でない)→ `Begin`(控えた値)
  - 値が変わった → `Update`(現在の値)。状態に「変わった」を立てる。**変わったかどうかは描き方の共有関数の戻り値で判定し、`IsItemEdited()` は使わない**。`EndGroup` は「グループの開始時にはこのフレームでまだ何も変更されておらず、終了時には変更がある」ときだけ変更の印を引き継ぐので、同じフレームで先に別のフィールドが変わっていると、`DragFloat3` の変更を取りこぼすため(v1.93 の `EndGroup`)
  - 操作中でなくなった → 変わっていれば `Commit`(現在の値)、変わっていなければ `Cancel`(値は持たない)。呼び出し側は `Cancel` で控えた `Begin` を捨てる
- このため、押して離すだけでも `Begin` → `Cancel` が出る。チェックボックスは、押したフレームに `Begin`、離したフレームに `Update` と `Commit` が出る(2 フレームにまたがる)。外へ動かしてから離すと `Begin` → `Cancel` になる。
- `DragFloat3` で部品を Tab で移ったとき、ImGui が 1 フレームでも非活性を挟むと、操作が 2 つ(`Commit` → `Begin`)に分かれる。Undo が 2 回になるだけなので許容し、T4 で実際の列を記録する。
- **描かれなくなった操作**: 操作中に、選択の切り替え・折り畳み・パネルを閉じるなどでフィールドが描かれなくなると、Visitor は非活性を検出できず、`Commit` も `Cancel` も出せない。次のように分担する。
  - 呼び出し側: 受け取った `Begin` のうち閉じていないものを持っているので、そのフィールドを描かなくなったフレーム(描く対象を切り替えたとき、折り畳んだとき、パネルを閉じたとき)に、自分で取り消して捨てる。描く前に、編集対象を区別する ID(E7 ではノード ID と `typeName`)を `PushID` する。フィールドのキーだけでは別のノードの同じフィールドと ID が重なるため。
  - Visitor: 状態に残った「最後に描いたフレーム番号」が前のフレームでなければ、古い操作の残りとみなして、イベントを出さずに状態を消す(再表示したときに古い操作の `Commit` / `Cancel` を出さない)。
- **操作中でないのに値が変わったとき**は、そのフレームに `Begin`(控えた値)と `Commit`(新しい値)を続けて出し、1 つの操作として閉じる。ImGui は、Ctrl+クリックの直接入力の途中で描かれなくなった文字列を保持し、再表示したときに適用することがある(v1.93 の `InputTextDeactivateHook` → `TempInputScalar`)。このとき項目は操作中でないまま値だけが変わるので、この規則がないと `Begin` の無い `Update` が出てしまう。
- `FieldPath` と文字列の `Field` は Enter で確定したときだけ値が変わる。確定し、**かつ値が控えと違うとき**だけ、確定のフレームに `Begin`(控えた値)と `Commit`(新しい値)を続けて出す。`Update` と `Cancel` は出さない。同じ値で Enter を押したときは何も出さない。
- `FieldPath` の戻り値は「確定し、かつ値が変わった」ときだけ true にする。描き方の共有関数で決めるので、既存の `ImGuiFieldVisitor` も同じになる(今は同じ値の Enter でも true を返し、Decal が `SetTexturePath` でロード状態を作り直してしまう)。
- 値の JSON 表現は `JsonWriteVisitor` と同じにする。`JsonFieldVisitor.h` の型ごとの書き出しを自由関数(`ToJson(const T&)`)に切り出し、2 つの Visitor から呼ぶ。Quaternion は UI では Euler 角で編集するが、イベントの値は `[x,y,z,w]` になる。
- **書き換えるのは渡された写しだけ**。写しの持ち方(項目が操作中の間は編集モデルから作り直さないこと)は呼び出し側(E7 のインスペクター)の責務にし、本節の契約として書いておく。
- Begin と Commit を組にしてコマンドを作るのも呼び出し側(7.6 節)。
- 検査のために、`recordItemRects` を true にすると、フィールドごとの項目の矩形(キーと最小・最大の座標)を `itemRects` に残す。既定は false。
- `ReadOnly(...)` は `ImGuiFieldVisitor` と同じく文字で出し、イベントは出さない。`hidden` のフィールドは描かず、イベントも出さない。`readOnly` 属性のフィールドは無効状態で描くので、イベントは出ない。

**4. `ComponentMeta` の公開情報**

```cpp
const char* category = nullptr;  // Add Component パレットの分類。nullptr は "Other"
bool        addable  = true;     // インスペクターの Add Component に出すか
std::function<void(void*, std::vector<FieldEditEvent>&)> drawEditPtr;  // AQ_DEBUG_IMGUI のみ。FillReflectPtrFns で埋める
```

- 削除の可否は既存の `remove == nullptr` のまま使う(別のフラグを足さない)。
- `addable = false` にするのは Transform と HierarchicalTransform(自動で付くもの)。カテゴリは Core(Transform 系)、Rendering(メッシュ、Decal、パーティクル、Terrain、Ocean)、Animation、Audio、Gameplay(Spawner、LevelStream)にする。
- 既存のパレット(Prefab エディタ、ヒエラルキー)は E6 では変えない。この 2 つを使うのは E7 から。
- `LevelStream` に `FillReflectPtrFns` を足すのは E6 の範囲外(`LevelComponentRegistry.cpp` の注記どおり、Level 設計の L7 で行う)。

**5. 検査ツール `Tools/ReflectionTest`**(CMake 専用。MixerTest と同じ構成)

```
ReflectionTest --selftest [--assets <Game/Assets のパス>] [--dump <出力ファイル>]
```

| 試験 | 内容 | 段 |
|---|---|---|
| T1 往復 | `serializePtr` を持つ全型で、既定値で作る(`AlignedStorage(TypeInfo)`)→ `serializePtr` → 新しい実体に `deserializePtr` → `serializePtr` が一致する | E6a |
| T2 疎な JSON | 全型で、`{}` を `deserializePtr` しても書き出しが変わらない。数値・真偽値・数値の配列の各キーについて、そのキーだけの JSON(数値は +1、真偽値は反転、配列は先頭の要素に +1)を `deserializePtr` すると、書き出しでそのキーだけが変わり、値が一致する(数値は float に丸めて比べる)。パスのキーは変えない(リソースを読ませないため)。Animation は既定値ではクリップが空で見逃すので、クリップを 1 つ持たせた実体でも `{}` と `playSpeed` だけの JSON を試す。E6a では Animation と Terrain の `resolution` / `heightScale` / `terrainSize` が `[XFAIL]`、E6b では `[PASS]` | E6a |
| T3 既存アセット | `--assets` 以下の全 `*.prefab.json` と `*.level.json` を開き、`components` オブジェクトの各コンポーネントを、既定値の実体へ `deserializePtr` してから `serializePtr` し、ファイル名・JSON の位置・型名・結果を `--dump` へ書く(書き出しは `JsonSerializer::Stringify`)。登録されていない型名と `serializePtr` が無い型名は、名前だけを書く | E6a |
| T4 編集イベント | 画面を持たない ImGui のコンテキストを作り、マウスとキーの入力を合成して、試験用の型(float、片側だけ範囲付きの float、bool、Vector3、Quaternion、パス、文字列、readOnly、hidden)を `ImGuiEditEventVisitor` で描く。期待: (1) float のドラッグで Begin 1 回 → Update 1 回以上 → Commit 1 回、Begin は変更前・Commit は変更後の値。(2) 押して動かさずに離すと Begin → Cancel。(3) チェックボックスのクリックで Begin → Update → Commit(フレームは問わない)、値が反転する。(4) Vector3 の 1 成分のドラッグで Begin → Update → Commit が 1 組。(5) パスと文字列は、値を変えて Enter で Begin と Commit が同じフレームに 1 組、同じ値で Enter では何も出ない。(6) readOnly と hidden はイベントを出さず、hidden は `itemRects` に出ない。(7) 同じフレームで先に別の項目が変わっていても、Vector3 のドラッグに Update が出る(試験では Vector3 を描く直前に `imgui_internal.h` の `ImGuiContext::AnyIdHasBeenEditedThisFrame` を true にして再現する)。(8) ドラッグの途中で描くのを 1 フレーム以上やめ、再び描いても、古い操作の Commit / Cancel が出ない。Ctrl+クリックの直接入力の途中で同じことをしても、`Begin` の無い `Update` が出ない(出るなら同じフレームの Begin と Commit の 1 組)。(1)〜(7) では、Begin の後には Commit か Cancel が必ず 1 つ来る | E6b |
| T5 属性 | `ImGuiFieldVisitor` と `ImGuiEditEventVisitor` の両方で、片側だけ範囲付きの float を下限の外へドラッグしても、Ctrl+クリックで下限の外の値を入力しても、下限に収まる。範囲の無い float は今と同じく制限されない | E6b |

- 結果は 1 試験 1 行で `[PASS]` / `[FAIL]` / `[XFAIL]`(既知の失敗)を出し、FAIL が 1 つでもあれば終了コード 1 にする。既知の失敗の印の付いた試験が通ったら `[XPASS]` と出し、これも終了コード 1 にする(直ったのに印を外し忘れないため)。
- 画面を持たない ImGui では、レンダラーが無いのでフォントアトラスを自分で作る(手順は実装時に v1.93 の `imgui.h` で確かめる)。
- 型によって画面無しで作れない(既定のコンストラクタが GPU に触れる)ことが分かったら、黙って外さず、名前と理由を試験の出力と本節に書く。

### テスト方針

| 確認 | 方法 | 担当 |

- T3 の出力は 4 構成とも E6a の控えと**完全に一致**した(Terrain を使うアセットが無いので、許していた差分も出なかった)。
- T4 で記録したイベント列(Metal Debug):
  - (2) 押して離す: `Begin` と `Cancel` が別のフレームに出る。
  - (3) チェックボックス: 押したフレームに `Begin`、離したフレームに `Update` と `Commit`。
  - (8) ドラッグの途中で描くのをやめる: `Begin` → `Update` の後、再表示しても古い操作の `Commit` / `Cancel` は出ない(呼び出し側が捨てる)。
  - (8) 直接入力の途中で描くのをやめる: 再表示のフレームに ImGui が保持していた入力を適用し、`Begin`(1.5)と `Commit`(3)の 1 組が出た。最初の `Begin` は閉じないまま残るので、呼び出し側が捨てる。
  - `DragFloat3` で Tab を使って x から y へ移る(記録のみ): 非活性を挟まず、`Begin` → `Update` → `Update` → `Commit` の **1 操作**になった。
- 実装で決めたこと(設計に書いていなかったもの):
  - 共有の描き方の関数は `aq::ecs::fieldwidget`(`DrawFloat` / `DrawInt` / `DrawBool` / `DrawVector3` / `DrawQuaternion` / `DrawString` / `DrawReadOnly`)。`DrawText` は Windows のマクロと衝突するので使わない。
  - `FieldAttr.h` は `ECS/ECS.h` から include する(各コンポーネントが追加の include なしで使えるように)。`Level/LevelComponents.h` は ECS.h を include しないので個別に include する。
  - `Asset(...)` は Reflect に加えて、各 `Inspect` の `FieldPath` にも付けた。`LevelStream` の `level` は `Asset(Level)`、`category` は `"Gameplay"`(`LevelComponentRegistry.cpp`)。
  - Animation の `drawEditPtr` は付けない(Reflect を持たず、`DrawInspectorImGui` が対象を直接書き換えるため)。E7 で、`drawEditPtr` の無い型を読み取り専用にするか、`serializePtr` の前後の差分でコマンドを作るかを決める(15 章)。
  - Terrain のオーサリング値は「0 は未設定で `chunk_` の値を使う」。`SetDesc` で 3 つの値を desc から写し、`Inspect` で heightScale / terrainSize を変えたときも `chunk_` の値を写す(保存が古い値を書かないように)。`heightScale` に 0 を保存したいときは `chunk_` の値が書かれる(実用上の問題は無いが、0 を区別したくなったら別のフラグにする)。
  - ツールチップは readOnly の項目でも出るよう `ImGuiHoveredFlags_AllowWhenDisabled` を付けた。
  - 検査ツールの画面無しの ImGui は、フォントアトラスを `GetTexDataAsAlpha8` の旧来の経路で作り、`io.ConfigMacOSXBehaviors = false`(Ctrl を Ctrl として扱う)。同じ位置を続けてクリックするとダブルクリックになるので、試験の間に 30 フレーム空ける。
