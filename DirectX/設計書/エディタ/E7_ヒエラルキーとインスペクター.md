### 現状(調査結果。7a663cf で確認)

| 項目 | 実コード |

### 決定

E7 を 3 段に分ける。

| 段 | 内容 |
|---|---|
| E7a | 構造の編集。エンジン: `LevelEditModel` の構造操作 API、ツリー関数を操作要求を返す形に直す(既存の Prefab / Level エディタはその場で適用して挙動を保つ)、ReflectionTest の T10。Editor: `EditorContext`、コマンドの列、ヒエラルキー(Edit)、Level の New / Open / Save、プレビューの維持 |
| E7b | 値の編集。エンジン: `LevelEditModel` の値・コンポーネントの API と参照ノードの解決、T11。Editor: インスペクター(Edit) |
| E7c | Play / Pause 中のヒエラルキーとインスペクター(実行中のワールド。`SceneHierarchySystem` の中身を流用) |

**1. 置き場所の分担**(ユーザー決定 2026-11-19 の「エンジンには口だけ」に沿う)

| 置き場所 | 持つもの |
|---|---|
| エンジン `LevelEditModel`(`AQ_DEBUG_IMGUI`) | 編集モデルを変える**操作の本体**(ノード ID で指す。履歴・UI・選択は持たない)。ReflectionTest から画面無しで試せるようにするため、ここに置く |
| エンジン `PrefabEditNodeOps` | ツリー描画(操作要求を返す)と、要求をその場で適用する補助(既存の 2 エディタ用) |
| Editor `EditorContext` | 編集モデルへの参照、選択(ノード ID)、コマンドの列、変更の有無(dirty)、モデルの版番号 |
| Editor `Commands/` | `IEditorCommand`(9 章)と E7 のコマンド。`Execute` は `LevelEditModel` の操作を呼ぶだけ。`Undo` は E8 で実装する(E7 では宣言だけで、呼ばない) |
| Editor `Panels/` | ヒエラルキー、インスペクター、Level のファイル操作(メインメニューバー) |

- **パネルには `const LevelEditModel&` だけを渡す。** 可変の参照はコマンドの `Execute` だけが受け取る(`EditorContext::ApplyCommands` が渡す)。ただし `const` の `GetEntities()` からでも `unique_ptr` の先のノードは書き換えられ、`AlignedStorage::Get() const` も `void*` を返すので、**`const` だけではコンパイルで保証できない**(Codex レビュー 1 回目)。パネルはノードを `const ecs::PrefabEditNode*` として読むだけにし、コンポーネントの値は自分の写し(7.)にだけ書く、という規約にして、本体の差分レビューで確かめる。
- 編集モデルは今と同じく `LevelEditorPanel` が持つものを使う(Play / Stop の記録と同じ実体)。Editor では **Level エディタのウィンドウとメニュー項目を出さない**(`LevelEditorPanel::SetHostedByEditor(true)`。Editor が起動時に呼ぶ)。同じモデルを 2 つの UI が触ると、Level エディタの生ポインタの選択が Editor の削除で宙に浮き、変更がコマンドを通らないため。`ProcessPreviewRequest` は今どおり `DebugRender` の先頭で呼ばれてよい(要求が無ければ何もしない)。

**2. `LevelEditModel` の構造操作(E7a)**

```cpp
/** ノードの置き場所。nodeId != 0 ならそのノードの子、0 なら subLevel のルート列(-1 = トップレベルの entities) */
struct NodeParent
{
	uint32_t nodeId        = 0;
	int      subLevelIndex = -1;   // 1 段目のインライン subLevel の添字(UI と同じく 2 段目以降は扱わない)
};

static constexpr size_t APPEND = SIZE_MAX;

bool     FindParent(uint32_t id, NodeParent& outParent, size_t& outIndex) const;
uint32_t InsertNode(const NodeParent& parent, size_t index, std::unique_ptr<ecs::PrefabEditNode> node); // 失敗は 0。AssignId する
std::unique_ptr<ecs::PrefabEditNode> DetachNode(uint32_t id, NodeParent* outParent = nullptr, size_t* outIndex = nullptr);
bool     MoveNode(uint32_t id, const NodeParent& newParent, size_t index);
bool     SetNodeName(uint32_t id, const std::string& name);
const ecs::PrefabEditNode* FindNode(uint32_t id) const;   // 既存の非 const 版に const 版を足す
```

- 取り外したサブツリーは `editId` を保ったまま返す(E8 の削除コマンドが持ち、Undo で戻すと子孫の ID も戻る。9 章)。`InsertNode` は採番済みの ID を変えず、未採番(0)のノードだけに振る。
- **参照ノードの下には挿入・移動しない**(7.2 節。override 編集 UI は E12)。自分自身と子孫の下へは移動しない。いずれも false(`InsertNode` は 0)を返し、モデルを変えない。
- `index` が範囲外なら末尾に置く。移動で同じ親の中の後ろへ動かすときは、取り外した後の添字として扱う。
- 外部ファイル参照の subLevel(`isInline == false`)を指す `NodeParent` は無効(false)。
- 新しく作る実体ノードは Transform を必ず持つ(今の Level エディタと同じ。`PrefabNodeEnsureTransform` をコマンドが作るときに呼ぶ)。

**3. ツリー関数を操作要求を返す形に(E7a)**

```cpp
enum class PrefabNodeOpKind : uint8_t { Select, AddChild, Delete, Move };

struct PrefabNodeOp
{
	PrefabNodeOpKind kind;
	PrefabEditNode*  target    = nullptr;   // Select / AddChild の親 / Delete / Move の移すノード
	PrefabEditNode*  newParent = nullptr;   // Move の移動先(このノードの子の末尾へ)
};

struct PrefabTreeDrawOptions
{
	const PrefabEditNode* selected       = nullptr;
	const PrefabEditNode* root           = nullptr;   // Delete を出さないノード(今の root 引数)
	bool                  enableMove     = false;     // ドラッグアンドドロップで Move を出す(Editor だけ)
	bool                  allowRefChild  = true;      // false なら参照ノードに Add Child を出さず、ドロップも受けない
	bool                  markReference  = false;     // 参照ノードの名前に印を付ける
};

void PrefabNodeDrawTree(const PrefabEditNode* node, const PrefabTreeDrawOptions& options, int depth, std::vector<PrefabNodeOp>& ops);
```

- ツリー関数は**モデルを書き換えない**(引数も `const`)。要求のポインタは、同じフレームで適用するか ID に直すまでの間だけ有効。
- 既存の Prefab エディタと Level エディタは、ツリーを描いた後で要求を**その場で**適用する(`PrefabNodeApplyOpsInPlace` を `PrefabEditNodeOps` に足す。Add Child の Transform の付与、Delete の削除予約、選択の更新を今と同じ順で行う)。オプションは `enableMove = false`、`allowRefChild = true`、`markReference = false` にし、**見た目と操作を変えない**。
- 適用の補助は、選択中のノードが削除したノードかその子孫なら選択を外す(今は削除したノードそのものの時だけ外している)。README の既知の課題(インライン subLevel の `[x]` による削除で `selected_` が宙に浮く)は**ツリーの要求を通らない別の経路**(`DrawSubLevels` の直接の `erase`)なので、E7 では直さず既知の課題のまま残す(Editor では Level エディタを出さないので影響しない)。
- `PrefabNodeDrawInspector` は既存のエディタ専用のまま残す(直接書き換え。16 章の「既存インスペクターをそのまま使う」は不採用のまま)。Editor のインスペクターは使わない。
- Move のドラッグの荷物はノードのポインタ(ImGui の荷物はコンテキストごとなので、他のコンテキストへは渡らない)。ドロップは描いたフレームに返るので、Editor はそのフレームのうちに ID へ直す。

**4. Editor のコマンドと適用の時点(E7a)**

```cpp
class IEditorCommand      // 9 章の形。Execute / Undo が受け取るのは EditorContext ではなく編集モデル
{
public:
	virtual ~IEditorCommand() = default;
	virtual bool        Execute(aq::level::LevelEditModel& model) = 0;   // 失敗(対象が無いなど)なら false
	virtual void        Undo(aq::level::LevelEditModel& model) = 0;      // E8 で実装する
	virtual const char* GetName() const = 0;
};
```

| コマンド | 持つもの | 段 |
|---|---|---|
| `CreateNodeCommand` | 親(`NodeParent`)、位置、作るノード(名前、Transform 付き)。実行後に振られた ID | E7a |
| `DeleteNodeCommand` | ノード ID。実行後に取り外したサブツリー・元の親・位置(E8 の Undo 用) | E7a |
| `MoveNodeCommand` | ノード ID、移動先の親・位置。実行前の親・位置 | E7a |
| `RenameNodeCommand` | ノード ID、変更前と変更後の名前 | E7b |
| `SetFieldCommand` | ノード ID、`typeName`、キー、変更前と変更後の JSON 値 | E7b |
| `AddComponentCommand` / `RemoveComponentCommand` | ノード ID、`typeName`、(削除は)取り外したコンポーネントの JSON | E7b |

- パネルは `EditorContext::Submit(std::unique_ptr<IEditorCommand>)` で列に積むだけ。**列は次のフレームの `OnBeginFrame` の先頭で**、`PlayModeController::ApplyPendingRequest` より前に、積んだ順にすべて実行する(5.3 の手順 7 にあたる、ECS の反復の外。同じ場所で遷移も実行しているので、コマンド → 遷移の順に揃える)。
- 1 つでも成功したら、版番号を進め、dirty を立て、**プレビューを置き換える**(`RequestPreview` → `ProcessPreviewRequest` をここで直接呼ぶ。完了待ちは 1 フレームに 1 回にまとまる。7.3 節)。Level エディタの `DebugRender` には任せない(F1 で隠すと呼ばれないため。8.5 節と同じ)。
- 失敗したコマンドは捨て、`startup_timing.log` にコマンド名と理由を 1 行出す。
- **Edit 以外のモードではコマンドを受け付けない**(`Submit` が捨てる。8.1 節「編集モデルは Play 中に変更しない」)。モードが変わるのはフレームの先頭だけなので、Edit で積んだコマンドが Play で実行されることは無い(同じフレームに Play も要求されていたら、コマンド → 遷移の順なので先に反映される)。
- Undo 履歴(コマンドスタック)は E8。E7 では実行したコマンドを捨てる。

**5. ヒエラルキー(E7a)**

- ウィンドウ名 `Hierarchy`。初回はゲームビューの左にドッキングする。同じドックスペースへ `SetNextWindowDockID` するだけでは同じノードのタブになるので(Codex レビュー 1 回目)、**`Hierarchy` の配置の保存が無いとき**(`ImGui::FindWindowSettingsByID` が nullptr)に 1 回だけ、`imgui_internal.h` の `DockBuilder` でドックスペースを左(Hierarchy、幅 20%)・中央(Game View)・右(Inspector、幅 25%)に分ける。既存の `editor_layout.ini`(Game View だけ)を持つ利用者にも効く。以後の配置は利用者が変えて `editor_layout.ini` に残る。`DockBuilder` は ImGui の内部 API なので、使うのは `EditorLayer` の初期配置の関数 1 か所だけにする。
- 上から: Level 名(見出し)、トップレベルの entities のツリー、`Sub Levels` の見出しの下に 1 段目の subLevel(インラインはその entities のツリー、ファイル参照はパスだけを無効表示)。
- ツリーは `PrefabNodeDrawTree`(`enableMove = true`、`allowRefChild = false`、`markReference = true`)。返った要求を ID に直して: Select → `EditorContext` の選択、AddChild → `CreateNodeCommand`(親 = そのノード)、Delete → `DeleteNodeCommand`、Move → `MoveNodeCommand`(親 = 移動先の子の末尾)。
- 各ルート列の見出し(Level 名、インライン subLevel 名)はドロップ先にもなり、そこへ落とすとその列の末尾へ移す。右クリック(と見出しの横の `+`)で `Create Entity`(その列の末尾に Transform 付きの `Entity`)。
- 削除したノード(とその子孫)が選択中なら、コマンドの実行後に選択を外す(選択は ID なので、`FindNode` が nullptr なら外すだけでよい)。
- 兄弟の中での並べ替え(挿入位置へのドロップ)、複数選択、subLevel 自体の追加・削除・パスや `loadOnStart` の編集は E7 では作らない(下の「このフェーズで作らないもの」)。
- Play / Pause 中は E7c の表示に切り替える。

**6. Level のファイル操作(E7a)**

メインメニューバーに `File` メニューを足す(`New`、`Open...`、`Save`、`Save As...`)。Play / Pause 中は無効。

- `Open...` / `Save As...` はパスを入れる小さなモーダル(OS のファイルダイアログは 10 章のとおりプラットフォーム抽象の後ろに置くべきもので、E9 以降)。既定値は今開いているパス、無ければ `Assets/Levels/New.level.json`。
- **`Save As...` で別のディレクトリへ保存するのは、モデルに相対パスの参照(参照ノードの `prefab`、ファイル参照の subLevel の `path`)が無いときだけ許す**。`SaveFile` は参照の文字列をそのまま書いて `baseDir_` だけを変えるので、相対参照の指す先が変わってしまうため(Codex レビュー 1 回目)。あるときは「相対参照があるので同じフォルダにしか保存できない」と出して保存しない。参照の書き換え(再配置)は E9 以降。モデルの判定は `LevelEditModel::HasRelativeReferences()`(E7a で足す。絶対パスの判定は `PrefabSerializer` の `JoinPath` と同じ)。新規(`baseDir_` が空)のモデルも同じ規則(空の基準ディレクトリはカレント基準なので、`Assets/...` のような参照はディレクトリを変えると指す先が変わる)。
- `Save As...` で基準ディレクトリが変わったら、プレビューを置き換える(相対参照が無いので見た目は変わらないが、プレビューの基準をモデルと揃えておく)。
- `New` / `Open` は、dirty なら「保存していない変更を捨てるか」を確認する。
- `Save` は**dirty のときだけ** `LevelEditModel::SaveFile` を呼ぶ(7.7 節。dirty でなければ何もしない)。パスが未定(New の直後)なら `Save As...` を開く。`Ctrl+S` も同じ(`ImGui::Shortcut(ImGuiMod_Ctrl | ImGuiKey_S, ImGuiInputFlags_RouteGlobal)`)。
- 開く・新規・保存の後は dirty を下ろし、選択を外し、版番号を進める。開く・新規の後はプレビューを置き換える。
- これらはモデル全体を入れ替える操作なので**コマンドにしない**(Undo の対象外。E8 では New / Open で履歴を空にし、Save / Save As では履歴を残す。9.1 節 4.)。モデルの差し替えは、コマンドと同じく次のフレームの `OnBeginFrame` で行う(`EditorContext` に要求として積む)。
- ウィンドウのタイトル代わりに、メニューバーに今のパスと dirty の印(`*`)を出す。
- 起動時は空の新規 Level(今の `LevelEditModel` の既定)で、プレビューを 1 回作る。`-editor-selftest` の準備の Playground のロードは今のまま。

**7. インスペクター(E7b)**

- ウィンドウ名 `Inspector`。初回の配置は 5. の分割で右に入る(E7a で分割と空のウィンドウだけ作り、中身は E7b)。選択が無ければ `No selection`。
- 見出し: Name(`InputText`。Enter か項目から外れたときに、値が変わっていれば `RenameNodeCommand`)。参照ノードは Prefab のパスを読み取り専用で出す(差し替えは E9 のドロップ)。
- **編集用の写し**: 選択中のノードのコンポーネントごとに `AlignedStorage` の写しを持つ。実体ノードは `serializePtr` → `deserializePtr` で作る。参照ノードは 8. の解決済みの値から作る。写しは「選択が変わった」「版番号が進んだ」ときに作り直すが、**フィールドの操作が開いている間(Begin を受け取って Commit / Cancel がまだ)は作り直さない**(6.4 節 3. の呼び出し側の契約)。
- 各コンポーネントは `PushID(ノード ID)` → `PushID(typeName)` の下で `CollapsingHeader` を描き、`drawEditPtr(写し, events)` を呼ぶ。イベントは: `Begin` で変更前の値を控え、`Commit` で控えと組にして `SetFieldCommand` を積み、`Cancel` で控えを捨てる。`Update` は使わない(ドラッグ中はプレビューに出ない。7.3 節)。
- 開いている操作のフィールドが描かれなかったフレーム(選択の切り替え、ヘッダの折り畳み、ウィンドウを閉じた・隠れた)は、控えを捨て、**写しも捨てて次のフレームで作り直す**(6.4 節 3.)。操作中に写しは書き換わっているので、控えだけを捨てると、確定していない値が残って表示され、次の `Begin` もその値を変更前として控えてしまうため(Codex レビュー 1 回目)。
- コンポーネントの削除: ヘッダの右クリックの `Remove Component` → `RemoveComponentCommand`。Transform(`addable == false` の型)は消せない。参照ノードでは出さない(7.2 節)。消せるかは編集モデルでは `addable` で決める(`remove == nullptr` は実エンティティから外す関数が無いことを表し、6.4 節 4. の Scene Hierarchy の判定。今は両方とも Transform 系の 2 型で一致する)。
- 追加: `Add Component` ボタン → `addable` の型を `category` ごとのサブメニューに並べ、すでに持つ型は出さない → `AddComponentCommand`(既定値)。写しと保存に要るので、`typeName` / `serializePtr` / `deserializePtr` を持つ型だけを出す(型消去の関数を持たない LevelStream は出ない。Level 設計の L7 で足すまで)。`drawEditPtr` の無い型(Animation)も追加はできる。参照ノードでは出さない。
- **`drawEditPtr` の無い型(Animation)は読み取り専用**にする(15 章の TODO の決定)。写しの `serializePtr` の JSON を整形して文字で出す。`drawInspectorPtr` の前後の差分でコマンドを作る案は、ドラッグのたびに 1 フレーム 1 回コマンドが出てプレビューの置き換え(GPU の完了待ち)が毎フレーム走るので採らない。Animation を Reflect 化するときに編集できるようにする。
- E7b ではフィールドの属性の追加は行わない(6.4 節 1. の「必要になったときに足す」は、E7b の確認で必要が出たものだけ足し、本節に記録する)。

**8. 参照ノードの値(E7b)**

```cpp
/** 参照ノードの解決済みのコンポーネント({ typeName: JSON })。参照ノードでなければ false */
bool ResolveReferenceComponents(uint32_t id, util::JsonValue& outComponents, std::string* error = nullptr) const;
bool SetComponentField(uint32_t id, const std::string& typeName, const std::string& key, const util::JsonValue& value);
bool AddComponent(uint32_t id, const std::string& typeName, const util::JsonValue* json = nullptr);  // 実体ノードだけ
bool RemoveComponent(uint32_t id, const std::string& typeName, util::JsonValue* outJson = nullptr); // 実体ノードだけ。Transform は消さない
```

- `ResolveReferenceComponents` は `PrefabSerializer::FromJson(PrefabNodeToJson(node), baseDir)` の根の `components` を返す(参照先の展開と override の適用を実行時と同じ経路で行う)。ファイルを読むので、インスペクターは写しを作り直すときだけ呼ぶ(毎フレーム呼ばない)。
- **失敗の判定**: 解決の結果が空でも失敗とは限らない(コンポーネントを持たない Prefab がある)し、途中の参照が失敗しても外側の override で空でなくなることがある(`ResolveNode` は失敗をログに出して空のオブジェクトを返すだけ)。そこで、`ResolveReferenceComponents` は解決の前に**直接の参照先**(`JoinPath(baseDir, prefabRef)`)を `JsonParser::ParseFile` で読めるかを確かめ、読めなければ false を返す(`std::string* error` に理由)。入れ子の参照の失敗は実行時と同じくログだけで、結果はそのまま使う(実行時に生成される内容と同じものを表示する)。
- **基準の付け替え(rebase)**: 今の override コンポーネントは「既定値 ← override の疎な JSON」で作られ(`LoadOverrideComponent`)、Prefab 側の値を持たない。このままでは、例えば Prefab で `maxCount = 3`、override 無しのとき、編集コンポーネントと `loadedJson` は既定値の `-1` で、UI で `3 → -1` にしても差分が出ない(Codex レビュー 1 回目)。そこで、参照ノードのコンポーネントを**初めて値の操作の対象にするとき**に、そのコンポーネントの基準を解決済みの値へ付け替える。
  - `R_raw` = 読み込んだときの override(`overridesRaw`)だけで解決した値、`R_cur` = 今の `PrefabNodeToJson(node)` で解決した値(どちらも上の経路で作る)。
  - そのコンポーネントの `loadedJson` ← `serializePtr(既定値 ← R_raw[型])`、実体 ← `既定値 ← R_cur[型]`。`PrefabEditComponent` に `bool rebased` を足して立てる(2 回目以降は付け替えない)。
  - override が無かったコンポーネントは、この 2 つで新しく作り、出どころを `Components` にする(`R_raw[型] == R_cur[型]`)。
  - 付け替えの前後で保存結果は変わらない: 書き出しは「`overridesRaw` ← (`loadedJson` と実体の差分)」で、`R_raw = 参照先 ⊕ overridesRaw`、`R_cur = R_raw ⊕ これまでの編集` なので、差分はこれまでの編集のうち `R_raw` と違うキーだけになり、実行時の結果は同じ。
- `SetComponentField` は、参照ノードなら上の付け替えをしてから、`deserializePtr(実体, { key: value })` でそのキーだけを変える(6.4 節「疎な JSON」)。
  - 実体ノード: そのコンポーネントを持たなければ false。付け替えは無い。
  - 参照ノード: 保存では、出どころが `components` なら `R_raw` と違うキーだけが増え、`addedComponents` なら全フィールドを書き戻す(E4a の規則のまま)。`3 → -1` は `-1` が書かれ、`3 → 5 → 3` は何も増えない。
  - 参照ノードで、`R_cur` にそのコンポーネントが無い(`removedComponents` で消えた型など)、または `ResolveReferenceComponents` が false: false。
- 値を変えて元に戻したキーは、差分に当たらないので書かれない(E4a の規則)。override が無かったコンポーネントで全キーを元に戻したときは、`overrides.components` に空のオブジェクトも作られない(差分が無ければ `MergeSectionMember` を呼ばない)。
- `rebased` と付け替えは Editor の経路(`SetComponentField`)だけが使う。既存の Prefab / Level エディタのインスペクター(`drawInspectorPtr` の直接書き換え)は今のまま(既定値基準)で、挙動を変えない。

**9. Play / Pause 中の表示(E7c)**

- ヒエラルキーとインスペクターは、Play / Pause の間は実行中のワールドを出す。`SceneHierarchySystem` のウィンドウの中身を描く部分を、ウィンドウを開かない公開関数 `DrawHierarchyContents()` / `DrawInspectorContents()` に切り出し(ゲーム用コンテキストのウィンドウはこれを呼ぶ形にして**挙動を変えない**)、Editor のパネルがエディタ用コンテキストで呼ぶ。選択は `SceneHierarchySystem` が持つもの(1 つ)を両方のコンテキストで共有する。
- Editor のパネルからは**値の直接の書き換えだけ**を許し(`drawInspector`。履歴に残さない。停止でワールドを作り直すので元に戻る。8.5 節)、**構造の変更(コンポーネントの追加・削除、親の付け替え、エンティティの破棄)は出さない**(切り出す関数に `allowStructuralEdit` を持たせ、Editor は false、ゲーム用のウィンドウは今どおり true)。7.4 節の「Play 中は読み取り中心」に合わせるのと、次の理由のため。パネルの上に `Playing: changes are not saved` と出す。
- **理由(Codex レビュー 1 回目で判明した既存の問題)**: Scene Hierarchy のコンポーネント削除・破棄は遅延コマンドで予約され、次のフレームの `EntityContext::Update` の Flush で、GPU の完了を待たずに実行される。GPU リソースを自分で持つコンポーネント(D3D12 のバッファはデストラクタで即時 `Release`)だと、GPU がまだ前フレームで使っている間に解放されうる。ゲーム用のデバッグ UI の Scene Hierarchy には今もこの問題があり、E7 では直さず README の「既知の課題」に記録する。値の書き換え(`drawInspector`)はリソースを解放しない範囲では安全だが、パスのフィールドを変えたときのリソースの差し替えは同じ問題を持ちうるので、これも同じ課題に含めて記録する。
- 呼ぶ時点(`OnBuildUI`)は、ゲーム用コンテキストの `DebugRender` と同じく ECS の更新の後・描画の提出の前なので、値の直接の書き換えは今の Scene Hierarchy と同じ条件で動く。
- Edit 中は今までどおり、ゲーム用のデバッグ UI の Scene Hierarchy でプレビューのワールドを直接いじれる(次のプレビューの置き換えで消える。今の挙動のまま)。

### 保存のコメントと改行(2026-11-22、E7 の後の対応)

E7a の自動操作で、保存すると `.level.json` の `//` コメントが消えることが分かった。ユーザー決定でコメントを保持する。

- 今のアセットと試験データのコメントは、すべてファイルの先頭(ルートの `{` より前)にある。そこで**先頭のコメントだけを保持する**。`JsonParser::ExtractLeadingComments` / `ReadLeadingComments` が先頭の `//` 行と空行を取り出し(改行は LF、BOM は落とす、後ろの空行は落とす)、`LevelEditModel::LoadFile` と Prefab エディタの Load が控え、`JsonSerializer::WriteFile(path, v, leadingComments)` で先頭に書き戻す。新規の Level / Prefab にはコメントを付けない。

- `JsonSerializer::WriteFile` をバイナリで開いて LF で書くようにした。テキストモードでは Windows で CRLF になり、LF で管理しているアセットを保存するたびに改行が全部変わっていた(UI のスタイル・ドキュメントの保存も同じ関数なので LF になる。UI のアセットも LF で管理されている)。

### E7b の結果(2026-11-21、f14609f)

確認の結果は 11.3 節。実装で決めたこと・分かったこと:

- `ResolveReferenceComponents` の結合は `PrefabSerializer` の `JoinPath` と同じ規則の関数を `LevelEditModel.cpp` に持つ(公開はしない)。解決済みの値は Prefab ファイルに書かれた**疎な JSON** で、書かれていないキーは既定値になる(インスペクターの写しは「既定値 ← 解決済みの値」で作る)。
- 参照ノードの `SetComponentField` は、`rebased` 済みのものと `loadedJson` が空(Prefab エディタで足した型)のものは付け替えずに適用する。`removedComponents` にある型、`R_raw` / `R_cur` に無い型は false。一時のコンポーネントに作ってから差し替えるので、失敗してもモデルは変わらない。
- `AddComponent` はモデルでは `addable` を見ない(インスペクターが `addable` の型だけを出す)。`RemoveComponent` は `addable == false` で false。
- インスペクター: 描いたノード ID と型名をフレームごとに記録し、開いている操作のうち描かれなかったものを捨てて写しも作り直す。Commit でコマンドを積んだら写しを捨て、次のフレームに反映後のモデルから作る(コマンドが失敗しても確定していない値を残さない)。参照ノードの解決に失敗したら、作り直すまで再試行しない。名前は `IsItemDeactivatedAfterEdit` で確定し、入力中に描かれなくなったときは自分で確定する。空の名前は送らない。
- 試験で分かったこと: 読めないファイルへの `JsonParser::ParseFile` はアセットパスの候補を探すときに `Engine::GetContentRoot` を引き、Engine が無いと落ちる(ReflectionTest の画面無しの試験だけで起きる。Editor・Game では Engine がある)。T11 の該当の試験は、その間だけ Engine を作る。
- E8 への申し送り: `RemoveComponentCommand` は取り外した JSON を持つが、並びの位置は持たない。Undo で並びも戻すならエンジンの API に位置の受け渡しが要る。

### E7a の結果(2026-11-21、2a97702)

確認の結果は 11.3 節。実装で決めたこと(設計に書いていなかったもの):

- `NodeParent` と `APPEND` は `aq::level` の名前空間に置き、`LevelEditModel::NodeParent` / `LevelEditModel::APPEND` でも引けるようにした。`FindParent` / `DetachNode` が返す `NodeParent` は、親がノードのとき `subLevelIndex = -1` にそろえる。
- 構造操作の対象は、トップレベルと 1 段目のインライン subLevel の木だけ(UI と同じ)。2 段目以降の subLevel の中のノードは `FindParent` / `DetachNode` / `MoveNode` / `InsertNode` の対象外(false)。`FindNode` と `SetNodeName` は今までどおり入れ子も見る。
- `HasRelativeReferences` は参照ノードの子孫まで見る。ファイル参照の subLevel の空のパスは相対とみなす。参照ノードの `overrides.children` の中の参照は見ない(override の編集 UI は E12)。
- ドラッグの荷物の種類名は `PREFAB_NODE_DRAG_PAYLOAD`(`PrefabEditNodeOps.h`)。ツリーの受け側は、受けられないドロップ(自分・子孫・参照ノード)では `AcceptDragDropPayload` を呼ばない。見出しへのドロップは、荷物のポインタが今のモデルにあることをアドレスで確かめてから読む。
- 既存のエディタ: 要求は 1 つのリストを描いた直後に適用する(選択の変更は同じフレームの描画後になる)。Prefab エディタは、削除で選択が外れたらルートを選ぶ(今までは削除したノード自身が選択中のときだけだった)。Level エディタの Add Child / + Entity のノードは今までどおり `editId` を振らない(Editor では Level エディタを出さないので使われない)。
- `EditorContext` の呼び出し順は `ApplyPending`(コマンド → ファイル操作 → プレビューの置き換え)→ 自己テストの Tick → `PlayModeController::ApplyPendingRequest`。失敗したコマンドの理由は `IEditorCommand` に返す口が無いので、コマンド名だけをログに出す。
- プレビューのログは、Level ごとにエンティティを引く API が無いので Edit のワールド全体を出す(Editor は空のワールドで起動するので、Edit ではワールド = プレビュー)。木は 400 文字ずつ `preview tree[n]` に分ける(ログの 1 行が 512 バイトで切れるため)。
- パスが未定(New の直後)の Save は Save As のモーダルを開く。Open / Save の失敗はメニューバーに赤で出す。Inspector は E7a では `EditorLayer` の中の仮の描画(選択ノード名だけ)で、E7b で `Panels/` に移す。
- 初期配置は最初のフレームで 1 回だけ判定する(ImGui が ini を書くまでは `FindWindowSettingsByID` が nullptr のままなので、毎フレーム判定すると分割を繰り返す)。分割したフレームは Game View の `SetNextWindowDockID` を省く。Hierarchy と Inspector は Game View より先に描く(起動直後のフォーカスを Game View に残すため)。
- 自動操作の注意: `SendKeys` で `^a` とパスを 1 つの文字列で送ると、パスの入力が効かないことがあった。別々に送ると効く。
