## 3. 不足機能の分類(2026-11-11 に実コードで確認)

「無い」= 該当コードが無い。「薄い」= 土台や一部は在るが、名前から期待する機能には届かない。「在る」= 使える。

| 領域 | 機能 | 分類 | 根拠(実コード) |
| --- | --- | --- | --- |
| ポストプロセス | SSAO | 無い | 該当パス・シェーダが無い。GBuffer は `baseColor+metallic` / `N+roughness` の 2 枚で AO チャンネルも無い(`PBRGBuffer.fx`) |
| | SSR | 無い | 該当パス・シェーダが無い。HiZ は在るが用途は遮蔽カリング(`Rendering/Occlusion/HiZRenderer`) |
| | 被写界深度 | 無い | 該当パス・シェーダが無い |
| | カラーグレーディング | 薄い | `Tonemap.fx` の `ApplyTonemap` が露出とホワイトポイント付きのトーンマップだけ。LUT・彩度・コントラストは無い |
| | ビネット | 薄い | `Vignette.fx` は在るが、使っているのは `Sample/Application/VignettePass.cpp` だけ。エンジンのパス列には無い |
| | アンチエイリアス(TAA・FXAA など) | 無い | 該当パス・シェーダ・MSAA 設定が無い。TAA の前提になるジッターも無い |
| | Bloom・MotionBlur・Tonemap・Outline・Decal | 在る | `Rendering/Pipeline/Passes/` |
| ライティング | IBL(環境光の反射) | 無い | `PBRLighting.fx` に irradiance / prefiltered cube の参照が無い。スカイボックスは描画のみ |
| 影 | ソフトシャドウ | 薄い | `ShadowSampling.fx` の 3x3 PCF 固定。幅は `ShadowSettings::softness` で変えられる |
| | CSM | 無い | `ShadowCBData` に `lightViewProj[4]` と `cascadeSplits` の枠は在るが、`HardShadowRenderer::FillShadowCBData` は**ディレクショナルライトごとに 1 枚**として使っている(`cascadeCount` = ライト数、split は未使用)。各スライスは `sceneCenter` 中心の固定の正射影 |
| ナビゲーション | NavMesh / 経路探索 | 無い | grep で該当なし |
| ネットワーク | ゲーム用通信 | 無い | ソケットは `Link/LinkSocket` (エディタ連携用のローカル TCP)だけ |
| 物理 | Joint / Constraint | 無い | `BulletPhysicsWorld` / `BulletRigidBody` に拘束の API が無い。`GetDynamicWorld()` で `btDiscreteDynamicsWorld` を直接触れば Bullet の拘束は足せる(抽象の外) |
| | 剛体・Raycast・ConvexSweep・CharacterController・Ghost | 在る | `Physics/` |
| アニメーション | ステートマシン | 無い | エンジンに無い。ゲーム側の `app::actor::StateMachine`(`Game/Application/Actor/StateMachine.h`)は Entry/Update/Exit の汎用 FSM で、アニメとは結び付いていない。AquaDash は `SpeedCharacterSystem` がコードでクリップを選ぶ |
| | ブレンドツリー / レイヤー / マスク | 無い | `AnimationComponent` は `Play(nameHash, looping, blendSec)` の 2 クリップ間フェードのみ |
| | IK | 無い | grep で該当なし |
| | アニメーションイベント | 無い | `AnimationClip.h` に通知・イベントの仕組みが無い |
| ゲーム周辺 | セーブデータ | 薄い | 書き込み先 `Engine::GetUserDataDirectory()` は全プラットフォームに在り、`JsonSerializer::WriteFile` も在る。使っているのはゲーム側のゴースト保存(`GhostData::SaveToFile`、ステージごとに 1 ファイル)だけで、スロット・バージョン・設定の保存といった汎用の仕組みは無い |
| | ローカライズ | 無い | 文字列テーブル・言語切替が無い |
| | スクリプト | 無い | 組み込みスクリプト言語が無い |

## 6. Windows 確認(2026-11-16)

§5 の済の 4 件(SSR・IBL・被写界深度・SSAO)は Mac(Metal / Vulkan)でしか動かしていなかった。Windows 機で D3D11 / D3D12 / Vulkan の 3 構成を確認した。
この節が手順と結果の一次記録で、各設計書からはここを参照する。

### 手順

- Sample: `build_windows.bat` と同じく CMake の VS 2026 生成で、API ごとにビルドディレクトリを分ける(`-DAQ_GRAPHICS_API=D3D11 / D3D12 / Vulkan`)。Debug。
- Game: `Game/DirectX.vcxproj` を msbuild で `/p:AqGraphicsApi=D3D11|D3D12`。Debug。
- 起動 → 12 秒後にクライアント領域を撮影 → `CloseMainWindow` で終了コードを見る。Game はタイトルで Space を送ってステージに入れてから撮る。
- 画の比較は、左上の ImGui とメニュー行を除いたチャンネルごとの最大差。Windows の Vulkan を基準にする(Mac で確かめた経路と同じシェーダ・同じ SPIR-V 変換)。

### 結果

| 対象 | D3D11 | D3D12 | Vulkan |
| --- | --- | --- | --- |
| Sample(SSAO・SSR・DoF・IBL すべて有効)のビルド | 通る(差分ビルド) | 通る(差分ビルド) | 通る(初回ビルド。警告 52 件はすべて既存の Bullet 由来) |
| Sample の起動〜終了コード | 0 | 0(下の修正 2・3 の後) | 0 |
| Sample の画(Vulkan との差) | 最大 7/255・10 画素 | 右下隅の 2 画素のみ(修正 3 の後) | 基準 |
| AquaDash のステージ(IBL 有効)| 表示・終了コード 0(修正 4 の後) | 表示・終了コード 0 | 見ていない |

### 見つけて直したもの

1. **Sample が Windows でコンパイルできなかった。** `SampleModule.cpp` の変数名 `small` が Windows ヘッダのマクロ(`#define small char`)と衝突。SSAO P3 で足した行。変数名を `topBox` に変えた。
2. **D3D12 で SSR を有効にすると起動時にアサートで止まっていた。** SSR トレースの compute が t3 を使うのに、D3D12 の compute ルートシグネチャが t0〜t2 しか持たず PSO が作れなかった。t0〜t3 に広げた(README「既知の課題」)。
3. **D3D12 だけ IBL の粗さ 0 / 1 の箱の色が違っていた**(最大 43/255)。D3D12 が `PSSetSampler` を無視し、BRDF LUT を Wrap で読んでいた。LUT の座標を端の texel 中心までに収めて回避(README「既知の課題」。根本の D3D12 のサンプラの扱いは未対応)。
4. **D3D11 でインスタンス描画が消えていた。** 草・花だけでなく道路・路肩線・中央線・コインも消えていた。D3D11 にインスタンス描画を実装した(README「既知の課題」)。

### 見ていないもの

- デバッグ UI での各機能の ON/OFF、各機能を無効にしたときに画が変わらないこと(Mac で確認済みの項目。Windows では既定の構成の画だけ見た)。
- Release 構成と FPS。
- Windows の Vulkan での AquaDash。
