### 2.2 設計

**バックエンド側**(P1-A)。`IGraphicsDeviceImpl` に no-op 既定のフックを足す。

```cpp
struct ImDrawData;   // 前方宣言のみ。imgui.h を引き込まない

virtual bool ImGuiInit()                  { return true; }   // 失敗時 false
virtual void ImGuiShutdown()              {}
virtual void ImGuiNewFrame()              {}
virtual void ImGuiRender(ImDrawData*)     {}   // レンダースレッドで呼ばれる
// VSync(現状 D3D12 のみ)
virtual bool CanToggleVSync() const       { return false; }
virtual bool GetVSync() const             { return true; }
virtual void SetVSync(bool)               {}
```

- `GraphicsDevice` が同名の薄い転送を持つ(既存の `RecreateSurface` / `WaitIdle` と同じ流儀)。
- 各バックエンドの `ImGuiInit` 等は、いま AppHost / ImGuiRenderCommand が直接呼んでいる処理をそのまま内側へ移す。
  - D3D11: `ImGui_ImplDX11_*` を `D3D11GraphicsDeviceImpl` 内で呼ぶ(device/context は自分が持つので `dynamic_cast` が消える)。
  - D3D12: `BeginFrameIfNeeded()` + `D3D12ImGui::Render(drawData, GetCommandList())` を `ImGuiRender` 内へ。
  - Vulkan / Metal: `ImGuiRender` が従来の `SetImGuiDrawData` を呼ぶ(drawData は CopyToBackBuffer 後に描く従来の挙動を維持)。
- `ImGuiRenderCommand::Execute` は `GraphicsDevice::Get().ImGuiRender(drawData_)` の 1 行になり、`#include` の `#if` も消える。
- **スレッド境界は変えない**: `ImGuiInit` / `ImGuiNewFrame` / `ImGuiShutdown` はメインスレッド、
  `ImGuiRender` は `ImGuiRenderCommand::Execute` の実行スレッド(= コマンドを実行するレンダースレッド。
  `AQ_RENDER_PIPELINED` が変えるのは待機の位置で、実行スレッドではない)。
- **終了順序は現状の契約を保つ**: CPU 描画完了 → レンダースレッド join → GPU `WaitIdle` →
  バックエンドの `ImGuiShutdown` → Platform の `ImGuiShutdown` → `ImGui::DestroyContext`
  ([AppHost.cpp](../aqEngine/Core/AppHost.cpp) の終了処理と同順)。フックへ移しても順序を入れ替えない。
- AppHost のバックエンド名表示は `GraphicsDevice` に `GetBackendName()`(既定 `"?"`)を足して `#if` を消す。
  **TODO**: 既に同等の API が在るか確認してから足す。

**Platform 側**(P1-B)。`IPlatform` に no-op 既定のフックを足す。

```cpp
virtual bool ImGuiInit()      { return true; }
virtual void ImGuiShutdown()  {}
virtual void ImGuiNewFrame()  {}
```

- Win32 → `ImGui_ImplWin32_*`(HWND は自分が持つ)。Mac → `MacImGui::*`。Android / iOS → `ImGuiPointerInput::*`。
- **フックの形(P1-B で確定)**: `ImGuiInit()` は `bool`(既定 true)、`ImGuiShutdown()` は `void`、
  `ImGuiNewFrame()` は **`bool`(既定 false)**。`true` は「Platform のバックエンドが `ImGuiIO` を更新した」、
  `false` は「持たない」で、このとき **AppHost が最低限の `DisplaySize` / `DeltaTime` を自分で入れる**
  (UWP が該当。値は Engine のものなので、Platform 層に Engine の参照を持たせないための形)。
- **決定(P1-B)**: 初期化中のフォント読込(Win32/Mac のシステムフォント)、モバイルの UI スケール、iOS の ini パスは
  **プラットフォーム固有の設定だが AppHost に残す**(別フックへは出さない)。Win32 と Mac でフォント探索の
  ロジックを共用していて、5 つの Platform へ散らすと重複が増えるため。この領域は `AQ_PLATFORM_*` の `#if` が残る。
  P1 の合格線は「**バックエンド側の `ENGINE_GRAPHICS_*` の `#if` が 0 件**」と「**Platform の入力バックエンド
  (init / shutdown / newFrame)の `#if` が 0 件**」とする。
- Platform の取り出しに `Engine::GetPlatform()`(`IPlatform*`、無ければ nullptr)を `Engine.h` へ足した(従来は公開の経路が無かった)。

## 3. P2: 無言の失敗を潰す + README の記述更新

### 3.1 現状(実コード確認済み)

1. [AppHost.cpp](../aqEngine/Core/AppHost.cpp) `SetupStandardRenderers`(L151〜): `PipelineBuilder::Build` 失敗時に
   `EngineAssertMsg(false, ...)` の後 `return` する。`EngineAssertMsg` は **Release では no-op**
   ([Utility.h](../aqEngine/Utility.h):23)なので、`renderer_` にパイプラインが設定されないまま起動が続き、
   `Renderer.cpp` の `if (!pipeline_) return;` で**全描画が黙って消える**。`Build()` 自身は `[pipeline]` ログを出すが、
   起動は失敗扱いにならない。戻り値が `void` なので呼び出し側が失敗を知れない。
2. `ShadowPass::Build`(`if (!renderer_) return;`)、`SkyPass`(`if (!sky_) return;`)、
   `FullscreenComputeCommand`(RT 取得失敗 / `computeShader_` が null で return)は**ログ無し**。
   影・空・ポストが消えても原因が分からない。

### 3.2 設計

- **README の更新**: `dynamic_cast` / `PostProcessChain` の 2 項目を「解消済み」へ。ImGui の項目は P1 完了時に更新。
  `-mode=edit` の「未実装ログ」の場所は AppHost ではなく [Engine.cpp](../aqEngine/Engine.cpp):91〜93 と訂正する。
  01 レンダリング設計 §7 の「既知の課題④の寸法契約」は、README に該当項目が見当たらない宙に浮いた参照

- **Build 失敗を初期化失敗として伝える**: 実際のゲーム経路は `SetupStandardRenderers` ではなく

  そのまま `SetRenderPipeline(nullptr)` へ渡され、`OnInitialize` は最後に `true` を返す。よって:
  - `AppHost::SetRenderPipeline` を `bool` 戻りにし、null を受けたら Release でもログを出して `false` を返す。
  - `GameModule::OnInitialize` は `false` なら `false` を返す(初期化失敗として `AppHost::Initialize` へ伝わる)。
  - `SetupStandardRenderers` も同様に `bool` 戻りにし、呼び出し側が初期化失敗として返す。
  - [System登録契約設計](System登録契約設計.md) の「登録失敗を初期化失敗として伝える経路」と同じ作法に揃える。
- **無ログ return の解消**: 毎フレームのログは禁物なので、**生成時に 1 回だけ** `StartupMarkf` で理由を出す。
  - 影・空: 標準プリセット([PipelinePresets.cpp](../aqEngine/Rendering/Pipeline/PipelinePresets.cpp))は
    生成に失敗すると **`ShadowPass` / `SkyPass` を列へ追加しない**ので、パスの `Setup` にログを足しても実行されない。
    ログは**プリセット側の生成失敗の分岐**(`shadow->Create` / `sky->Create` が false の else)に足す。
    機能自体は従来どおり無効のまま続行する(影なしで続行する既存作法を維持)。
  - `FullscreenComputeCommand`: RT 取得失敗 / `computeShader_` が null での return は、初回のみフラグで 1 回ログ。

## 4. P3: ドローの計測 → ソート

### 4.1 現状(実コード確認済み)

- 収集: [BodyComponentSystem.cpp](../aqEngine/Component/BodyComponentSystem.cpp) が ECS 走査順に `frame.items`(deferred)と
  `frame.forwardItems` へ `push_back`。**ソートは無い**(Rendering 配下の `std::sort` はパーティクルのみ)。
- 発行: GBuffer → `DeferredRenderer`(items 順)。Shadow → ライトごとに items + forwardItems。
  Forward → 不透明 → 半透明(`AlphaBlend` に切替えて同じ forwardItems を**もう 1 回走査**)→ instancedItems。
  **半透明は奥→手前のソートが無く、収集順のまま。** 重なると描画が崩れ得る。
- `RenderItem`([RenderFrame.h](../aqEngine/Rendering/RenderFrame.h):57〜104)は shared_ptr の `vs`/`ps`/`gbufferPS`/`vertexBuffer`/
  `indexBuffer`/`samplerState`、`textures[4]`、`worldMatrix`、`materialCB`(値)、`translucent` 等を持つ。
  `layer` は**常に 0 で誰も使っていない**(`MeshRenderHelper.h` の代入のみ)。PSO やマテリアル ID は無い。
- 1 ドローごとに b0(per-draw)・b1(lighting)・b2(material)・b3(shadow)・テクスチャ t0〜t3・サンプラー・VB・シェーダを
  毎回設定する(`DrawItemCommand.cpp`)。b1 / b3 は**フレーム共通なのに毎ドロー再バインド**。
  D3D11 の `D3D11RenderContextImpl` は状態キャッシュ無しで直接 `Set`。**TODO**: D3D12 / Vulkan / Metal のキャッシュの有無。
- 既存のインスタンシング([InstancedStaticMesh](../aqEngine/Graphics/InstancedStaticMesh.h))は forward 専用で、
  メッシュとマテリアルを手で登録する前提。シャドウ・GBuffer・法線/PBR・`materialCB` には未対応。
- 計測: [Profiler](../aqEngine/Util/Profiler.h)(CPU スコープ、`AQ_DEBUG_IMGUI` のみ)と ProfilerDebugPanel はある。
  **ドロー数・状態変更数のカウンタも GPU タイムスタンプも無い。**
  AquaDash の通常メッシュのドロー数は**静的には分からない**(実行時に数える必要がある)。

### 4.2 設計: 3 段階。ソートの採否は計測結果で決める

**P3-A 計測(挙動を変えない)**。ソートやバッチングの効果を言うには、まず数える。

- レンダースレッドが `DrawItemCommand` / `GBufferItemCommand` / `ShadowCastCommand` / `InstancedDrawItemCommand` の
  Execute でカウンタを加算する。数えるのは次の 3 種で、**「呼び出し回数」と「実際の状態遷移数」を区別する**

## 5. P4: リサイズ対応

### 5.1 現状(実コード確認済み)

- **通知経路が無い**: [PlatformWin32.cpp](../aqEngine/Platform/PlatformWin32.cpp) の `MsgProc` は `WM_PAINT` / `WM_DESTROY` のみで
  `WM_SIZE` を処理しない([アプリケーション構成とエディタ連携設計](アプリケーション構成とエディタ連携設計.md) L47「リサイズ非対応」)。
- **面寸法の追従だけがある**: [Engine.cpp](../aqEngine/Engine.cpp) の `SyncScreenSize()`(L337〜)は
  `GraphicsDevice::GetSurfaceSize` で `screenWidth_/Height_` だけ更新する。コメントで「レンダー解像度は据え置き」と明記。
  Vulkan / Metal / Android のみ `GetSurfaceSize` を実装(D3D11 / D3D12 は既定の false)。
- **サーフェス再作成**: `Engine::EnsureSurfaceUpToDate`(L362〜)→ `RecreateSurface` は Vulkan のみ実装
  (Android の窓差し替え用)。ただし extent は旧 `swapchainExtent_` を流用している。

- **固定寸法で作る画面依存リソース**(寸法は `PipelineBuilder::Build(w,h)` → `pass->Setup(res,w,h)` で渡る):

### 5.2 設計

**方針**: レンダー解像度 = 提示面のサイズ(倍率 1.0)に追従させる。固定内部解像度 + アップスケールは本書の対象外
(必要になったら別設計。`CopyToBackBuffer` の拡大挙動は **TODO(実装時に確認)**)。

**対応の有無はバックエンドが宣言する**。`IGraphicsDeviceImpl` に `virtual bool SupportsRenderResize() const { return false; }`
を足し、未対応のバックエンドは**従来どおり固定寸法のまま**動く(検出しても何もしない)。
これでフェーズ途中でも、対応済みバックエンドだけが新しい挙動になり、未対応のものは挙動が変わらない。

**検出**(P4-A)。寸法の読み取りは**デバイスの状態ではなく Platform から**行う。

- 現状の `Engine::SyncScreenSize` が使う `GetSurfaceSize` は、Vulkan では `swapchainExtent_` を読む。
  この値はレンダースレッドのスワップチェーン再作成が書き換えるため、`AQ_RENDER_PIPELINED` で前フレームが
  実行中のときにメインスレッドから読むと競合し得る(変更検出後の `WaitForRenderIdle` では、検出前の読み取りを守れない)。
  既存の `SyncScreenSize` も同じ値を読んでいたので、P4-B で Vulkan の `GetSurfaceSize` を原子の写し(`publishedExtent_`)へ変えて解消した。
- そこで `IPlatform` に `virtual bool GetClientPixelSize(uint32_t& w, uint32_t& h) const { return false; }` を足す。
  Win32 は `GetClientRect`、Mac / iOS はビューの bounds(`UpdateLayerBacking` が `drawableSize` に使う値)、
  Android は `ANativeWindow` の寸法。デバイスの内部状態を読まないので、レンダースレッドと競合しない。
  `false` を返す Platform は、従来どおり `GetSurfaceSize` にフォールバックする。
- `Engine` は `GetClientPixelSize` の値と**現在のレンダー解像度**を比較する。ドラッグ中の連続変更で毎フレーム
  作り直さないよう、**同じ値が 2 フレーム続いたら**確定とする。
- 0×0(最小化)は無視して現状維持。下限 1×1、上限はデバイス制限で `Clamp`。
- 確定したら `Engine::ResizeRenderTargets(w, h)` を呼ぶ(`SupportsRenderResize()` が false なら何もしない)。

**再作成の手順と失敗時の方針**。デバイス層では「失敗しても旧のまま」を保証できない
(Vulkan は `oldSwapchain` を指定すると、新規作成に失敗しても旧スワップチェーンが退役する。DXGI の `ResizeBuffers` は
旧バックバッファ参照を先に解放する必要があり、成功後の RTV 生成失敗も旧へは戻せない)。よって保証は次の分担にする:

- **パス層は「準備 → 確定 / 取り消し」の強い保証**(旧 RT を残したまま新 RT を一時領域へ作り、全員成功してから入れ替える)。
- **デバイス層は保証しない。代わりに「リサイズ保留」状態でフレームを飛ばして再試行する**。
  提示先が無い間はフレームごと飛ばす既存の作法(`IsRenderable()` / `EnsureSurfaceUpToDate` の再試行)と同じ。
  再試行は最大 `kMaxResizeRetries`(初期値 5)回。超えたら致命エラーとしてログを出し、終了を要求する
  (リサイズで確保できないのはデバイスロスト / メモリ枯渇相当で、描画を続けても壊れた画面になるため)。

手順(すべてゲームスレッド。フレームの外):

0. **対応可否の判定(デバイスを変える前)**: `SupportsRenderResize()` が true、かつメインパイプラインの
   `RenderPipeline::CanResize()`(全パスが `Independent` か `Resizable`)が true のときだけ先へ進む。
   どちらかが false なら**何もせず従来の固定寸法のまま**(`Engine` の寸法・viewport・デバイスも変えない。ログは 1 回)。
   デバイスの寸法だけ変えて未対応パスが旧寸法のまま取り残される、という状態を作らないための入口の判定である。
1. `AppHost::WaitForRenderIdle()`(CPU・GPU 双方の完了待ち)。
2. **デバイス**: `GraphicsDevice::ResizeMainTargets(reqW, reqH, outW, outH)`。スワップチェーンとメイン RT / 深度を作り直し、
   **実際に確定した寸法 `outW / outH`** を返す(Vulkan は `currentExtent` を優先するため、要求値と異なり得る)。
   失敗なら「リサイズ保留」のままフレームを飛ばし、次のフレームで 1 から再試行する。
3. **準備**: 全パスの `PrepareResize(outW, outH)` を列順に呼ぶ。**パスの寸法は要求値ではなく手順 2 の確定寸法**にする
   (メイン RT・提示面・全パスの寸法を一致させる)。新しい RT を一時領域へ作り、旧 RT はそのまま。
   失敗したパスは**自分で一時領域を片付けてから** false を返す(`Prepare` の契約)。1 つでも false なら、
   **`true` を返したパスだけ** `AbortResize()` を呼び、「リサイズ保留」のままフレームを飛ばして次のフレームで手順 3 から再試行する
   (デバイスは新寸法に確定済みなので、手順 2 は繰り返さない)。
4. **確定**: `PassResources` を**初期状態**(Build 時と同じ。Scene のみ)へ戻し、全パスの `CommitResize(res)` を列順に呼ぶ。
   各パスは一時領域を本体へ入れ替え、**旧 RT を解放**し、掲示板への登録と入力の取り直し(`Wire`)をやり直す。
5. `Engine` の寸法・ImGui の `DisplaySize` を更新し、「リサイズ保留」を解除。**TODO**: カメラのアスペクト比の更新箇所を確認する。

**リサイズ保留中の扱い**。
- **通常経路(1 回で成功)はフレームを飛ばさない**。`FrameStep` の先頭(`EnsureSurfaceUpToDate` の直後)で手順 1〜5 を実行し、
  そのまま同じフレームの `Update` へ進む。ゲーム・入力・UI・サウンドの更新は止まらない。
  確定のフレームだけ処理時間が延びてデルタ時間が大きくなるので、復帰後の最初のフレームは
  `GameTimer` の上限(既存。[GameTimer.cpp](../aqEngine/Util/GameTimer.cpp))に頼らず、**確定直後にデルタ時間を 1 フレーム分へ丸める**。
  **TODO**: `GameTimer` に丸める手段が在るか確認する(無ければ足す)。
- **失敗経路(まれ)だけフレームを飛ばす**。保留中は `FrameStep` が `Update` を呼ばずに戻る(`IsRenderable()` が false のときと同じ形)。
  この間、ゲーム時間・入力・UI は止まる。**サウンドは、再生を止めるのではなく供給を続ける**。`Update` を飛ばすと
  ストリーミング音声の供給(サウンド管理の更新。[Engine.cpp](../aqEngine/Engine.cpp) の `Update` 内の呼び出し)も止まり、
  既存バッファ(48 kHz で最大約 680 ms)を使い切ると音が切れる。200 ms 間隔の再試行が続くと間に合わなくなり得るので、
  保留中のフレームでも **サウンド管理の更新だけを呼ぶ経路**(`Engine::UpdateSoundOnly()`。`Update` 内の該当呼び出しを
  切り出して共有する)を通す。
  **デルタ時間の契約**: 保留中は `GameTimer::Tick()` が走らず、既存の呼び出しをそのまま切り出すと**前回のデルタ時間を繰り返し使う**。
  非ブロッキングのループでサウンド更新を続けると、フェード(`VolumeEnvelope`)が実時間より速く進み、フェードアウト中の音声が早期停止する。
  よって `UpdateSoundOnly()` は**自前で `steady_clock` の実経過時間を測って**それを渡す(`GameTimer` の値は使わない)。
  フェードは実時間どおりに進み、ストリームの供給だけが保留中も続く。
  **TODO**: `Update` 内でサウンド供給に当たる呼び出しの範囲(`SoundEngine::Update` が受け取る引数)を確認して切り出す。
  `AppHost::Update` は末尾で描画するので、保留中に一部だけ更新する案は採らない。
- **再試行の間隔**: デスクトップの `PumpEvents` は非ブロッキングで、失敗経路が短時間に空転して 5 回を使い切り得る。
  そこで**再試行は前回から 200 ms 以上あけて**行う(`steady_clock`。5 回で約 1 秒)。間隔が未満のフレームは何もせず戻る。

**検出の安定化**。要求寸法と確定寸法が異なる場合(Vulkan の `currentExtent` など)に、毎フレーム再作成を繰り返さないよう、
`Engine` は**直近に要求した寸法**(`lastRequestedSize_`)を覚え、`GetClientPixelSize` の値が `lastRequestedSize_` から
変わったときだけ再要求する(確定寸法とは比較しない)。

**パス側の契約**(P4-A)。`IRenderPass` は**ゲームが独自パスを足せる公開の拡張点**で、実際に
`Sample/Application/VignettePass` が画面寸法の RT を作り、前段の `Output` を `inputRT_` に保持している。
「既定は何もしない」にすると、こうしたパスが旧寸法・旧 RT のまま残って静かに壊れる。そこで**既定を「未対応」に倒す**
(opt-in)。

```cpp
enum class ResizePolicy { Unsupported, Independent, Resizable };
virtual ResizePolicy GetResizePolicy() const { return ResizePolicy::Unsupported; }   // 既定は未対応

// Resizable のパスだけが実装する。
virtual bool PrepareResize(uint32_t width, uint32_t height) { return true; }  // 新 RT を一時領域へ作る。失敗時は自分で片付けて false
virtual void CommitResize(PassResources& res)               {}                // 入れ替え + 旧 RT の解放 + Wire
virtual void AbortResize()                                  {}                // 一時領域の破棄(何度呼んでも安全)
```

- `Independent` = 画面寸法に依存する資源を持たない(影・空・UI・オーシャン等。保持する RT 参照も無い)。
- `Resizable` = 画面寸法の RT を持ち、上の 3 関数を実装する。
- **`RenderPipeline::Resize` は、列の全パスが `Independent` か `Resizable` のときだけ有効**。1 つでも `Unsupported` が
  あれば、そのパイプラインはリサイズ無効(固定寸法のまま)になり、`[pipeline] リサイズ無効: <パス名> が未対応` を 1 回ログに出す。
  これで未対応のカスタムパスが黙って壊れない。
- エンジンの全パス(約 16 本)に `GetResizePolicy` を付ける(実装時に全パスを洗って分類する。**TODO**: 一覧を本書へ追記)。
- **`Sample/Application/VignettePass` を P4-A で `Resizable` へ移行する**(同じリポジトリの利用者であり、移行例になる)。
  `Sample/README.md` の独自パスの書き方(L280 付近)も更新する。

- **`Setup` を 2 つに割る**。`CreateTargets(w, h)`(RT の生成。`PrepareResize` と共有)と `Wire(res)`
  (掲示板から入力を読み、自分の出力を登録する)。`Setup = CreateTargets + Wire`、`CommitResize = 入れ替え + Wire`。
  登録と入力の取り直しを 1 か所に集めるので、Setup と Resize で食い違わない。
- **有効かどうかの判定は `Setup` で 1 回だけ行い、メンバに保持する**。`OutlinePass` は `Setup` の先頭で
  掲示板に `GBuffer1` があるかを見て、無ければ資源を作らず無効として正常終了する(Forward のみの列)。
  この判定を `active_` に保持し、`PrepareResize` / `CommitResize` / `Wire` / `Build` はそれを見る
  (無効なら Prepare は何もせず true、Wire は登録しない)。列の構成はリサイズで変わらないので、判定をやり直さない。
  `CreateTargets` は判定の後ろでだけ呼ぶ(無効なときに不要な確保をして、従来成功した列で確保失敗を起こさない)。
- **保持済みの RT 参照の再配線**。`Setup` が掲示板から取って**メンバに保存している参照**は、掲示板を更新しても追従しない。
  実コードで確認した例: `OutlinePass` は `Setup` で `normalRT_`(GBuffer1)と `inputRT_`(直前の Output)を保存し、
  `Build` では掲示板から再取得しない。さらに、掲示板に旧 `OutlinePass` 自身の出力が `Output` として残っている状態で
  取り直すと、**入力に旧自分の RT を拾い、旧 RT の解放後は無効参照になる**(GBuffer ありで Tonemap なしの列で起きる)。
  このため手順 4 で**掲示板を初期状態へ戻してから**列順に `Wire` を呼び直す。
  対象は `Setup` で `res.Get` した値を保持する全パス(実装時に全パスを洗う)。
- **共有インスタンスは交換しない**。`GBufferPass` / `DecalPass` / `DeferredLightingPass` は同じ
  `std::shared_ptr<DeferredRenderer>` を持つ。`DeferredRenderer` 自体は作り直さず、**同じインスタンスの中身
  (G0〜G3・深度)を `DeferredRenderer::PrepareResize/CommitResize` で入れ替える**。`DecalPass` / `DeferredLightingPass` は
  そのまま新 RT を見る。`HiZPass` が持つ `std::shared_ptr<HiZRenderer>` も同様。
- エンジン側で `Resizable` にするのは `GBufferPass`(DeferredRenderer 経由)・`HiZPass`・`BloomPass`・`MotionBlurPass`・`TonemapPass`・`OutlinePass` の 6 パス。
  ほかのエンジンパスは `Independent` か、画面依存が見つかれば `Resizable`。
- **パイプライン全体の再 `Build` は採らない。** `GameModule` が `OutlinePass` を `UIPass` の前へ挿すなど、
  ゲームが列を加工するため、プリセットからの再構築では加工が失われる。

**オフスクリーン RT の解放経路(新設)**。現状、オフスクリーン RT はデバイス側の `offscreenRTs_`(`unique_ptr` の配列)が所有し、
`CreateOffscreenRenderTarget` が配列へ追加して**添字をハンドルとして返す**だけで、**個別に解放する API が無い**
(Metal / Vulkan / D3D11 / D3D12 で共通)。ハンドルを捨てても GPU 資源は解放されないので、リサイズのたびにリークする。
そこで次を足す(`SupportsRenderResize()` を true にするバックエンドは必ず実装する):

- `IGraphicsDeviceImpl::ReleaseOffscreenRenderTarget(uint32_t index)`(既定 no-op)と `GraphicsDevice::ReleaseOffscreenRenderTarget(handle)`。
- 実装は `offscreenRTs_[index].reset()` + 空き番号リスト(`freeOffscreenSlots_`)へ登録。
  `CreateOffscreenRenderTarget` は**空き番号を先に再利用**する(添字がハンドルなので、詰め直さない)。
- 解放は必ず `WaitForRenderIdle` 済みの区間で行う(在フライトのコマンドが旧 RT を参照しないため)。
  所有権: 旧 RT は `CommitResize` で、準備した新 RT は `AbortResize` で、それぞれそのパスが解放する。
- 解放済みハンドルを `GetRenderTarget` に渡すと `nullptr`(既存の呼び出し側が null を扱うかは実装時に確認。**TODO**)。
- ハンドルは再利用されるので、**積み済みコマンドが旧ハンドルを持ったまま残っていない**ことが前提。
  手順 1 の `WaitForRenderIdle` 済み・フレームの外で行うので成り立つはずだが、実装時に確認する(**TODO**)。

**バックエンド側**。

| バックエンド | `ResizeMainTargets` の中身 |
| --- | --- |
| Metal | `drawableSize` の更新 + メイン RT / 深度の再作成 + `ReleaseOffscreenRenderTarget`。Mac の窓拡大・iOS の回転 |
| Vulkan | 既存の `RecreateSurface` のスワップチェーン再作成を流用し、**確定寸法(`currentExtent` 優先)を返す**。旧 `swapchainExtent_` の流用を直す(新寸法を渡す)。失敗時は旧が退役済みなので「リサイズ保留 + 再試行」で扱う。`ReleaseOffscreenRenderTarget` を実装 |
| D3D11 | 旧バックバッファ参照(RTV 等)を解放 → `ResizeBuffers` → RTV / 深度の再作成。失敗は旧へ戻せないので「リサイズ保留 + 再試行」。`ReleaseOffscreenRenderTarget` を実装 |
| D3D12 | 旧バックバッファ参照を解放(フレーム在フライトの完了待ち) → `ResizeBuffers` → RTV / 深度の再作成。`ReleaseOffscreenRenderTarget` を実装 |
| Android | 既に `WINDOW_RESIZED` → `RecreateSurface` の経路がある。`ResizeMainTargets` を足す |

**Win32**: `WM_SIZE` は通知として使わず、`GetClientPixelSize`(`GetClientRect`)のポーリングで値を返すだけにする。

### 5.3 フェーズ分割(P4 は大きいので 3 つに割る)

`SupportsRenderResize()` が false のバックエンドは挙動が変わらないので、フェーズごとに独立してコミットできる。
**検出は、パス側の実装(6 パス)が揃ったバックエンドでだけ有効にする**(寸法の混在を防ぐ)。

| フェーズ | 内容 | 検証 |
| --- | --- | --- |
| **P4-A** | 抽象一式(`SupportsRenderResize` / `GetClientPixelSize` / `ResizeMainTargets` / `ReleaseOffscreenRenderTarget` / `RenderPipeline::Resize` / `IRenderPass` の 3 関数 + `Setup` の `CreateTargets` / `Wire` 分割)+ **6 パスの Prepare/Commit/Abort + 全エンジンパスの `GetResizePolicy` + `Sample` の `VignettePass` 移行** + **Metal の実装**。全部そろった Metal だけ `SupportsRenderResize() = true` | Mac(Metal) |
| **P4-B** | Vulkan(MoltenVK)の `ResizeMainTargets`(強い保証への作り替え含む)、iOS の回転の確認 | Mac(Vulkan) + iOS シミュレータ |
| **P4-C** | D3D11 / D3D12 の `ResizeBuffers`、Win32 の `GetClientPixelSize`、Android の確認 | **Windows 実機** + Android |

D3D / UWP の確認が取れるまで P4-C のチェックは残す。

### 5.4 評価チェックリスト

**P4-A の実装記録と結果(2026-11-09、Mac Metal Debug)**。Vulkan は `SupportsRenderResize` が false のままで P4-B で扱う。

実装で決めた点・設計からの差:
- **致命終了は `std::abort()`**。Engine に終了要求の API が無いため、再試行の上限(5 回・200 ms 間隔)を超えたら `[engine] FATAL` を残して止める
  (設計書の「終了を要求する」からの逸脱。終了要求の API を足すかは P4-B 以降で判断する)。
- **`DecalPass` は Independent ではなく Resizable(する作業は無い)**。`DeclareResources` が `GBuffer0` を Writes しており
  Independent の規則に当たるが、掲示板へは登録しない。G-Buffer の RT は GBufferPass が持ち、同じ `DeferredRenderer` の中身が入れ替わる。
- `MotionBlurEffect::CommitResize` は `prevValid_ = false`(旧寸法の前フレーム viewProj を使わず、速度ゼロから再開)。
  `HiZRenderer::CommitResize` は CPU リードバックを mutex 下でクリア(次の読み戻しまで遮蔽判定は「可視」扱い)。
- 追加した小物: `GameTimer::ResetDelta()`(再作成の時間をデルタ時間に載せない)、`Renderer::SetMainViewport()`、
  確定時にメインカメラの `SetViewportSize` を更新、`Engine::UpdateSoundOnly()`(保留中のサウンド供給。実経過時間を測る)。
- 検出は `IPlatform::GetClientPixelSize`(Mac はビューの bounds)。起動直後は要求済み寸法 = 描画解像度(1280×720)で、起動時にリサイズは発生しない。

**P4-B の実装記録と結果(2026-11-10、Mac Vulkan(MoltenVK)Debug・validation 有効)**。

実装で決めた点:
- **`SupportsRenderResize` は `__APPLE__` だけ true**。Android / Windows の Vulkan は P4-C で確認するまで固定寸法
  (Android は `GetClientPixelSize` 未実装で、回転のたびに未検証の再作成が走るのを避ける)。
- **`ResizeMainTargets` の順序**: スワップチェーン → その確定寸法(`currentExtent` 優先)でメイン RT を一時領域へ作成 → 入れ替え。
  サーフェス寸法が今のスワップチェーンと同じなら作り直さない(ドラッグ中にデバイス側が OUT_OF_DATE で先に作り直していることが多い)。
- **`oldSwapchain` の失敗**: `CreateSwapchain` は生成に失敗したとき、旧スワップチェーンが退役済みの可能性があるので
  「スワップチェーン無し」へ落とす(退役済みは次回の `oldSwapchain` に渡せない)。`BeginFrame` / `ResizeMainTargets` が
  `oldSwapchain` 無しで作り直す。画像ビュー / セマフォの途中失敗も同様に畳む(`IsSwapchainReady` を false へ戻す)。
- **寸法の読み取り競合**: `GetSurfaceSize` は `swapchainExtent_`(レンダースレッドが書き換える)ではなく、
  原子の写し `publishedExtent_` を読む。`Engine::SyncScreenSize` が抱えていた競合もこれで解消する。
- `ReleaseOffscreenRenderTarget`(空き番号の再利用)を Vulkan にも実装。`CreateSwapchain` の寸法をデバイス制限で `Clamp`。
- iOS: `PlatformiOS::GetClientPixelSize`(ビュー bounds)を追加。Metal は P4-A で対応済みなので、iOS は Engine のリサイズ経路に入る。

確認できたこと(Vulkan・Mac。タイトル画面と、ゲームプレイ中の 1280×720 → 1300×728 → 820×488。

## 7. 対象外: `-mode=edit`

`-mode=edit` が「保持するだけ」なのは、実体が [アプリケーション構成とエディタ連携設計](アプリケーション構成とエディタ連携設計.md) §8 の
P4(`IAppModule` の Enter/Exit、System の層分け、Play 後の復元)と P5(WPF エディタ)にあるため。
未決の論点は 11 件(edit の定義、止める対象、エディタカメラ、復元方式、保存先と Undo、Link 命令セット、
Release での可否、非 Win32、ImGui か WPF か ほか)で、本書と同じサイクルに入れると設計が発散する。

- 本書では扱わない。着手するときは §8 を一次資料として別途設計する。
- 当面の整理として、README の記述を「`Engine.cpp` が未実装ログを出して play で動く」へ訂正するのみ(P2 に含める)。

## 8. 発見した課題(その場では直さない)

- `RenderItem::layer` は常に 0 で未使用(P3-B の案 A では使わなかった。描画レイヤの置き場として残っている)。
- `IRenderPass::Setup` が RT 生成を担うため、`PrepareResize` と二重実装になりやすい(P4-A で共通化する)。
- Engine に終了要求の API が無く、リサイズの致命的な失敗は `std::abort()` で止めている(P4-A)。
- `Engine::SyncScreenSize` が `GetSurfaceSize` を読む際、Vulkan では `swapchainExtent_` をレンダースレッドの再作成と競合して読み得る(Codex 指摘。P4-A で確認し、`GetClientPixelSize` へ寄せる)。
- (P2 で解消)`AppHost::SetRenderPipeline(nullptr)` が黙って通り、`GameModule::OnInitialize` が `Build` 失敗を握りつぶしていた。
- 初期化失敗(`application Initialize FAILED`)でもプロセスの終了コードが 0 だった(P2 の確認で観測。`Main` / `MacMain` の戻り値の扱いは未調査)。
- `GetImplRaw()` が公開されたまま(D3D11 / D3D12 の static アクセサが内部で使っている。P1 では触らない)。
- 01 レンダリング設計 §7 の「既知の課題④の寸法契約」は README に実体が無い宙に浮いた参照。
