## 0. 設計の全体像(要約)

グラフィックスと**同じ Bridge パターン**。コア(`aq::sound`)は API 非依存で、`ISoundBackend`/`ISoundVoice` の実装を差し替える。

```
Game / ECS
   │  ResourceManager::Load<SoundClip>() → SoundEngine::Play(clip) / SoundSource
   ▼
SoundEngine (aq::sound, コア・シングルトン・Bridge)
   ├─ SoundListener / SoundSource / SoundClip / SoundStream / SoundHandle
   ├─ Mixer3D        3D パラメータ → per-voice ゲイン/周波数比 をコア側で計算
   └─ SoundBus       Master / BGM / SE / Voice グループ音量
   │
   ▼  impl_ : ISoundBackend  (Bridge — IGraphicsDeviceImpl と同じ立ち位置)
   ├─ XAudio2SoundBackend    (Win32 / UWP)
   │     └─ XAudio2SoundVoice : ISoundVoice
   ├─ CoreAudioSoundBackend  (Mac / iOS。AudioUnit + SoftwareMixer)
   ├─ AAudioSoundBackend     (Android。AAudio + SoftwareMixer)
   │     └─ MixerSoundVoice : ISoundVoice   (CoreAudio / AAudio 共通の薄いアダプタ)
   └─ NullSoundBackend       (無音。移植の足場用。`SOUND_BACKEND_NULL` を手動で定義したときだけ選ばれる)
```

**ハイブリッドの肝**:
- 3D 音響(距離減衰・パン・ドップラー)は **X3DAudio を使わずコア(`Mixer3D`)で計算**し、プラットフォーム間で聞こえ方を統一。バックエンドには「ボイス再生 + per-channel ゲイン + 周波数比」だけを渡す。
- バックエンド選択は `SoundBackend.h` の `#define`(Windows 系=XAudio2 / Apple=CoreAudio / Android=AAudio)。他 OS のバックエンドは該当ビルドで空 TU になり、リンクもされない。
- Xbox/UWP でも XAudio2 がそのまま動く(`AQ_PLATFORM_WINDOWS_FAMILY` に含まれる)。
- Mac / iOS / Android は OS が「PCM を要求してくるだけ」なので、XAudio2 のソースボイス相当の意味論(状態機械・リサンプル・出力行列・バス)は共通部品 `SoftwareMixer` が持つ。バックエンドはデバイスを開いてレンダーコールバックから `Render` を呼ぶだけ。詳細は [Mac移植設計.md](Mac移植設計.md) §5、[iOS移植設計.md](iOS移植設計.md) §6、[Android移植設計.md](Android移植設計.md)、[Sound設計.md](Sound設計.md) §8。

## 4. バックエンド

### 4.1 XAudio2(`Sound/XAudio2/`。Win32 / UWP)

| ファイル | 責務 |
|---|---|
| `XAudio2SoundBackend.h/.cpp` | **XAudio2 バックエンド実装**。`XAudio2Create`→`CreateMasteringVoice`→バス分 `CreateSubmixVoice`。`CreateVoice` は `CreateSourceVoice` して指定バスへ送出。`GetOutputClock` は `GetPerformanceData` で latency/underrun を埋める(mastering の SamplesPlayed は device clock として使わない)。 |
| `XAudio2SoundVoice.h/.cpp` | **`IXAudio2SourceVoice` ラッパ**。`SubmitBuffer` は per-voice ブロックへコピー後 `SubmitSourceBuffer`(`OnBufferEnd` で回収)。`SubmitClipRegion` はゼロコピー + `RefSoundClip` 保持 + ループを `XAUDIO2_BUFFER` に設定。`Pause=Stop(0)`/`Stop=Stop+FlushSourceBuffers`。`SetOutputMatrix/SetFrequencyRatio`/`GetConsumedFrames=SamplesPlayed`。 |

**初期化の別スレッド化**(`286fd15`): `XAudio2Create` + マスタリングボイスは実測 0.25〜1.0 秒(大半がデバイス待ち)かかるため、`Engine::Initialize` が `SoundEngine::Create<DefaultSoundBackend>()` までを同期で済ませ、`SoundEngine::Initialize()` を `std::async(std::launch::async)` に投げる(`soundInitFuture_`)。ウィンドウ/グラフィックス/シェーダ初期化と並列に走り、`Engine::EnsureSoundInitialized()` の `future.get()` で合流する(`Initialize` 内の application 初期化前に必ず合流する)。`Create` は同期で済むので `SoundEngine::IsAvailable()` は合流前から true。つまり**合流前に `Initialize` 済みを前提とした再生をしてはいけない**(application 初期化中に BGM を鳴らす側は `EnsureSoundInitialized()` を呼ぶ)。この仕組みは Engine 側の共通コードなので、非 Windows でも同じ流れで `Initialize` が別スレッドから呼ばれる。
COM は `Engine::Initialize` がメインスレッドで `CoInitializeEx(MTA)` をプロセス寿命ぶん保持し(Windows 系のみ)、`XAudio2SoundBackend::Initialize` は自スレッド内で `ComScope`(`CoInitializeEx` / `CoUninitialize` の対)を取る。

### 4.2 CoreAudio / AAudio(共通: `SoftwareMixer` + `MixerSoundVoice`)

| ファイル | 責務 |
|---|---|
| `Mixer/SoftwareMixer.h/.cpp` | **プラットフォーム非依存のソフトウェアミキサ**(`ISoundVoice` / `ISoundBackend` を実装しない純粋な部品)。固定 64 ボイスのプール、出力は最大 8ch、ボイスごとに 16 ブロックの投入リング(コピー)、線形補間リサンプル(入力レート/出力レート × ピッチ)。ボイス操作は SPSC コマンドリング経由で `Render()` 冒頭に適用、`Render()` はロック/確保/IO なし、`RefSoundClip` は回収リングへ退避して `Update()` で解放。**プロデューサはサウンドスレッド 1 本に限る**。 |
| `Mixer/MixerSoundVoice.h/.cpp` | `ISoundVoice` を `SoftwareMixer` の同名操作へ**委譲するだけ**のアダプタ。破棄時にスロットをミキサへ返す。 |
| `CoreAudio/CoreAudioSoundBackend.h/.mm` | **Mac / iOS 共通**(`AQ_PLATFORM_APPLE`)。AudioUnit を 1 つ開き(macOS=DefaultOutput / iOS=RemoteIO)、レンダーコールバックで `SoftwareMixer::Render`。出力は 48kHz / float32 / 2ch インターリーブ固定。出力遅延は macOS=HAL デバイスプロパティ、iOS=AVAudioSession(`GetOutputClock` の latency)。iOS のみ `AVAudioSession`(カテゴリ `Ambient`、有効化/無効化)と中断通知(`OnInterruptionBegan/Ended`)を扱う。停止理由は `suspended_`(背面)と `interrupted_`(中断)を別フラグで持ち、**両方が下りたときだけ** `AudioOutputUnitStart`(`ApplyOutputRunState`)。`OnSuspend/OnResume` と中断通知はともにメインスレッド。 |
| `AAudio/AAudioSoundBackend.h/.cpp` | **Android**(`AQ_PLATFORM_ANDROID`)。AAudio 出力ストリームを 1 本開き、data callback で `SoftwareMixer::Render`。48kHz / float32 / 2ch を要求し、実際に開けたレート/チャンネル数でミキサを作り直す(`OpenAndStartStream`)。`OnSuspend` でストリームを止めボイス状態は保つ。デバイス切替などでストリームが切れるとエラーコールバックが `streamLost_` を立て(そのスレッドでは閉じない)、`Update`(サウンドスレッド)で作り直す。`suspended_` 中の作り直しは止めたまま。 |
| `NullSoundBackend.h/.cpp` | **無音バックエンド**。`NullSoundVoice` は PCM を出さないが再生位置(`GetConsumedFrames`)と自然終了を実時間で進め、ボイス回収・ストリーム背圧が通常どおり回る。音量は保持のみ。 |

### 4.3 ライフサイクル(背面 / 前面)

- `Engine::FrameStep` が毎フレーム `SyncSoundActivity()` を呼ぶ。`platform_->IsRenderable()` の変化(前面=true)を検出し、変化時だけ `SoundEngine::OnResume()` / `OnSuspend()` を呼ぶ(`soundActive_` で冪等化)。XAudio2 と Null は既定 no-op(出力デバイスを持ち続ける)。
- Android: `APP_CMD_PAUSE/RESUME` → `OnSuspend/OnResume`。窓を失う = 背面なのでここでストリームを止める(フレームを飛ばすだけでは AAudio が鳴らし続ける)。通知シェードを下ろしただけの `FocusLost` では止めない。
- iOS: `PlatformiOS::OnSuspend/OnResume` が `renderable_` を切り替え、`SyncSoundActivity` 経由でバックエンドへ届く。
- UWP: `PlatformUWP::OnSuspend/OnResume` は GPU 側のみ呼んでいる。サウンドを止めるかどうかは `IsRenderable()` の実装次第。TODO: UWP での挙動は未確認。

## 9. レビュー時のチェックポイント

- [ ] **抽象の純度**: `aq::sound` コアや ECS に XAudio2 型が漏れていないか(`ISoundBackend`/`ISoundVoice` に閉じているか)。
- [ ] **PCM 生存**: `SubmitClipRegion` が `RefSoundClip` を保持し、ResourceManager の unload・Finalize 順に依存せず PCM が生きているか(XAudio2 はデータをコピーしないため重要)。
- [ ] **オーディオスレッド無ブロック**: コールバック内でロック/確保/IO をしていないか。供給はロックフリーリングか。
- [ ] **ハンドルの安全性**: 再生終了ボイス/破棄ソースへのアクセスが世代チェックで no-op になるか。ECS が生ポインタを持っていないか。
- [ ] **3D の一致**: `Mixer3D` の距離減衰/パン/ドップラーがプラットフォーム非依存(コア計算)で完結しているか。
- [ ] **プラットフォーム分離**: `MFDecoder` / `XAudio2*` / `CoreAudio*` / `AAudio*` / `ExtAudioFileDecoder` が `#if` で他構成から除外される(空 TU)構造か。
- [ ] **ミキサの契約**: `SoftwareMixer` のプロデューサがサウンドスレッド 1 本のままか。`Render()` 内でロック/確保/IO をしていないか。
