> 対象コミット: e796de8 / 最終更新: 2026-09-07

各フェーズは「設計確認 → 実装 → 評価」のサイクル(スキル `feature-dev-cycle`)で進める。
**1 フェーズ = 1 回のビルド・実機確認・コミット**を原則とし、評価チェックが埋まるまで
次フェーズへ進まない。評価結果は本書のチェックボックスに反映する。

### P8(設計 2026-09-07)

実装内容(設計の一次資料: バウンディング方式は `DirectX/設計書/カリング設計.md` §13):

1. **明示バウンディング(エンジン)**: `StaticMesh::SetLocalBounds(math::AABB)` を追加し、
   `FillRenderItem` で `meshResource_` 無しでも `hasBounds` を立てられるようにする。
   `BoxStaticMeshComponent::Update()` の `InitializeShared` 直後に単位キューブ
   AABB(center 0, extent 0.5)を設定 → 路面タイル約 360 枚がフラスタムカリング対象になる。
2. **色指定 API(エンジン+シェーダ)**: `SimpleBox.fx` のハードコード赤
   (`PSMain` の `float4(1,0,0,1)`)を `MaterialCB.h`(b2) の `params[0]` 参照へ変更。
   b2 は `DrawItemCommand` が全 forward アイテムへ既にアップロードしているため
   C++ パイプライン変更は不要。`BoxStaticMeshComponent` に `SetColor(Vector4)` +
   保持メンバ(既定は現状互換の赤)を追加し、
   初期化完了時に `staticMesh_.SetParameter(0, color_)` を適用する
   (`SetColor` が初期化前に呼ばれても保持値が後から適用される)。
   ※ `Reflect` への `color_` 登録は見送り: 反射 Visitor(ImGui/Json)に `Vector4` の
   `Field` オーバーロードが無くコンパイル不可のため。箱色はコード設定専用とし、
   Prefab JSON への永続化が必要になったら Visitor の `Vector4` 対応とセットで行う。
3. **ゲーム側の色設定**: `AquaDashStates.cpp` の路面タイルを青みグレー系、
   コインをゴールド系に変更(具体値は実機の見た目で微調整)。
   `InstancedSimple.fx` の赤ハードコードは未使用経路のため本フェーズでは触らない。

### P10(設計 2026-09-07)

実装内容(**ゲーム側のみ**。エンジンは P9 の per-instance カリング+I_COLOR をそのまま利用):

1. **コインの描画をインスタンス化**: コインエンティティから `BoxStaticMeshComponent` を外し
   (`Transform` + `CoinComponent` は論理用に維持: 位置=取得判定とエフェクト、
   spinPhase/baseRotation=回転)、`RegisterInstancedMesh("CoinBox")` + Coins 1 エンティティ
   (`InstancedStaticMeshComponent` + `InstancedPointListComponent`)を追加。
   `GameContext` に `coinInstancesHandle` を追加(collectFxHandle と同パターン。
   退場時のクリアも同箇所)。
2. **CoinSystem が毎フレーム InstancePoints を再構築**: Update の最後に
   Clear → 非取得コインのみ Add(position / spin×baseRotation / scale(0.8, 0.8, 0.15) /
   ゴールド)。スピンは `tc->rotation` への書き込みをやめ InstancePoint 側だけに反映。
   取得時の `SetVisible(false)` と `ReactivateAll` の `SetVisible(true)` は削除し、
   取得=再構築で消える/復活=`ReactivateAll` 内で即時再構築(ポーズ中でも見た目が戻る)。
3. スレッド境界: CoinSystem(ワーカー)が書く InstancePoints を読むのは
   後段の BuildRenderFrame(メイン)の gather のみで、実行フェーズが分かれているため競合しない。

### P11(設計 2026-09-07)

実装内容:

1. **リングコイン(ゲーム+小さなエンジン変更)**:
   - トーラスメッシュ(外径 0.9m / 管半径 0.09m、24×12 分割、XY 平面・穴が Z 向き =
     旧箱コインと同じ姿勢)を `AquaDashStates.cpp` で生成し、

   - **エンジン**: リングの立体感のため `InstancedSimple.fx` にランバート陰影を追加
     (法線を I_WORLD の上 3x3 で回して正規化、光方向は InstancedModelTex と同じ
     ハードコード、ambient+diffuse)。共有箱 `BOX_VERTEX_BUFFER` は法線が全ゼロの
     8 頂点なので**面法線付き 24 頂点+インデックス更新**に修正(路面タイルにも陰影が乗る。
     SimpleBox.fx は法線未使用なので既存 BoxStaticMeshComponent 経路に影響なし)。
2. **地形の見た目(ゲーム+ベイクツール+アセット)**:
   - `Game/Tools/bake_stage_terrain.py`(純 Python、依存なし)を新設し、.stage.json から
     `Stage01_heightmap.png` / `Stage01_splatmap.png`(512²・8bit)をベイクして
     `Assets/Terrain/` へ出力する。
     - **コース回廊(スプライン XZ 中心線 ±35m)= R0 の完全平坦**(走行・路面タイルと整合)。
       その外側 80m で smoothstep 立ち上げ → バリューノイズのなだらかな丘(最大 22m)。
       ガウスぼかしで 8bit バンディングを抑制。
     - スプラット: 平地=grass(低周波ノイズで rock を 0〜15% 混ぜて単調さを消す)、
       斜面=rock、高所=snow を少量。外周 2px はエッジ複製(Wrap サンプラー対策)。
     - 座標対応はエンジン仕様どおり(画像左上=地形原点、列=+X/行=+Z、端ピクセル=端頂点。
       原点/terrainSize は `CreateStageWorld` と同一式: コース AABB+マージン 60m の正方形)。
   - `.stage.json` に省略可能な `terrain` ブロックを追加(03_ステージデータ仕様.md 参照)し、
     `StageData` にパース、`CreateStageWorld` が desc(heightmapPath / splatmapPath /
     heightScale / resolution=256)へ反映。省略時は従来の平坦 grass。
   - 丘のセルフシャドウ(SetCastShadow)は今回入れない(影マップ範囲との相性を見てから)。
3. スコープ外: コイン取得 SE(Decision.wav 流用のまま)、走行アニメ、タイトル本番アート、
   専用路面メッシュ。丘は見た目のみで判定に関与しない(コース回廊は平坦を保証)。

> **実装中に発見したエンジンバグ**: DirectXTex の `Convert` は変換元と変換先が同一フォーマット
> だと失敗するため、WIC が R8G8B8A8 で返す PNG(RGB/RGBA)は heightmap / splatmap とも
> **ロードが常に失敗して平坦 grass にフォールバックしていた**(従来の heightmap.png /
> splatmap.png も一度も効いていなかった)。同一フォーマット時は Convert をスキップする修正を
> `HeightmapChunk.cpp` に実装(P11 の Engine コミット)。
